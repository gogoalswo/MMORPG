# 기능 문서

각 기능이 **무엇을 하는지 / 어디에 있는지 / 왜 그렇게 했는지**를 기능 단위로 적어 둔 곳이다.

## 왜 있나

새 작업을 시작할 때마다 소스를 처음부터 읽으면 시간과 토큰이 그대로 나간다.
여기 있는 문서는 그 대신 읽는 것이다. **"어느 파일의 어느 함수를 봐야 하는지"까지
적어 두는 게 목적**이라, 문서만 읽고 바로 그 자리로 갈 수 있어야 한다.

## 쓰는 법

1. 작업 전 — 아래 표에서 관련 문서를 먼저 읽는다. 인접 기능 문서도 함께 본다
   (전투를 고치면 아이템·스킬이 같이 흔들린다).
2. 작업 후 — **바꾼 내용을 그 문서에 반영한다.** 수치·규칙·파일 경로가 문서와
   달라지는 순간 이 폴더는 쓸모가 없어지고, 다음 사람은 다시 소스를 통독한다.
3. 새 기능을 만들면 이 표에 줄을 추가하고 문서를 새로 만든다.

## 전체를 관통하는 규칙

읽지 않고 고치면 반드시 밟는 것들이다.

- **판정은 서버가 한다.** 클라이언트가 보내는 건 전부 "요청"이고, 거리·쿨타임·
  소지 여부·직업·레벨은 서버가 다시 본다. 클라이언트 UI의 회색 처리나 잠금은
  안내일 뿐이다.
- **수치는 `packages/shared` 한 곳에만 둔다.** 서버와 클라이언트가 같은 함수를
  불러야 예측 보정이 튀지 않는다.
- **표에서 만든다.** 존·몬스터·아이템·스킬은 전부 생성 함수와 표로 만든다.
  손으로 60줄을 적으면 어긋나고, 어긋난 건 한참 뒤에 "이 구간만 이상하다"로만
  드러난다. 규칙 위반은 `*.test.ts` 가 전수 검사한다.
- **Node 타입 스트리핑 제약** — `shared`/`server` 는 빌드 없이 `node src/index.ts`
  로 돈다. 그래서 파라미터 프로퍼티(`constructor(private x)`)를 쓸 수 없고,
  상대 임포트에 `.ts` 확장자를 반드시 붙여야 한다.
- **`requestAnimationFrame` 은 화면이 가려지면 멈춘다.** 탭을 옮기거나 폰에서
  화면이 꺼지면 0~1Hz가 된다. 계속 돌아야 하는 것(자동 사냥, 추격)은 전부
  서버에 둔다. 이것 때문에 "얼어붙었다"고 오진한 적이 여러 번 있다.
- 소스 파일은 CRLF와 LF가 섞여 있다. 스크립트로 패치할 때 줄바꿈을 가정하지 말 것.
- **확인은 글로 한다.** 스크린샷은 눈으로 봐야 할 때 한 장만. 이유와 도구는
  [verification.md](verification.md) 에 있다.
