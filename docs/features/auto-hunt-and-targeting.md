# 자동 사냥과 클릭 타겟팅

## 무엇

둘은 하는 일이 다르다.
1. **자동 사냥** — 버튼으로 켠다. 켠 자리 주변을 돌며 알아서 고르고 싸운다.
2. **클릭 타겟팅** — 몬스터를 클릭하면 그놈을 **겨눈다.** 캐릭터는 제자리에
   서 있고, 공격·스킬은 사람이 누를 때 그쪽으로 나간다.

**아래 절반은 지워진 웹 클라이언트와 옛 Colyseus 서버 얘기다.** 지금 만드는
고도 클라이언트의 자동 사냥은 "고도(Godot) 쪽 자동 사냥" 절에 있다 — 규칙이
다르다 (반경 고정 27m, 땅 누르기 = 앵커 옮기기).

**예전에는 클릭이 "붙어서 죽을 때까지 때린다"였다** (클릭 추격, 2026-09-13 에 바꿨다).
그건 자동 사냥과 하는 일이 같아서, 사람이 **직접 쏘려고** 지목한 것까지 서버가
대신 해 버렸다. 지금은 겨누기와 싸우기를 나눴다 — 알아서 싸우는 건 자동 사냥
버튼의 일이고, 지목은 "어디로 쏠까"만 정한다.

## 왜 자동 사냥은 서버가 하나 ★

`requestAnimationFrame` 은 탭을 옮기거나 폰에서 화면이 꺼지면 **0~1Hz 로 떨어진다.**
클라이언트가 몰면 그 순간 캐릭터가 그 자리에 선다. 그래서 **계속 돌아야 하는 것**
(자동 사냥의 판단·이동·공격)은 전부 서버 틱에 얹었다. 실제로 측정하고 내린 결정이다.

클릭 타겟팅은 사람이 눌러야 나가는 것이라 이 문제가 없다. 화면이 멈추면 입력도
멈출 뿐이다. 그래서 겨누기는 이동을 서버가 몰지 않는다.

## 규칙

### 공유 경로 `engageTarget(client, player, target, dt)`
붙는다 → 바라본다 → 때린다. 자동 사냥과 자동 시전이 **둘 다 이걸 부른다.**
```
stand = standoffPoint(..., attackRange * HUNT_STANDOFF)   // 0.7 — 꽉 채우면 조금만 움직여도 빠진다
stepAutoPlayer(player, stand, dt, target)                  // 걷고, 대상을 정확히 바라본다
tryAutoSkill(...) || (거리 <= attackRange && handleAttack(...))
```
- 때리는 건 사람이 눌렀을 때와 **똑같은** `handleAttack` / `handleSkill` 이다.
  쿨타임·정면각 검증을 두 벌 만들면 반드시 어긋난다.
- **어느 놈을 치는지 인자로 넘긴다** (`handleAttack(client, target)`). 안 넘기면
  그 둘이 사람이 찍어 둔 타겟을 보고 **엉뚱한 쪽으로 몸을 돌린다** — 자동 사냥이
  고른 놈과 사람이 찍어 둔 놈이 다를 수 있다.
- 서버가 `player.rotY` 를 직접 정한다. 클라이언트 이동으로는 "움직인 방향"밖에
  못 정해서 옆구리로 굳는다.
- **휘두르는 동안에는 `stepAutoPlayer` 가 발을 멈춘다** (`ATTACK_ROOT_MS`, 400ms).
  사람이 모는 이동(`handleInput`)만 막으면 자동 사냥은 그대로 미끄러지면서 친다 —
  여기가 서버가 직접 위치를 옮기는 다른 한 길이다. 각은 계속 맞춘다: 붙어 있는
  대상을 향해 **선 채로** 치는 그림이어야 한다 → [combat.md](combat.md).

### 자동 사냥
- `player.auto` (스키마 필드). 켠 자리를 `autoAnchor` 로 잡는다.
  앵커가 없으면 몬스터를 따라 맵 끝까지 끌려간다.
- 반경은 사람이 조절: `HUNT_RADIUS = 22`, 범위 `6~40`. 슬라이더 값은
  `localStorage['mmo.autoRange']`, 서버가 `clampHuntRadius` 로 다시 자른다.
- `huntLeash(r) = r + 8` — 잡고 있던 대상은 리쉬 안에서 계속 잡는다.
  같으면 경계에 걸친 몬스터를 잡았다 놓았다 반복한다.
- 대상이 없으면 앵커로 돌아가 기다린다.
- **자동 사냥 중 땅 클릭 = "저기로 먼저 가라"** (메시지 `moveTo { x, z }`). ★
  자동 사냥은 켜진 채로 있다. 서버가 `moveOrder` 에 그 자리를 담아두고, 도착할
  때까지 **대상을 고르지 않고 걷기만** 한다(`driveAutoHunt` 가 대상 선택 앞에서
  가로챈다). 도착하면 지시를 지우고 평소 자동 사냥으로 돌아간다.
  - **앵커도 같은 자리로 옮긴다.** 안 옮기면 도착하자마자 "대상이 없으면 앵커로
    돌아간다"에 걸려 원래 자리로 되돌아간다.
  - 가는 길에는 싸우지 않는다 — "저기로 옮겨라"가 "저쪽으로 싸우며 가라"가 되면
    클릭한 자리에 언제 도착할지 알 수 없다. 대신 **먼 거리를 지시하면 맞으면서
    걷는다.** 사냥터를 가로지를 때는 자동 사냥을 껐다 켜는 게 안전하다.
  - `moveOrder` 는 자동 사냥을 켜고 끌 때, 존을 떠날 때 지운다. 켤 때 앵커를
    지금 자리로 새로 잡으므로 옛 지시가 남으면 엉뚱한 데로 걷는다.
- **자동 시전 전용 모드**: 자동 사냥이 꺼져 있어도 `A` 켠 스킬이 있으면
  `casting` 모드로 같은 경로를 탄다. 앵커가 "지금 서 있는 자리"라 돌아가지 않는다.

### 클릭 타겟팅 ★
- 메시지 `target` (id 또는 null) → `handleTarget`. 서버는 `targets` 맵에
  **몬스터 id 만** 적어 둔다. **스키마에는 없다** — 겨누는 건 남에게 보일 필요가
  없고, 무엇보다 이동을 뺏지 않으므로 클라이언트가 예측을 멈출 이유도 없다.
- **이동은 하지 않는다.** 사거리 안으로 붙는 건 사람이 걸어서 한다.
- 푸는 방법: `Esc` / 대상이 죽음 / 내가 죽음 / 존 이동. **땅 클릭으로는 안 풀린다** —
  땅 클릭은 이동일 뿐이고, 원거리 직업이 자리를 옮겨 가며 같은 놈을 쏘는 게 자연스럽다.
- 죽은 대상을 놓는 자리는 `sweepTargets`(매 틱) 한 군데다. 몬스터가 죽는 길이
  여럿(내 공격·남의 공격·리스폰 정리)이라 각자 지우게 두면 반드시 한 곳이 빠진다.
  **조준이 시체에 남으면 다음 스킬이 시체 자리로 나간다.**
- 서버가 `target` 메시지로 지정·해제를 **다시 알려준다.** 클라이언트가 혼자
  판단해 표시를 지우면 서버와 어긋난다 (유효성은 서버가 본다).
- **자동 사냥을 끄지 않는다.** 주인이 겹치지 않기 때문이다. 대신 자동 사냥은
  **지목한 놈을 먼저 잡는다** — 켜 둔 채로 "쟤부터" 라고 찍는 일이 있어서다.
  단 리쉬(`huntLeash`) 밖까지 따라가지는 않는다. 앵커를 두는 이유(맵 끝까지
  끌려가지 않기)가 그대로 살아 있어야 한다.

**고도 쪽은 표시만 옮겼다.** 누른 놈 발밑에 고리를 그리고 쫓아가서 치지만,
맞출 놈을 판정에 정해 주지는 않는다 (정면 부채꼴에서 서버가 다시 고른다. 자동 사냥 중에
보내는 `strike {id}` 는 볼 쪽과 스킬 사거리에만 쓴다 — 아래 "눌러 쫓아도 스킬부터") →
[godot-migration.md](godot-migration.md) 의 "몬스터를 골라 두면 발밑에 고리가 돈다".

### 안 찍고 스킬을 누르면 가장 가까운 놈 ★
겨눈 놈이 없는 채로 **스킬**을 쓰면 서버가 `acquireTarget` 으로 **그 스킬 사거리
안에서 가장 가까운 몬스터**를 잡아 조준으로 등록하고(=`handleTarget` 과 같은 자리,
`target` 메시지로 알린다) 그쪽으로 쏜다.

- 고르는 건 자동 사냥과 **같은 `pickHuntTarget`**(`currentId = null`) 이다.
- **임시로 쓰지 않고 진짜 조준으로 남긴다** — 이름표 표시·해제 규칙이 그대로 살고,
  클라이언트 이펙트와 서버 판정이 같은 놈을 본다.
- 클라이언트도 누르는 순간 같은 계산을 한다 (`faceTarget(사거리)` →
  `RemoteMonsters.nearest`, **보간 위치가 아니라 서버가 준 마지막 좌표**로 잰다).
  안 하면 서버 `target` 메시지가 오기 전 한 번은 이펙트가 정면으로 나간다.
- **기본 공격에는 없다.** 근접 사거리는 짧아서 자동으로 잡아 줄 애매한 거리가
  안 나온다. 회복기(`maxTargets <= 0`)도 잡지 않는다.
- 규칙과 이유는 [skills.md](skills.md) 의 "안 찍고 눌렀을 때".

### 겨눈 쪽으로 쏜다 ★
공격·스킬이 나가기 직전에 서버가 `focusOf` 로 대상을 확인하고 `faceMonster` 로
**`player.rotY` 를 대상 쪽으로 대입한다.** 판정 부채꼴이 `rotY` 를 보기 때문이다 —
클라이언트가 보내는 건 "움직인 방향"뿐이라, 안 돌리면 서서 쏠 때 마지막으로 걷던
쪽으로 나간다.

- **원거리는 타겟 자리에서, 근접은 내 몸에서 터진다** (`blastAt`).
  자세한 규칙과 이유는 [skills.md](skills.md) 의 "겨누고 쏘기".
- 사거리 밖을 찍어 두고 눌러도 날아가지 않는다. 그때는 예전처럼 내 몸에서
  부채꼴로 재고, 닿는 게 없으면 헛친다.
- 클라이언트도 쏘는 순간 `player.faceTo` 로 **즉시** 같은 각을 잡는다.
  예측 중에는 서버 각이 안 내려오므로, 안 돌리면 이펙트만 엉뚱한 쪽으로 나간다.
  보간으로 부드럽게 돌리면 그 0.3초 동안 판정 방향과 그림 방향이 다르다.

### 토글 버튼 표시
- `AutoHuntToggle.setOn` 은 받은 값을 `!!` 로 굳혀서 쓴다. `classList.toggle` 의
  두 번째 인자가 `undefined` 면 강제 지정이 아니라 뒤집기가 되어, 상태 패치마다
  버튼이 깜빡인다. 서버가 `player.auto` 를 생성 시점에 `false` 로 대입하지 않으면
  실제로 그 값이 내려온다 — [networking-state.md](networking-state.md) 참고.
- 클래스(`is-on`)와 글자(켜짐/꺼짐)를 **같은 값**으로 쓴다. 둘이 어긋나 보이면
  (초록인데 "꺼짐") 누군가 클래스만 따로 건드린 것이다.

### 클라이언트가 하는 일
- `myState.auto` 이면 **예측을 멈추고** 서버 위치를 따라간다
  (`Player.setDriven`). 양쪽이 동시에 움직이면 보정이 계속 싸워서 캐릭터가 떨린다.
- 이때는 `reconcile` 대신 `setServerPose(x, z, rotY)` 를 쓰고, 매 프레임
  `follow(dt)` 가 세 가지를 한다. **셋 다 필요하다** — 처음엔 위치만 따라가게
  해뒀는데, 그래서 캐릭터가 정면을 본 채 대기 자세로 덜덜 떨며 미끄러졌다.
  1. **위치** — 목표 쪽으로 매 프레임 당긴다(`FOLLOW_RATE`). 상태는 15Hz 로
     오는데 화면은 60Hz 다. 도착한 순간에만 옮기면 초당 열다섯 번 툭툭 끊긴다.
  2. **각** — 서버가 준 `rotY` 로 돌린다. 클라이언트는 "움직인 방향"밖에 몰라서,
     안 받으면 대상을 옆구리로 보고 걷는다.
  3. **속도** — 실제로 움직인 거리에서 되돌린다. 0 으로 두면 대기 자세로
     미끄러지고, RUN_SPEED 로 박아두면 멈춰 서서도 달리는 시늉을 한다.
- 그래서 **자동 사냥 버튼은 이동 동기화가 깨졌는지 알려주는 계기판이기도 하다.**
  켜자마자 엉뚱한 자리로 튀면 자동 사냥이 아니라 그 전부터 서버와 내 위치가
  달랐던 것이다 — 예측을 멈추는 순간 그 차이가 한 번에 드러날 뿐이다.
  이동 입력이 서버에서 버려지고 있는지부터 본다
  ([networking-state.md](networking-state.md) 의 `seq` 규칙).
- 클릭 레이캐스트는 몬스터 그룹을 지면보다 먼저 본다. 죽은 몬스터는 안 잡힌다.
- **몸 메시가 아니라 안 보이는 상자를 맞힌다** (`hitBoxSize`, `makeHitBox`). ★
  몬스터는 스킨드 메시라 레이캐스트가 팔·다리·꼬리의 실제 삼각형에 맞아야 하고,
  자세가 바뀌면 더 얇아진다 — **눌렀는데 땅으로 새는 일이 잦았다** (2026-09-14).
  지금은 몸 크기만 한 상자를 씌우고 그걸 맞힌다.
  - 크기는 `packages/shared/src/beasts.ts` 의 `hitBoxSize` 한 곳에서 나온다.
    몸 반지름의 2.4배(지름)·**키의 0.55배**·최소 1.0m 중 큰 것을 폭으로,
    머리 높이의 1.05배를 높이로 쓴다. 들늑대가 1.36m × 2.60m 이고 1920×1080 에서
    **100×156픽셀** 표적이다 (`npm run hit-probe`).
  - **키로도 폭을 받친다.** 충돌 반경(`monsterRadius`)은 레벨로만 정해져서
    겉모습과 무관하다 — 2.2m 오우거가 0.38m 늑대와 같은 값이다. 반경만 보면
    상자가 어깨보다 좁아서 팔을 눌러도 땅으로 샌다.
  - **리그 그룹에 걸린 배율로 나눠서 붙인다.** ★ 상자는 리그의 자식인데, 모델
    리그는 파일 단위를 세계에 맞추려고 그룹을 통째로 키우고(오우거 2.4배)
    절차적 리그는 `kind.scale` 을 건다. 월드 미터로 잰 크기를 그냥 넣으면 그
    배율이 한 번 더 곱해진다 — 들늑대 상자가 2.47m × 7.32m, 초원 보스가
    10.6m × 35.2m 였다 (2026-09-15).
    - 증상은 "안 눌린다"가 아니라 **"엉뚱한 놈이 잡힌다"** 였다. 머리 위 허공까지
      먹는 상자가 뒷줄 몬스터의 몸을 덮어서, 뒤에 선 놈을 눌러도 앞놈이 잡힌다.
      2m 뒤에 선 들늑대가 18%(보스는 0%)만 남았고, 고친 뒤 49% 다.
    - **프로브가 이걸 못 잡았다.** `hit-probe` 가 상자 공식을 베껴 두고 리그
      배율을 몰라서 "72×92픽셀, 넉넉하다"를 찍고 있었다. 지금은 프로브도
      `hitBoxSize` 를 임포트해서 같은 상자를 재고, 앞줄이 뒷줄을 몇 % 가리는지
      같이 찍는다. 공유 수치를 `shared` 한 곳에 두는 이유가 이것이다.
  - `colorWrite: false` 라 화면에는 안 그려진다. **`visible = false` 는 못 쓴다** —
    레이캐스터가 그런 물체를 통째로 건너뛴다.
  - 상자도 `noAO` 다. GTAO 는 장면을 깊이로 다시 그리므로, 안 빼면 안 보이는
    상자가 음영을 만든다.
  - 몸 메시는 레이캐스트에서 빼지 않았다. 맞아도 같은 id 라 해롭지 않고, 빼려면
    리그가 만드는 메시마다 손을 대야 한다.
- 겨누고 있는 대상은 **이름표를 금색으로 밝히고, 발밑에 금색 고리를 놓는다**
  (`TARGET_RING`, `RemoteMonsters.updateRing`). 이름표는 머리 위에 여럿이 겹쳐
  뜨는데 발밑은 한 놈에 하나뿐이라, 난전에서는 고리 쪽이 먼저 읽힌다.
  - **테 두께는 비율이 아니라 미터다** (0.22m). 반지름의 24% 로 잡았더니
    들늑대(몸반지름 0.38m)에서 **1080p 6픽셀**이었다 — 작은 놈일수록 얇아져
    정작 자주 보는 몬스터에서 안 보인다. 지금은 크기와 무관하게 1080p 11픽셀이다.
    스킬 고리에서 이미 겪은 것과 같은 실수다 ([skills.md](skills.md) 의 이펙트 절).
  - 그래서 **지오메트리를 대상이 바뀔 때마다 다시 만든다** (`shapeRing`). `scale` 로
    키우면 테까지 같이 스케일된다. 바뀌는 건 사람이 클릭할 때뿐이라 비용이 없다.
  - 고리는 몬스터 리그의 자식이 **아니다.** 리그는 회전하고 종류마다 크기 보정이
    달라서, 붙이면 고리가 같이 돌고 찌그러진다. 자리만 따라간다.
  - 지면 위 0.03m 에 눕힌다(z-fighting). 가산 혼합이라 `noAO` 를 붙이고,
    클릭 레이캐스트에 걸리지 않게 `raycast` 를 비웠다.

## 고도(Godot) 쪽 자동 사냥 ★

지금 만드는 클라이언트는 고도다 ([godot-migration.md](godot-migration.md)).
위의 TS 구현을 **그대로 옮기지 않았다** — 판정하는 쪽이 몬다는 것만 같고,
반경·지시 방식은 아래대로 단순하게 다시 지었다 (2026-09-18).

| 파일 | 역할 |
|---|---|
| `godot/world/world.gd` | `set_auto` / `_drive_auto` / `_pick_hunt_target` / `_walk_auto` / `_auto_strike` / `_auto_cast` / `strike` / `_patrol_auto` / `_take_manual` / `_anchor_here`, 상수 `HUNT_*` · `MANUAL_HOLD_MS` |
| `godot/net/local_transport.gd` | 메시지 `autoHunt {on}` · `strike {id}` |
| `godot/game/game.gd` | 칸과 표시 — `_toggle_auto` / `_refresh_auto`. **퀵슬롯 옆 다섯 번째 칸**이고 켜면 화살표 고리가 돈다 (2026-09-19) → [hud.md](hud.md) |
| `godot/tests/auto_hunt_test.gd` | 반경·붙어서 때리기·스킬 먼저·눌러 쫓을 때도 스킬 먼저·순찰·리쉬·끄기·조작 우선 |

### 반경은 무리 하나 크기로 고정이다 ★

`HUNT_RADIUS = 27` **한 값이고 슬라이더가 없다.** 사냥터의 무리는 반지름 13m 원에
50마리가 흩어져 있고(`zones.json` 의 `monsters[].radius`) 무리끼리는 32m 떨어져
있으므로, 무리 안 **어디에 서서 켜도** 그 무리가 통째로 들어오려면 13 × 2 = 26 이
필요하다. 여유를 얹어 27 로 잡았다.

**무리가 20마리(반경 8)에서 50마리(반경 13)로 커지면서 18 → 27 이 됐다.** 이때 무리
자리도 ±20 → ±28 로 물려야 했다 — 간격 40 으로는 "무리 하나는 통째로(≥26) · 옆
무리는 안(≤22)" 이 **동시에 성립하는 반경이 없기 때문**이다 ([world-zones.md](world-zones.md)).

**2026-09-23 에 맵을 줄이며 무리를 ±16 으로 붙였다 — 옆 무리도 끌려온다.**
50마리·반경 13 을 그대로 두기로 해서(사용자 선택) 무리 간격이 32 가 됐고, 옆 무리
가장자리가 6m 밖이다. "옆 무리는 안" 은 더는 지키지 않는다. 반경 27 은 그대로다.

실제 초원에서 잰 값 (`auto_hunt_test.gd` 가 매번 찍는다):

| | |
|---|---|
| 한 무리 양 끝 | **25.6m** — 반경 27 안 |
| 옆 무리까지 | **7.5m** — 반경 27 안 (예전 ±28 배치에서는 31.0m) |

테스트는 "한 무리가 통째로 들어온다" 만 검사하고, 옆 무리 거리는 찍기만 한다.
**무리 반경(`zones.json`)을 바꾸면 이 테스트가 먼저 깨진다** — 반경을 같이 본다.

리쉬는 `HUNT_LEASH = 18 + 6 = 24`. 잡고 있던 놈만 여기까지 봐준다. 반경과 같게
두면 경계에 걸친 놈을 잡았다 놓았다 하면서 앵커로 걸어가다 되돌아오기를 반복한다.

### 한 틱이 하는 일

`World.step` → `_drive_auto` 로 매 틱 돈다 (화면이 아니라 **판정하는 쪽**이다 —
위의 "왜 자동 사냥은 서버가 하나"가 고도에서도 그대로다).

1. `_pick_hunt_target` — 앵커 반경 안에서 **가장 가까운** 산 놈. 잡고 있던 놈은
   리쉬 안이면 계속 잡는다 (대상을 안 바꾼다).
2. `_walk_auto` — 사거리의 `HUNT_STANDOFF`(0.7) 까지 붙는다. 사람이 모는 입력과
   같은 `Movement.apply_move` 를 타므로 경계·몬스터 충돌이 같다. **휘두르는
   동안에는 발을 멈춘다**(`rooted_until`).
3. 대상 쪽으로 `rot` 를 대입하고, **경직(`rooted_until`)이 풀렸을 때만** 다음 것을
   넣는다 — 스킬이 먼저(`_auto_cast`, 아래), 나간 스킬이 없으면 **사거리 안일 때만**
   `attack()` 을 부른다.
   - **멀리서 헛휘두르면 안 된다.** 거리를 안 보고 부르게 했더니 첫 틱에 휘두르고
     경직 400ms 가 걸려, 10m 밖에서 한 발짝도 못 나가고 제자리에서 팔만 돌았다
     (2026-09-18, 테스트가 잡았다).
   - 누구를 맞출지는 여전히 `World._pick_target` 이 정면 부채꼴에서 고른다
     ([godot-migration.md](godot-migration.md) 의 "대상은 서버가 고른다").
4. 대상이 없으면 **앵커 주변을 서성인다**(`_patrol_auto`, 아래).

### 잡을 것이 없으면 서성인다 ★

앵커 반경 `HUNT_PATROL_RADIUS`(8m) 안에서 **한 다리 걷고 1.2초 쉰다** — 몬스터
순찰(`_patrol`)과 같은 모양이고, 목적지는 `auto_patrol_x/z`, 쉬는 시각은
`auto_rest_until` 이다.

- **선 채로 기다리지 않는 이유**: 가만히 서 있으면 자동 사냥이 멈춘 것처럼 보이고,
  리스폰을 기다리는 동안 한 발짝도 안 움직이면 무리 반대편에 새로 나온 놈을
  사거리 안에 두는 데 그만큼 더 걸린다.
- 순찰 반경을 사냥 반경(18)이 아니라 **무리 반지름(8)** 으로 잡았다. 더 넓게 돌면
  리스폰을 기다리다 무리 밖으로 걸어 나가 옆 무리를 끌고 온다.
- 쫓다가 반경 밖까지 나와 있으면 **먼저 앵커 쪽으로 돌아온다.** 안 돌아가면
  마지막으로 쫓던 자리에 눌러앉아 무리 밖에서 서성인다.

### 켜 둔 채로 조작하면 사람이 이긴다 ★

이동 입력(`input_move`)이 들어오면 `manual_until = now + MANUAL_HOLD_MS`(0.4초)
가 잡히고, 그동안 `_drive_auto` 는 **그 사람을 통째로 건너뛴다.** 손을 떼면 0.4초
뒤에 자동 사냥이 그 자리에서 이어받는다.

- 켜 둔 채로 잠깐 자리를 옮기거나 위험한 놈을 피하는 것이 가장 흔한 조작이라,
  그때마다 끄게 하면 단추를 두 번 더 눌러야 한다.
- **걸어간 자리가 새 사냥터다** — 이동이 성공할 때마다 앵커를 지금 자리로 옮긴다
  (`_anchor_here`). 안 옮기면 손을 떼는 순간 자동 사냥이 원래 자리로 도로 끌고
  가고, 그러면 조작이 이긴 것처럼 보이지 않는다.
- **휘두르는 중(경직 400ms)이라 발이 묶여 있어도 먼저 잡는다.** 안 그러면 경직마다
  자동 사냥이 한 번씩 끼어들어 조작하던 방향과 다른 데로 몸이 돈다.
- 유예를 0.4초로 둔 것은 이동 입력이 매 프레임 오기 때문이다. **화면이 멈춰서
  입력이 끊긴 것과 손을 뗀 것은 구별할 수 없고, 구별할 필요도 없다** — 둘 다
  "사람이 안 몰고 있다"이고, 그 순간 자동 사냥이 이어받는 게 맞다.
- 몬스터를 눌러 쫓는 것(`_target_mob`)도 같은 길이다. 매 프레임 이동 입력을
  보내므로 그동안은 사람이 이기고, 그놈이 죽으면 자동 사냥이 이어받는다.
- **존을 옮기면 꺼진다** (`join` 을 다시 타므로). 앵커가 지난 존의 자리라 남겨 두면
  켜 둔 채로 엉뚱한 데를 향해 걷는다.
- 화면의 파란 고리는 **조작 중이 아닐 때만** 앵커를 가리킨다. 조작 중에는 같은
  고리가 "눌러 둔 자리"라, 겹쳐 쓰면 걸어가는 도중에 표시가 발밑으로 튄다
  (앵커가 따라오기 때문이다).

### 판정이 옮긴 것도 걷는 것이다 ★

`game.gd` 의 `_moving` 은 원래 `_move`(내가 보낸 입력)에서만 켜졌다. 자동 사냥은
입력을 안 보내므로 **대기 자세로 미끄러졌다** (2026-09-18 에 지적받았다).

지금은 `_draw_state` 가 **실제로 움직인 거리**에서 되돌린다 — 지난 프레임 자리와의
차이를 `_last_delta` 로 나눠 `RUN_SPEED_EPS`(0.5m/s)를 넘으면 달리기다. 웹
클라이언트가 서버 주도 이동에서 쓰던 방법과 같다 (위 "클라이언트가 하는 일" 3번).

- 존을 옮긴 프레임(`zone_changed`)은 세지 않는다. 자리가 통째로 튀어서 한 프레임
  달리는 시늉을 한다.
- 몬스터는 이 문제가 없다. `World` 가 `state`(`chase`·`patrol`·`attack`·`idle`)를
  스냅샷에 넣어 주고 화면은 그걸 보고 클립을 고른다.

### 스킬도 쓴다 (`_auto_cast`) ★

2026-09-23 "자동사냥하면 스킬을 안 사용해" 로 붙였다. **액션바에 올린 스킬 전부**를
쓴다 — TS 의 칸마다 `A` 스위치는 옮기지 않았다(액션바에 올린 것이 곧 쓰겠다는 뜻).

- 액션바 **칸 순서대로** 보고, 쿨타임이 돈 것 중 **대상이 그 스킬 `range` 안**에 든
  첫 것을 쓴다. 칸 순서가 우선순위다. 원거리기는 걸어 붙는 도중에 사거리에 들면 나간다.
- 회복기(`selfHeal`)는 **채울 만큼 빠졌을 때만** 쓴다 — 가득 찬 채로 쓰면 쿨타임만 버린다.
- 쏘는 것은 사람이 누르는 것과 **같은 `cast`** 다. 나갔는지는 `rooted_until` 이 새로
  걸렸는지로 본다. 쿨타임으로 보면 테스트 스위치(쿨타임 0)에서 나갔는데도 안 나간 걸로
  읽혀 같은 틱에 기본 공격까지 휘두른다.
- **경직 중에는 아무것도 넣지 않는다.** 스킬 경직 중에 기본 공격이 끼면 스킬 동작이
  끊기고, 쿨타임 0 스위치에서는 스킬이 매 틱 나간다. 기본 공격만 쓸 때는 경직 ≤ 공격
  간격이라 이 조건이 아무것도 바꾸지 않는다.
- **스킬 시전(`cast_until`)이 끝날 때까지도 기다린다** (2026-09-24). 시전 중에는 다음
  스킬도 기본 공격도 판정이 거절하므로(`cast` · `attack`), 경직(0.4초)만 보고 넣으면 헛요청이다
  → [skills.md](skills.md) 의 "시전 중에는 다른 스킬을 못 쓴다".
- 위의 "보고 → 경직·시전 기다리고 → 스킬 → 사거리 안이면 평타" 는 `_auto_strike` 한 곳에
  있다. 자동 사냥 한 틱과 아래 "눌러 쫓을 때" 가 같이 쓴다.

### 켜 둔 채로 몬스터를 눌러 쫓아도 스킬부터 (`strike`) ★

2026-09-26 "자동공격중에 몬스터를 클릭하면 평타만 사용해" 로 고쳤다. 몬스터를 누르면
화면(`game.gd` 의 `_chase_and_hit`)이 매 프레임 이동 입력을 보내므로 **그동안 자동 사냥이
통째로 쉰다**(위 "조작하면 사람이 이긴다"). 그런데 화면은 `attack` 만 보내고 있어서 스킬이
안 나갔다.

- 자동 사냥이 켜져 있으면 화면은 `attack` 대신 **`strike {id}`** 를 보낸다. 판정(`World.strike`)은
  자동 사냥과 같은 `_auto_strike` 로 **스킬부터** 쓰고, 나간 게 없으면 사거리 안일 때만 평타다.
  꺼져 있으면 `strike` 는 그냥 `attack` 이다.
- **붙는 도중에도 매 프레임 보낸다.** 원거리기는 그 스킬 사거리에 들자마자 나가야 한다 —
  기본 공격 사거리까지 다 걸어 들어간 뒤에야 쓰면 원거리기가 아니다.
- 보내는 id 는 **어느 쪽을 볼지와 스킬 사거리를 재는 데만** 쓴다. 누구를 맞출지는 여전히
  `cast` · `attack` 이 정면에서 다시 고른다.
- 누른 놈을 자동 사냥의 대상(`auto_target`)으로 넘기는 방법은 쓰지 않았다. 앵커 리쉬 밖의
  놈을 누르면 자동 사냥이 놓아 버려서, 누른 놈을 쫓는다는 뜻이 깨진다.

### 아직 없는 것

반경 슬라이더·"지목한 놈 먼저"는 안 옮겼다. 필요해지면 위의 TS 절을 보고 붙인다.

## 손댈 때

- 새 "알아서 싸운다"를 만들면 `engageTarget` 을 재사용할 것. 붙는 거리·바라보는
  각·쿨타임을 다시 쓰면 한쪽만 고치는 실수가 난다.
- 확인은 `npm run probe -- aim` — 지목하고 제자리에 있는지, 쏠 때 각이 도는지,
  사거리 밖이면 안 맞는지를 글로 찍는다 ([verification.md](verification.md)).
- 서버가 이동을 모는 모드를 추가하면 `handleInput` 의 무시 조건과 클라이언트의
  예측 정지 조건을 **둘 다** 고쳐야 한다.
