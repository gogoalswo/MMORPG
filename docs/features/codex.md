# 장비 도감

## 무엇

가방의 장비를 **넣어(소모)** 칸을 채우면 능력치가 % 로 붙는다. 칸은 **등급 7 × 부위 6 × 강화 +0 ~ +9 = 420칸**,
창은 등급마다 탭 하나(일반 ~ 태초)에 부위 여섯 줄 × 강화 열 칸이다.

요청 (2026-10-01): "도감 만들자. 각 등급 0강부터 9강까지 등록할 수 있는 도감 만들어. 파츠별로 도감 만들어.
그리고 탭 만들어서 일반부터 태초등급까지 만들어". 등록하면 소모 · 칸마다 능력치 · 메뉴 단추는 바르코 그림 —
셋 다 물어서 고른 안이다.

## 규칙

### 칸과 등록 ★

- 칸 주소는 **아이템 id(등급·부위가 하나로 정해진다, 예 `g3_w`) + 강화**. 장부에는 `codex = { id: 비트 }` 로 둔다
  (+0 = 1, +1 = 2, … +9 = 512). 칸 주소를 따로 만들지 않은 이유 — 42종 카탈로그가 이미 등급 × 부위다.
- **등록하면 그 장비 하나가 가방에서 없어진다.** 겹친 칸이면 개수만 하나 준다.
- **끼고 있는 장비는 안 받는다** — 가방만 뒤진다. 몸에서 벗겨져 사라지면 되돌릴 수 없다.
- **넣을 장비는 창에서 고른다** (2026-10-01 요청 "등록할 때 어떤 아이템 넣을건지 선택하는 UI도 만들어").
  요청은 고른 **가방 번호**를 같이 싣고, 장부가 그 칸이 이 등급·부위·강화가 맞는지 다시 본다 — 그사이 가방이
  바뀌어 다른 것이 서 있으면 넣지 않는다("고른 … 이 가방에 없습니다"). 번호가 -1 이면 **옵션 줄(1·2·3차 합)이
  가장 적은 것**.
- 이미 찬 칸 · 가방에 없는 것은 거절(알림만). 표에 없는 id · 강화 범위 밖은 조용히 무시.
- 왜 소모인가: 강화가 실패하면 부서지는 게임이라 같은 등급 여벌이 계속 나온다 — 그 여벌을 쓸 곳이다.

### 수치 ★★

부위마다 올리는 능력치 하나, **능력치마다 부위 둘** — 셋이 같은 크기로 자란다.

| 부위 | 능력치 |
|---|---|
| 무기 · 목걸이 | 공격력 |
| 갑옷 · 투구 | 방어력 |
| 신발 · 반지 | 체력 |

**칸 몫 = 등급 몫 × (강화 + 1)** %:

| 등급 | 등급 몫(+0) | +9 | 한 부위 10칸 합 |
|---|---|---|---|
| 일반 | 0.01 | 0.1 | 0.55 |
| 고급 | 0.02 | 0.2 | 1.1 |
| 희귀 | 0.03 | 0.3 | 1.65 |
| 영웅 | 0.05 | 0.5 | 2.75 |
| 전설 | 0.08 | 0.8 | 4.4 |
| 초월 | 0.12 | 1.2 | 6.6 |
| 태초 | 0.2 | 2.0 | 11 |

- **다 채우면 능력치마다 +56.1%** (등급 합 28.05 × 부위 둘).
- 강화를 ×(강화+1) 로 크게 준 이유: 실패하면 부서져 +9 까지 닿기가 매우 어렵다 — 높은 칸이 값어치를 해야 한다.
- 처음 안은 `× (1 + 0.1 × 강화)` 였는데 소수 둘째 자리에서 0.06 · 0.06 처럼 **같은 값이 겹쳐서** 바꿨다.
  지금 공식은 늘 0.01 의 배수다.
- 바꾸려면 `CODEX_GRADE_VALUE` 를 고치고 `codex.test.ts` 의 56.1 과 이 표를 같이 고친다.

### 보너스는 따로 곱한다 ★

```
최종 = 기본(레벨) × (1 + 장비 %) × (1 + 헬스 %) × (1 + 도감 %)
```

헬스와 같은 이유 — 장비 % 에 더하면 태초 풀셋 앞에서 안 보인다 ([fitness.md](fitness.md)).
캐릭터 정보 창은 **줄을 늘리지 않고** 증가 줄 끝에 `도감 +N%`(소수 둘째 자리)를 붙인다 — 창이 720 을 넘는다.

### 창 (`codex_panel.gd`) ★

결은 헬스 창과 같다 (돌판 틀 `ui_dungeon_card` · 전체 화면 · 금빛 탭 · 오른쪽 칸 · 청록 단추).

```
 일반  고급  희귀•  영웅  전설•  초월  태초                                     X
 ──────────────────────────────────────────────────────┬──────────────────
          +0   +1   +2   +3   +4 … +9                   │    획득 효과
 무기     [■]  [■]  [■]  [□•] [ ] … [ ]                  │ ◆ 공격력 +0.18% (희귀 +0.18%)
 공격력                                                  │ ◆ 방어력 …
 갑옷 · 투구 · 신발 · 목걸이 · 반지 …                      │   희귀 6 / 60 · 전체 6 / 420
                                                        │    선택한 칸
                                                        │ [그림] 흑철 건틀릿 +3
                                                        │ 공격력 +0.12%
                                                        │ 가방에 1개 — 하나를 넣습니다
                                                        │ [        등록        ]
```

- 탭 글자는 **등급 색**(고른 탭만 밝게 + 금빛 밑줄). 그 등급에 넣을 수 있는 칸이 있으면 탭에 빨간 점.
- 칸 셋 — **찬 칸**(그림 또렷 · 등급 색 테) · **넣을 수 있는 칸**(그림 반투명 · 청록 테 · 빨간 점) · **빈 칸**(흐림).
  칸 그림은 장비 아이콘(`{부위}_g{등급}`)을 그대로 쓴다 — 새로 그리지 않았다.
- 칸을 직접 누르기 전에는 **넣을 수 있는 첫 칸**이 저절로 골라진다 — 하나 넣으면 다음 칸으로 넘어간다.
- 오른쪽 칸의 [등록] 은 바로 넣지 않고 **고르기 창**을 연다 (아래).
- 0% 는 "0" 으로 적는다 — `String.num(0.0, 2)` 가 "0.0" 을 돌려 "방어력 +0.0%" 로 찍혔다.
- 획득 효과는 도감 전체, 괄호(하늘색)는 이 등급 몫.
- 장부가 바뀌면(`codex` · 가방의 id·강화·개수) `refresh` 가 알아채 다시 그린다. 가방은 옵션까지 문자열로 만들지
  않는다(`_bag_key`).
- 창은 차원문 · 던전 · 헬스 창과 **같은 층(10)** — 하나를 열면 나머지를 닫는다.

### 고르기 창 (`codex_picker.gd`) ★

요청 (2026-10-01): "도감 등록할 때 가방에서 선택하는 UI를 따로 만들어. 지금 보면 2,3차 옵션은 안 보이자나".
그 전에는 오른쪽 칸 안 목록이 1차(`options`)만 한 줄로 이어 적었다 — 2차(`options2`) · 3차(`options3`)는 칸이 따로라 빠졌다.

```
 ┌──────────── 등록할 장비 선택 — 흑철 건틀릿 +3 ────────────┐
 │ ┌──────────────────────┐ ┌──────────────────────┐ │   두 열 칸, 끌어서 내린다(DragScroll)
 │ │[그림] 흑철 건틀릿 +3   │ │[그림] 흑철 건틀릿 +3   │ │   고른 칸은 금빛 테
 │ │ 1차  비어 있음         │ │ 1차  치명타 +6%        │ │   차수마다 줄 — 옵션이 없으면 "비어 있음"
 │ │ 2차  비어 있음         │ │ 2차  아이템 드랍률 +9% │ │   크리스탈로 붙는 2차는 금빛
 │ │ 3차  비어 있음         │ │ 3차  비어 있음         │ │
 │ └──────────────────────┘ └──────────────────────┘ │
 │ 넣은 장비는 가방에서 사라집니다       [ 취소 ] [ 등록 ] │
 └──────────────────────────────────────────────────┘
```

- 도감 창의 맨 뒤 자식이라 모든 것 위에 뜬다. 뒤는 어둡게 덮고 누름을 막는다. 결은 메뉴 판과 같은 어두운 판 + 얇은 금테.
- 처음엔 **옵션 줄(1·2·3차 합)이 가장 적은 것**이 골라져 있다 — 장부 기본과 같은 셈(`Items.option_lines`).
- [등록] → `picked(가방 번호)` → 도감 창이 `register_requested(id, 강화, 번호)` 를 낸다. [취소] · 도감 창 닫기는 그냥 닫는다.
- 차수 말("N차" · "비어 있음")은 크리스탈 창과 같다.
- 확인 사진: `npm run shot:godot -- codex_pick` → `logs/shot_codex_pick.png`.

### 그림 (바르코)

`ui_icon_codex` — 방패 문장이 든 펼친 책. **HUD 아이콘 기준 프롬프트 그대로**(세피아 단색조 · 참고 그림 둘,
[ui-art-style.md](ui-art-style.md)), 세 장 중 셋째. 메뉴 판의 ≡ · X 도 같은 날 같은 방법으로 뽑았다 → [hud.md](hud.md) "메뉴 판".

## 손댈 때

- 장부 칸을 더했으면 `Ledger.KEYS` · `fresh` · `World.join` · `restore` · `save.gd` 를 같이 본다 (헬스와 같다).
- `World.stats_of` 인자를 바꾸면 `kill_check.gd` 도 같이 — 안 그러면 서버 처치 검증이 어긋난다.
- 등급·부위 수가 바뀌면 칸 표(`CODEX_CELLS`)와 창의 탭·줄 수가 표에서 따라온다. 강화 끝이 바뀌면 `CODEX_MAX_ENHANCE`.
- 아직 없는 것: **일괄 등록**(한 번에 넣을 수 있는 칸 전부) — 420칸을 하나씩 누르는 게 번거로우면 붙인다.
