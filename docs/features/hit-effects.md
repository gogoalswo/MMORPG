# 피격 이펙트

맞을 때마다 화면에 나는 것. **섬광·파편·피해 숫자**가 맞은 자리에서 터지고,
**맞은 몸이 잠깐 붉어지고**, 내가 맞았으면 **화면 가장자리까지 붉어진다.**
여기에 **타격감**(히트스톱·흔들림·몸 튕김·찌그러짐)이 네 단계 세기로 붙는다.

## 어디

| 파일 | 역할 |
|---|---|
| `godot/game/hit_fx.gd` | 맞은 자리에서 터지는 3D 연출 한 벌 (`HitFx`). 스스로 사라진다 |
| `godot/game/skill_fx.gd` | **스킬 이펙트** (`SkillFx`). 할퀴기 자국 — 같은 규칙으로 짓는다. **모양을 짓는 도구**(바늘 메시·가산 재질·곡선)가 여기 있다 → [skills.md](skills.md) |
| `godot/game/lightning_fx.gd` | **낙뢰**(`LightningFx`) — 번개 세 번 · 갈라지는 땅 · 튀는 파편. 도구는 `skill_fx.gd` 것을 쓴다 → [skills.md](skills.md) |
| `godot/game/hurt_flash.gd` | 내가 맞았을 때 화면 가장자리 비네트 (`HurtFlash`) |
| `godot/game/hit_fx.gd` `TIERS` · `tier_of` · `react` · `apply_react` | **타격감** 단계 표와 몸 반응 |
| `godot/game/rig.gd` `freeze` | **히트스톱** — 애니메이션만 잠깐 세운다 |
| `godot/game/game.gd` `_feel_hit` | 한 대가 몇 단계인지 골라 위 넷과 화면 흔들림을 건다 |
| `godot/game/game.gd` `_show_hit` | `hit` 이벤트를 받아 위 둘을 부르는 **유일한** 자리 |
| `godot/world/world.gd` `_hit_monster` · `_hit_player` | 이벤트를 내는 자리 (판정) |
| `godot/tests/hit_fx_test.gd` | 헤드리스 확인 — 섰나·붉어졌나·치우고 갔나 |

## 이펙트는 항상 고도 엔진에서 만든다 ★

**에셋을 만들어 붙이지 않는다.** 섬광도 파편도 숫자도 비네트도 전부 코드로
짓는다 (2026-09-17 에 그러라고 했다).

- 이펙트 하나 보자고 `npm run sync:godot` 을 돌려야 하면 안 된다. 모델이 없으면
  기둥으로 그리는 것과 같은 이유다 — 에셋을 안 받은 사람도 게임이 돌아야 한다
- 색·시간·크기가 전부 상수라 고쳐서 바로 확인한다. 이미지를 다시 굽는 왕복이 없다
- `index.pck` 이 안 늘어난다. 폰이 받는 양이 곧 시작 시간이다

**스킬 연출은 어떻게 짓는지는 따로 있다** — [effect-rules.md](effect-rules.md)
(2026-09-18 에 사용자가 준 규칙). 띠·줄기는 파티클이 아니라 직접 메시고, 방향은
화면이 아니라 캐릭터 기준이며, 만들면 찍어서 보고 나서 "됐다" 고 말한다.
**이펙트를 만들거나 고치기 전에 그 문서를 읽는다.**

할퀴기 자국을 판 모양 메시로 만들어 제자리에 세웠더니 **"이미지 붙여 놓은 것
같다"** 는 말을 들었다 (2026-09-17). 텍스처를 쓴 것은 아니었지만 **평평한 판이 한
자리에 서 있으면 그림 한 장과 다를 게 없다** — 중심에서 뻗어 나가거나, 리본이
움직이거나, 어느 쪽이든 **살아 있어야** 한다.

맞은 자리에서 터지는 이 문서의 피격 연출은 섬광이 부풀고 파편이 튀므로 그대로 둔다.

## 크기는 px 로 정한다 ★

**미터로 정하면 안 보인다.** 카메라가 화면 세로 14.3m 를 보므로 720p 에서
**1m 가 41px** 다 ([godot-migration.md](godot-migration.md) 의 카메라 절). 처음에
숫자를 0.38m·파편을 0.09m 로 잡았더니 화면에서 16px·4px 이라 **이펙트가 서는데도
"맞아도 이펙트가 안 나온다"** 는 말을 들었다 (2026-09-17). 테스트가 통과한 이유도
같다 — 노드가 있는지만 봤지 얼마나 큰지는 안 봤다.

그래서 `hit_fx_test.gd` 의 `_case_visible` 이 **내 캐릭터 자리에서** px 로 다시 잰다
(멀리 있는 보스 자리에서 재면 원근 때문에 헐거워진다).

**그 다음엔 반대로 너무 컸다.** 키운 값(숫자 58px)을 보고 "너무 크다" 고 해서
크기만 반으로 나눴다 (2026-09-17, 뜨는 시간과 비네트는 그대로 뒀다). 지금은
**숫자 29px · 섬광 50px · 파편 6px** 이고, HUD 글자가 28px 이니 피해 숫자가
그만하다. 테스트 하한은 24px·40px·5px 이다 — 16px 은 안 보였고 58px 은 컸다는
두 번의 눈 확인에서 나온 선이다.

## 수치

| | 값 | 왜 |
|---|---|---|
| 숫자가 떠 있는 시간 `LIFE` | 0.75초 | 더 길면 무리를 칠 때 화면이 숫자로 덮인다 |
| 섬광 `FLASH` | 0.22초 | 오래 남으면 타격감이 아니라 조명이 된다 |
| 몸이 붉은 시간 `BODY_FLASH` | 0.2초 | 공격 간격(0.9초)보다 짧아야 한 대마다 따로 보인다 |
| 숫자가 뜨는 속도 `RISE` | 1.8 m/초 | |
| 파편 `SPARKS` | 7개 × `SPARK_SIZE` 0.15m | 초당 수십 번 터져도 폰이 버티는 선 |
| 섬광 `FLASH_RADIUS` | 0.3m → 터지며 2배 | 지름 1.2m ≈ 50px |
| 처치했을 때 섬광 | 1.6배 | 마지막 한 대는 크게 보인다 |
| 피해 숫자 `NUMBER_SIZE` | 0.011 (글자 0.70m ≈ 29px) | HUD 글자와 같은 정도 |
| 치명타 `CRIT_SIZE` | 0.017 | **읽지 않아도 크기로 안다** |
| 비네트 최대 `PEAK` | 0.55 | 더 올리면 화면이 빨개서 몬스터가 안 보인다 |
| 비네트 사라짐 `FADE` | 0.45초 | |
| 비네트 세기 | `피해 / (최대체력 × 0.25)`, **하한 0.55** | 크게 맞으면 제일 진하고, 스쳐도 알아보게 바닥을 깐다 |

| | 색 |
|---|---|
| 내가 때림 | `#ffe6a0` |
| 내가 때림·치명타 | `#ff4fd8` (자홍) |
| **내가 맞음** | `#ff5a4a` |
| 회복 | `#7ce08a` |

## 규칙

- **화면은 판정을 다시 하지 않는다.** 숫자·치명타·처치·회복은 `World` 가 낸 `hit`
  이벤트에 다 들어 있다. 화면이 따로 계산하면 반드시 어긋난다 → [combat.md](combat.md)
- **터지는 높이는 몸에서 잰다.** 자리(`x`,`z`)는 `World` 가 주지만 높이는 안 준다.
  그려 둔 몸의 AABB 에서 6할(가슴)을 쓴다 — 발밑에서 터지면 맞은 것처럼 안 보이고,
  키 3m 보스와 1m 슬라임에 같은 높이를 쓰면 둘 중 하나는 어긋난다
- **몸은 덧칠(`material_overlay`)로 붉힌다.** 원래 재질을 건드리지 않아서 되돌릴 때
  `null` 만 넣으면 된다. 모델(메시 여러 장)이든 기둥(한 장)이든 같은 코드다.
  **이펙트가 사라질 때 반드시 걷는다** — 안 걷으면 그 몬스터는 영영 빨갛다
- **숫자는 항상 앞에 그린다**(`no_depth_test`). 몬스터 몸에 가리면 얼마 맞혔는지
  읽을 수가 없다
- **비네트는 가운데를 비운다**(`FILL_RADIAL`). 알리는 것이지 가리는 것이 아니다 —
  맞는 동안 도망칠 자리를 봐야 한다
- **비네트가 겹치면 더 진한 쪽을 남긴다.** 더하면 연타에 화면이 새빨개진다
- **회복은 때린 것이 아니다.** 초록 `+n` 숫자만 뜨고 섬광·파편·비네트가 없다
- **이펙트는 스스로 사라진다.** 보스 예고 원(`_aoe_marks`)과 달리 터진 뒤에 손댈
  일이 없어서 화면이 목록을 들고 있지 않는다 — `_process` 가 수명을 세고 `queue_free`
- 존 아래(`_zone_node`)에 붙는다. 차원문을 타면 통째로 지워진다

## 타격감 (2026-09-23) ★

눈에 보이는 연출만으로는 "걸렸다" 는 느낌이 안 난다. **시간·움직임**을 더했다.
**내 캐릭터는 맞으면 동작(`Hit`)도 튼다** (2026-09-24) — 뒤로 젖히며 팔로 얼굴을 막는다.
언제 트는지는 [characters-and-animation.md](characters-and-animation.md) 의 "블렌더 동작".
세기는 네 단계 — **평타 < 치명타 < 처치 < 보스.** 매번 같은 세기면 금방 무뎌진다.

| 단계 | 히트스톱 | 흔들림 | 밀림 | 퍼짐 |
|---|---|---|---|---|
| 0 평타 | 0.045초 | 없음 | 0.12m | 8% |
| 1 치명타 · 내가 맞음 | 0.07초 | 0.05 / 0.18초 | 0.22m | 14% |
| 2 처치 | 0.09초 | 0.09 / 0.24초 | 0.32m | 18% |
| 3 보스 | 0.13초 | 0.14 / 0.35초 | 0.40m | 22% |

- **단계 고르기**(`tier_of`) — 치명타 1, 처치 2 에서 시작해 **보스가 끼면 한 단계
  올린다**(보스 평타 = 잡몹 치명타, 보스 처치 = 맨 위). **내가 맞으면 적어도 1** —
  평타 단계는 화면이 안 흔들려서 맞은 걸 모른다. 회복은 -1(아무것도 안 건다)
- **히트스톱은 애니메이션만 멈춘다**(`Rig.freeze`, 배속 0). `Engine.time_scale` 을
  쓰면 판정 시간까지 멈춰 공격 간격이 늘어난다. 때린 쪽과 맞은 쪽 **둘 다** 멈춘다.
  겹치면 긴 쪽이 남는다. 기둥(모델 없음)은 멈출 동작이 없다
- **단, 내가 평타·스킬 동작 중에 맞으면 내 몸은 안 멈춘다** (2026-09-24). 여러 마리에게
  둘러싸이면 0.07초씩 연달아 걸려 스킬 동작이 뚝뚝 끊겼다. 붉어짐·흔들림·퍼짐과 때린
  몬스터의 멈춤은 그대로다. 맞음 동작(`Hit`)을 공격 중에 안 트는 것과 같은 규칙이다
- **평타에는 화면을 흔들지 않는다.** 초당 몇 번씩 흔들리면 멀미가 난다.
  흔들림은 `CameraRig.shake` 를 그대로 쓴다 — 약한 것이 센 것을 덮지 않는다
- **몸 튕김은 값만 적어 두고 매 프레임 얹는다.** 몸 자리는 화면이 매 프레임
  `World` 좌표로 덮어쓰므로 `react` 가 메타(`hit_react`)에 적고, 덮어쓴 **바로 뒤에**
  `apply_react` 가 그 위에 더한다. 판정 좌표는 그대로다. 새로 맞으면 값을 갈아 끼워서
  겹쳐도 되돌릴 게 없다. 0.05초에 튀어 나갔다가 0.18초까지 천천히 돌아온다
- **내 캐릭터는 밀지 않고 퍼지기만 한다.** 밀면 카메라가 쫓아가 화면째 흔들리고,
  걷는지 보는 거리 계산(`_moving`)이 밀린 거리를 달린 걸로 읽는다
- **보스는 절반만 밀린다**(`BOSS_KICK`). 무거운 놈이 잡몹처럼 날아가면 가볍다
- **죽어서 숨긴 몸은 `settle` 로 걷는다.** 안 걷으면 되살아날 때 찌그러져 있다.
  그래서 처치 단계의 밀림·퍼짐은 화면에 안 보인다(맞자마자 숨는다) — 처치는
  섬광 1.6배·흔들림으로 안다
- **폰 진동은 쓰지 않는다.** 단계별로(25~60ms) 넣었다가 바로 뺐다
  (2026-09-23, "핸드폰에 진동은 제거해"). 다시 넣자고 하지 않는다
- 치명타 숫자를 **자홍**(`#ff4fd8`)으로 바꿨다 ("크리티컬 터지면 데미지 플로터 색상도
  바꿔"). 주황은 평타의 연노랑과 같은 난색이라 크기로만 갈렸다. 자홍은 게임 안
  어디에도 안 쓰는 색이다

## 경험치는 여기서 띄우지 않는다 (2026-09-23)

잡으면 쓰러진 자리에서 `+n EXP` 를 3D 글자(`ExpFx`)로 띄웠었는데, 피해 숫자와 같은
자리에서 터져 **"데미지랑 같이 뜨니까 안 보여"** 라는 말을 듣고 걷었다. 경험치와
장비 획득은 **화면 왼쪽 아래 채팅창**에 적힌다 → [hud.md](hud.md) 의 "채팅창".
전투 자리에는 전투(피해 숫자)만 띄운다.

## 왜 3D 이펙트만으로 부족한가 ★

3D 이펙트는 **맞은 자리를 보고 있어야** 보인다. 뒤에서 맞거나 손가락에 가리면
체력이 줄어든 뒤에야 안다. 화면 테두리는 어디를 보고 있든 보이므로, "내가 맞았다"
만큼은 3D 와 UI 양쪽에 건다.

## 확인

```bash
npm run test:godot -- hit_fx
```

노드로 읽는다 — 숫자가 떴나, 가슴 높이인가, **화면에서 몇 px 인가**, 몸이
붉어졌나, 사라질 때 덧칠도 걷었나, 화면이 붉어졌다 잦아드나, 회복은 섬광이
없나. 스크린샷을 찍지 않는다. 눈으로 볼 것은 색뿐이다 →
[verification.md](verification.md).
