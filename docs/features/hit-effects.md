# 피격 이펙트

맞을 때마다 화면에 나는 것. **섬광·파편·피해 숫자**가 맞은 자리에서 터지고,
**맞은 몸이 잠깐 붉어지고**, 내가 맞았으면 **화면 가장자리까지 붉어진다.**

## 어디

| 파일 | 역할 |
|---|---|
| `godot/game/hit_fx.gd` | 맞은 자리에서 터지는 3D 연출 한 벌 (`HitFx`). 스스로 사라진다 |
| `godot/game/skill_fx.gd` | **스킬 이펙트** (`SkillFx`). 지금은 할퀴기 자국 — 같은 규칙으로 짓는다 → [skills.md](skills.md) |
| `godot/game/hurt_flash.gd` | 내가 맞았을 때 화면 가장자리 비네트 (`HurtFlash`) |
| `godot/game/game.gd` `_show_hit` | `hit` 이벤트를 받아 위 둘을 부르는 **유일한** 자리 |
| `godot/world/world.gd` `_hit_monster` · `_hit_player` | 이벤트를 내는 자리 (판정) |
| `godot/tests/hit_fx_test.gd` | 헤드리스 확인 — 섰나·붉어졌나·치우고 갔나 |

## 이펙트는 항상 고도 엔진에서 만든다 ★

**에셋을 만들어 붙이지 않는다.** 섬광도 파편도 숫자도 비네트도 전부 코드로
짓는다 (2026-09-17 에 그러라고 했다).

- 이펙트 하나 보자고 `npm run sync:godot` 을 돌려야 하면 안 된다. 모델이 없으면
  기둥으로 그리는 것과 같은 이유다 — 에셋을 안 받은 사람도 게임이 돌아야 한다
- 색·시간·크기가 전부 상수라 고쳐서 바로 확인한다. 이미지를 다시 굽는 왕복이 없다
- `index.pck` 이 안 늘어난다. 폰이 받는 양이 곧 시작 시간이다

**스킬 연출은 파티클로 짓는다** (2026-09-17 에 추가로 지적받았다). 할퀴기 자국을
판 모양 메시로 만들어 제자리에 세웠더니 **"이미지 붙여 놓은 것 같다"** 고 했다 —
텍스처를 쓴 것은 아니었지만 **평평한 판이 한 자리에 서 있으면 그림 한 장과 다를 게
없다.** 중심에서 **뻗어 나가고 흩어지는** 것이 있어야 터진 것으로 읽힌다
(`godot/game/skill_fx.gd` 의 `CPUParticles3D` 여섯) → [skills.md](skills.md).

맞은 자리에서 터지는 이 문서의 피격 연출은 섬광이 부풀고 파편이 튀므로 그대로 둔다 —
다시 손댈 일이 생기면 파편을 `CPUParticles3D` 로 옮기는 게 다음 자리다.

## 크기는 px 로 정한다 ★

**미터로 정하면 안 보인다.** 카메라가 화면 세로 14.3m 를 보므로 720p 에서
**1m 가 41px** 다 ([godot-migration.md](godot-migration.md) 의 카메라 절). 처음에
숫자를 0.38m·파편을 0.09m 로 잡았더니 화면에서 16px·4px 이라 **이펙트가 서는데도
"맞아도 이펙트가 안 나온다"** 는 말을 들었다 (2026-09-17). 테스트가 통과한 이유도
같다 — 노드가 있는지만 봤지 얼마나 큰지는 안 봤다.

그래서 `hit_fx_test.gd` 의 `_case_visible` 이 **내 캐릭터 자리에서** px 로 다시 잰다
(멀리 있는 보스 자리에서 재면 원근 때문에 헐거워진다).

**그 다음엔 반대로 너무 컸다.** 키운 값(숫자 58px)을 보고 "너무 크다" 고 해서
크기만 반으로 나눴다 (2026-09-17, 뜨는 시간과 비네트는 그대로 뒀다). 지금은
**숫자 29px · 섬광 50px · 파편 6px** 이고, HUD 글자가 28px 이니 피해 숫자가
그만하다. 테스트 하한은 24px·40px·5px 이다 — 16px 은 안 보였고 58px 은 컸다는
두 번의 눈 확인에서 나온 선이다.

## 수치

| | 값 | 왜 |
|---|---|---|
| 숫자가 떠 있는 시간 `LIFE` | 0.75초 | 더 길면 무리를 칠 때 화면이 숫자로 덮인다 |
| 섬광 `FLASH` | 0.22초 | 오래 남으면 타격감이 아니라 조명이 된다 |
| 몸이 붉은 시간 `BODY_FLASH` | 0.2초 | 공격 간격(0.9초)보다 짧아야 한 대마다 따로 보인다 |
| 숫자가 뜨는 속도 `RISE` | 1.8 m/초 | |
| 파편 `SPARKS` | 7개 × `SPARK_SIZE` 0.15m | 초당 수십 번 터져도 폰이 버티는 선 |
| 섬광 `FLASH_RADIUS` | 0.3m → 터지며 2배 | 지름 1.2m ≈ 50px |
| 처치했을 때 섬광 | 1.6배 | 마지막 한 대는 크게 보인다 |
| 피해 숫자 `NUMBER_SIZE` | 0.011 (글자 0.70m ≈ 29px) | HUD 글자와 같은 정도 |
| 치명타 `CRIT_SIZE` | 0.017 | **읽지 않아도 크기로 안다** |

| 비네트 사라짐 `FADE` | 0.45초 | |
| 비네트 세기 | `피해 / (최대체력 × 0.25)`, **하한 0.55** | 크게 맞으면 제일 진하고, 스쳐도 알아보게 바닥을 깐다 |

## 규칙

- **화면은 판정을 다시 하지 않는다.** 숫자·치명타·처치·회복은 `World` 가 낸 `hit`
  이벤트에 다 들어 있다. 화면이 따로 계산하면 반드시 어긋난다 → [combat.md](combat.md)
- **터지는 높이는 몸에서 잰다.** 자리(`x`,`z`)는 `World` 가 주지만 높이는 안 준다.
  그려 둔 몸의 AABB 에서 6할(가슴)을 쓴다 — 발밑에서 터지면 맞은 것처럼 안 보이고,
  키 3m 보스와 1m 슬라임에 같은 높이를 쓰면 둘 중 하나는 어긋난다
- **몸은 덧칠(`material_overlay`)로 붉힌다.** 원래 재질을 건드리지 않아서 되돌릴 때
  `null` 만 넣으면 된다. 모델(메시 여러 장)이든 기둥(한 장)이든 같은 코드다.
  **이펙트가 사라질 때 반드시 걷는다** — 안 걷으면 그 몬스터는 영영 빨갛다
- **숫자는 항상 앞에 그린다**(`no_depth_test`). 몬스터 몸에 가리면 얼마 맞혔는지
  읽을 수가 없다
- **비네트는 가운데를 비운다**(`FILL_RADIAL`). 알리는 것이지 가리는 것이 아니다 —
  맞는 동안 도망칠 자리를 봐야 한다
- **비네트가 겹치면 더 진한 쪽을 남긴다.** 더하면 연타에 화면이 새빨개진다
- **회복은 때린 것이 아니다.** 초록 `+n` 숫자만 뜨고 섬광·파편·비네트가 없다
- **이펙트는 스스로 사라진다.** 보스 예고 원(`_aoe_marks`)과 달리 터진 뒤에 손댈
  일이 없어서 화면이 목록을 들고 있지 않는다 — `_process` 가 수명을 세고 `queue_free`
- 존 아래(`_zone_node`)에 붙는다. 차원문을 타면 통째로 지워진다

## 왜 3D 이펙트만으로 부족한가 ★

3D 이펙트는 **맞은 자리를 보고 있어야** 보인다. 뒤에서 맞거나 손가락에 가리면
체력이 줄어든 뒤에야 안다. 화면 테두리는 어디를 보고 있든 보이므로, "내가 맞았다"
만큼은 3D 와 UI 양쪽에 건다.

## 확인

```bash
npm run test:godot -- hit_fx
```

노드로 읽는다 — 숫자가 떴나, 가슴 높이인가, **화면에서 몇 px 인가**, 몸이
붉어졌나, 사라질 때 덧칠도 걷었나, 화면이 붉어졌다 잦아드나, 회복은 섬광이
없나. 스크린샷을 찍지 않는다. 눈으로 볼 것은 색뿐이다 →
[verification.md](verification.md).
