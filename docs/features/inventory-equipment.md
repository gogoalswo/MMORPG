# 가방과 장비

## 무엇

가방 200칸, 장착 6슬롯. **창이 셋이다** (2026-09-23) — 왼쪽 끝에 장비 창,
오른쪽 끝에 인벤토리, 칸을 누르면 인벤토리 바로 왼쪽에 상세 창이 뜬다.

## 규칙

### 슬롯 6종 ★
`weapon · armor · helmet · boots · necklace · ring` (무기·갑옷·투구·신발·목걸이·반지)

**2026-09-18 에 여덟에서 여섯으로 줄였다** (요청: "슬롯은 무기, 갑옷, 투구, 신발,
목걸이, 반지 이렇게야"). 없앤 것은 **보조(offhand)** 와 **귀걸이(earring)** 다.

같이 따라간 것:
- 아이템이 **240종 → 160종**. 보조는 직업마다 달라 한 단계에 셋씩 차지하고 있었다.
  (**2026-09-21 에 단계 축을 없애며 42종이 됐다** — [items.md](items.md).
  `godotExport.test.ts` 의 수가 이것이다.)
- 직업을 타는 자리는 **무기 하나만** 남았다 → **2026-09-21 에 그것마저 없앴다.**
  장비는 전 직업 공용이라 `JOB_SLOTS` 는 빈 표다.
- `OFFHAND_NAME`(보호대·마법서·화살통)과 `slotLabel` 의 직업 갈래를 걷었다.
  `slotLabel(slot, job)` 의 `job` 은 부르는 쪽을 다 안 고쳐도 되게 **받아서 무시**한다.
- 서버 상태에서 `offhand` 를 뺐다 (`state.ts`·`syncLook`).
- 되살리려면 그 커밋을 `git revert` 하는 게 빠르다.

- 착용 조건은 `canEquip(item, job, level)` — **서버가 다시 본다.**

### 칸 크기는 실제로 재서 센다 ★

스크롤 높이는 `칸 * 줄수 + 칸 사이 * (줄수-1)` 이고, 격자 간격도 코드에서
못박는다(`BAG_GRID_GAP`). 가로에는 세로 스크롤바 폭(`SCROLLBAR_W`)을 더한다.

**"칸" 이 얼마인지는 두 번 바뀌었다.** 옛 칸(88·74)은 안쪽 여백만큼 커져서
`CELL * 줄수` 로 잡으면 **마지막 줄이 잘렸다** (2026-09-20). 인벤토리 결 칸
(2026-09-23)은 안에 최소 크기를 가진 것이 없어 **`CELL` 이 곧 바깥 크기**다 —
여백을 또 더했더니 격자 아래가 한 줄 가까이 비었다. 둘 다 찍어서 알았다.
지금 `CELL = 58`, 8줄이라 인벤토리 창이 670 높이다.

### 창 레이아웃 ★
2026-09-23 요청 — 사용자가 인벤토리 그림 한 장을 주며 **"이런 느낌으로. 아이템을
클릭하면 왼쪽처럼 상세 정보. 장착창은 왼쪽으로 따로 창을"**.
```
┌ 장비 LV.1 ───── X┐              ┌ 전설 ───── X┐┌ 인벤토리 ──────── X┐
│ [무기] 몸 [신발] │              │ 전설 반지 +1 ││ [][][][][]  [전체] │
│ [갑옷]    [목걸이]│  (게임 화면)  │ 반지·Lv.121 ▣││ [][][][][]  [무기] │
│ [투구]    [반지] │              │ 보유 중      ││ ... 8줄     [방어구]│
│ 공격력 · 방어력  │              │ 아이템 정보 ─ ││             [장신구]│
│ 체력 · 치명타 …  │              │ 등급   전설  ││ 소지품 3/200 [장비][정렬]│
│                  │              │ …    [장착]  ││ (동전) 1,240       │
└──────────────────┘              └─────────────┘└────────────────────┘
```
- **셋을 한 가로 상자에 넣고 가운데에 늘어나는 빈칸을 둔다** (`_build_bag_panel`).
  장비는 왼쪽 끝, 인벤토리는 오른쪽 끝에 붙고, 상세는 인벤토리 바로 왼쪽이다.
  앵커만으로 자리가 잡혀 해상도가 바뀌어도 양 끝에 남는다. 세 창의 높이는
  상자가 맞춘다(가장 큰 인벤토리 높이). `ui_test` 가 자리·겹침·화면 안을 잰다.
- **가방 단추는 인벤토리와 장비 창을 같이 연다.** 장비 창은 자기 X 로 따로 닫고
  인벤토리의 **"장비"** 단추로 다시 연다(`_toggle_gear`). 인벤토리 X 는 셋 다 닫는다.
- **상세 창은 칸을 눌러야 뜬다.** 빈칸을 누르거나 X 를 누르면 닫힌다 (`_pick_bag`).
  위에서부터 등급 이름 · 이름(+강화) · `슬롯 · 착용 Lv.N` · 보유 중/착용 중 · 큰 칸,
  "아이템 정보" 아래에 `등급 · 강화 · 보유 수량 · 기본 능력치 · 옵션` 을 이름/값
  두 칸 표(`_detail_info`)로 적는다. **이름과 등급은 등급 색**이다(`_grade_tint` —
  표의 흙빛을 30% 밝혀 쓴다). 장착/해제 단추는 이 창 맨 아래다.
- **등급은 칸 테 색이 말한다.** 칸 안쪽에 등급 색 가는 선을 두르고(`grade` 겹),
  배지에서는 등급 숫자를 뺐다 — 배지는 `+강화` · `x개수` 만.
- **고른 칸은 금테를 덮는다** (`pick` 겹 — 받은 그림처럼). 예전의 밝게 하기(modulate)는 없앴다.
- **정렬** 단추는 판정에 `sortBag` 을 보낸다 — 등급 높은 것 → 슬롯 순서 → 강화 높은 것.
- 장착 6칸은 캐릭터를 사이에 두고 **세 칸씩 세로로** 세운다 (`_gear_cells` — 격자가 아니라 목록이다).
- 스탯 여섯(`STAT_NAMES`)은 장비 창 아래 상자에 2열 세 줄.
- 가방은 **오른쪽 세로 탭으로 거른다** (`BAG_TABS`: 전체·무기·방어구·장신구).
  재료 탭은 2026-09-20 에 제작과 함께 없앴다.
  거르면 **칸 번호와 가방 번호가 어긋나므로** `_bag_view` 에 "보이는 칸 → 가방 몇 번째"
  를 적어 둔다. 끼울 때 이걸 안 거치면 엉뚱한 물건이 끼워진다 (`ui_test` 가 본다).
- `BAG_COLUMNS = 5` · `BAG_ROWS = 8`(받은 그림대로 40칸이 보인다) · `CELL = 58`.
  장비 378 · 상세 336 · 인벤토리 428 폭, 높이 670 (`ui_test` 가 잰다).
- **창 자리는 컨테이너가 잡는다.** ★ `set_anchors_preset` 만 부르면 앵커만 바뀌고
  오프셋이 0 이라 **왼쪽 위 구석에 박힌다** — 폰에서 창이 구석에 나온 게 이것이었다
  (2026-09-18). 지을 때 한 번만 맞추는 것도 안 된다: 가방에 든 것에 따라 창 크기가
  변해서 그만큼 밀린다(13px 밀렸다). 그래서 화면 전체 `MarginContainer` 안의
  가로 상자에 얹는다.
- **닫기 X 는 창 안쪽 여백 모서리에 붙인다** (`_close_button(..., 0)`). ★ `_close_button`
  은 X 를 트리에 넣기 전에 앵커를 잡아서 **최소 크기를 8 로 읽고 X 를 36px 오른쪽에
  붙인다** — 새 창에서 X 가 테 밖으로 나가 알았다(2026-09-23). 옛 창(스킬·NPC)은
  그 자리를 보고 `CLOSE_PAD` 를 고른 것이라 그대로 두고, `inset = 0` 일 때만 넣은
  뒤에 자리를 다시 잡는다.
- **같은 물건은 한 칸에 겹친다.** 열쇠는 `id#등급#강화#옵션` (`stackKey`).
  옵션이 다르면 성능이 다르므로 겹치지 않는다.
- 칸이 작아 이름을 다 못 쓴다. 이름·능력치·버튼은 **아래 상세 칸**에서 보여준다.
- 배지: 등급 숫자 / `+N` 강화 / 개수.
- 상세 칸의 옵션 칩은 `title` 로 `N등급 범위 min~max` 를 보여준다.
  잘 뽑은 물건인지 알 수 있어야 등급을 올릴 이유가 생긴다.
- **요약 줄**(`.bag-gear-sum`)은 상태바에 안 나오는 것만 적는다 —
  치명타 / 치명타 데미지 / 공격 속도. 옵션으로만 붙는 값이라 여기가 없으면
  무엇을 끼웠는지 알 방법이 없다.

### 아이콘 ★
바르코 커스텀 워크플로우 **"인벤토리 UI"** 로 만든 연한 청백색 선화 한 벌이다.
주소는 `scripts/fetch-assets.sh` 에 박혀 있고, `build-item-icons.mjs` 가 굽는다.

- **파일 이름 = 슬롯 이름.** `weapon.png` `armor.png` `helmet.png` `boots.png`
  `necklace.png` `ring.png` + 머리 줄용 `bag.png` `gold.png`.
  칸을 채울 때 슬롯 이름으로 바로 찾는다 — 표를 따로 두지 않는다. **여섯 칸이 다 있다.**
- **창을 짓는 그림 일곱 장**: `ui_panel`(창 바탕) · `ui_subpanel`(이름표·스탯 상자) ·
  `ui_slot`(칸) · `ui_tab_on`/`ui_tab_off`(탭) · `ui_button`(단추) ·
  `ui_figure`(칸 사이 캐릭터). 2026-09-18 에 처음 만들고,
  **2026-09-20 에 HUD 와 같은 결로 한 벌을 다시 뽑았다** ★ — 어두운 판 + 머리카락처럼
  얇은 금테 + 상아빛 포인트다. **HUD 아이콘 셋(X자 검·배낭·책)을 참고 그림으로 물려서**
  뽑았고, 그 방법은 [hud.md](hud.md) 의 "참고 그림은 작게 줄여서 올린다" 에 있다.
  - **고른 탭은 바탕이 상아빛**이라 글자를 어둡게 얹는다 (`_redraw_bag`). 흰 글자면 묻힌다.
  - **창 바탕은 배경을 넓은 폭으로 걷으면 안 된다** — `ui_panel` 을 `WIDE_TOLERANCE`
    에 넣었더니 **안쪽 바탕까지 걷혀 금테만 남고 뚫렸다** (`build-item-icons.mjs`).
  `StyleBoxTexture` 로 **9조각으로 늘여 쓴다** (`_frame_box`).
  - **9조각 여백과 안쪽 여백을 따로 준다.** ★ 안 주면 고도가 9조각 여백을 안쪽
    여백으로도 써서 칸마다 26px 씩 물러앉는다 — 창이 1320x758 로 부풀었다.
  - **모서리 조각은 원본 픽셀 그대로 그려진다** — 칸(88px)보다 큰 텍스처를 쓰면
    모서리가 겹쳐 뭉개진다. 그래서 칸은 128, 창은 256 으로 굽는다.
  - 굽는 단계에서 **알파 경계로 잘라낸다**(`TRIM`). 바르코는 그림 둘레에 배경을
    넉넉히 남기는데, 그대로 9조각으로 자르면 여백이 그림이 아니라 빈 자리에 걸린다.
  - 프롬프트에 "아무것도 넣지 말라" 를 길게 적어야 한다. 처음 판에는 창 둘레에
    검·물약이 굴러다녔고 칸에는 **"9-SLICE READY" 라는 글자와 안내선**이 그려져 나왔다.
- **2026-09-23 에 세 창을 "인벤토리 결" 조각(`inv_*`)으로 갈았다** — 받은 인벤토리
  그림을 참고 그림으로 물려 뽑은 것이다 → [ui-art-style.md](ui-art-style.md) 의
  "인벤토리 결". 위의 `ui_panel`·`ui_slot`·`ui_button`·`ui_figure` 는 스킬창·NPC 창·
  캐릭터 그림으로 계속 쓰고, `ui_tab_on`/`ui_tab_off` 는 이제 안 쓴다.
- 받아만 두고 안 쓰는 것이 둘 있다 — `glove` `belt` (어느 칸에 쓸지 안 정했다).
  `offhand.png`(방패)는 슬롯을 없애면서 같이 뺐다.
- **없으면 글자로, 테두리는 코드로 그린 것으로 나온다.** `npm run sync:godot` 을
  안 돌린 사람도 창은 돌아가야 한다 (모델이 없으면 기둥으로 그리는 것과 같은 규칙).
- **있는지는 `.png` 또는 `.png.import` 가 있는지로 본다.** ★★ 두 번 틀린 자리다:

  | 방법 | PC(에셋 있음) | PC(sync 안 함) | 웹 익스포트 |
  |---|---|---|---|
  | `ResourceLoader.exists` | 있다 | 없다 | **없다고 한다** — 폰에서 전부 글자로 나왔다 |
  | 안 거르고 `load` | 있다 | **오류 쏟아짐** | 있다 |
  | `.png` 또는 `.png.import` | 있다 | 없다 | 있다 |

  익스포트에서 PNG 는 `.ctex` 로 구워져 들어가고 원본 `.png` 는 빠지는데
  **`.png.import` 는 팩에 그대로 들어간다.** `load` 는 리맵을 따라가므로 임포트 파일이
  있으면 불러도 된다. 바닥(`.ktx2`)은 임포트를 안 거쳐 원본이 그대로 있어서 예전
  방식이 거기서는 통했다. 찾은 결과는 이름마다 기억해 둔다.
- 바르코가 준 원본은 **배경이 검은 것과 흰 것이 섞여 있다.** 그대로 쓰면 어두운 창에서
  흰 사각형이 번쩍이므로 굽는 단계에서 걷어낸다. 걷는 방법이 까다로워 세 번 고쳤다:
  밝기로 자르면 동전 속이 비고, 모서리 색만 보면 둥근 사각형 배경(반지·벨트·검)이
  안 걷히고, 겹을 무조건 세 번 벗기면 동전이 통째로 지워졌다(100%). 지금은
  **테두리에서 색을 모아 이어진 것만 걷고, 첫 겹이 25% 미만일 때만 한 겹 더** 들어간다.

### 서버
- 인벤토리는 **본인에게만** `inventory` 메시지로 보낸다 (상태 스키마에 없음).
- 장비가 바뀌면 `refreshMax` 가 최대 HP/MP 를 다시 계산한다.
- 가방이 꽉 차면(`INVENTORY_SIZE = 200`) 벗기·구입·드롭이 거부된다.

## 손댈 때

- 아이템에 필드를 더하면 `stackKey` 에 넣을지 판단할 것. 성능이 달라지는
  필드인데 안 넣으면 다른 물건이 한 칸에 겹쳐 보인다.
- 슬롯을 추가하면 `EQUIP_SLOTS`, `SLOT_CODE`, `bonusFor`, `FIXED_SLOT_LABEL`,
  아이콘, 창 격자를 같이 봐야 한다. 칸 이름은 `slotLabels`·`offhandNames` 로
  `items.json` 에 나가므로 `npm run export:godot` 을 다시 돌린다.
- **닫기는 창 오른쪽 위 X 하나다** (2026-09-20 요청 — 모든 창이 같다). 아래쪽
  "닫기" 글자 단추는 지웠고, 남은 단추는 **장착/해제** 하나뿐이다
