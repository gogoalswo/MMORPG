# 서버 — 장부만 판정한다

## 무엇

플레이어끼리는 **만나지 않는다**. 전투·이동·몬스터는 지금처럼 **기기 안에서** 돈다.
서버는 **"값이 생기고 없어지는 것"** 만 판정한다 — 경험치·레벨·골드·가방·장비·강화·
스킬·전직, 그리고 **드롭**. 그 위에 채팅과 랭킹을 얹는다.

2026-09-28 에 정했다 ("드롭까지 서버에서 판정하는 걸로 가자").
**2단계(서버 뼈대)까지 들어갔다** — 판정은 `ledger.gd` 로 뗐고 서버(`godot/server/`)도 뜨지만,
기기는 아직 서버에 붙지 않는다.
아래 "단계" 가 순서다.

## 왜 이렇게 나눴나 ★★

- **쓰는 것만 검증하면 소용없다.** 전투가 기기 안에 있으면 "몬스터 잡아서 골드 10만"
  이라는 보고를 믿을 근거가 없다. 버는 쪽이 뚫리면 쓰는 쪽 검증은 그냥 통과한다.
  그래서 **드롭을 굴리는 것도 서버다** — `_kill` 의 주석 "굴리는 쪽은 언제나
  판정하는 쪽이다" 그대로다.
- **전투까지 서버로 옮기지 않는다.** 만나지 않는 게임에서 매 틱 입력을 서버로 보내면
  비용(서버·지연·보정)만 늘고 얻는 게 없다. 옛 16단계 계획("고도 헤드리스가 `World`
  를 통째로 돈다")은 **이 결정으로 바뀌었다.**
- **서버도 고도 헤드리스다.** 드롭·랜덤 옵션·강화 확률·스탯 계산이 GDScript
  (`items.gd`·`stats.gd`·`combat.gd`)에 있다. Node 로 짜면 판정이 두 언어 두 벌이 된다
  ([godot-migration.md](godot-migration.md) "왜 서버까지 고도로 가나").
  서버는 이 파일들을 **그대로 불러 쓴다.**

## 판정을 둘로 가른다

| | 기기 (`World`) | 서버 (`Ledger`) |
|---|---|---|
| 이동·충돌·카메라 | ✔ | |
| 몬스터 AI·체력·피해 계산 | ✔ | |
| 스킬 시전·쿨타임·이펙트 | ✔ | |
| **처치 인정 → 드롭·경험치·골드** | 보고만 한다 | ✔ 굴린다 |
| 레벨·스킬 포인트 | 받아서 그린다 | ✔ |
| 가방·장비·장착·정렬 | 받아서 그린다 | ✔ |
| 상점·강화·크리스탈·스킬 경험치 넣기 | 요청만 한다 | ✔ |
| 스킬 배우기·강화, 전직 | 요청만 한다 | ✔ |
| 물약 쿨타임 | ✔ (개수를 세지 않는다 — 장부가 아니다) | |
| 채팅·랭킹 | | ✔ |

기기는 서버가 준 장부(레벨·장비)로 스탯을 만들어 싸운다. 장비를 기기에서 부풀려도
**서버에 없는 장비라 다음 접속에 사라지고**, 보상 계산에도 안 쓰인다.

## 처치 보고를 어떻게 믿나 ★

전투가 기기에 있는 이상 "잡았다" 는 주장이다. 완전히 막을 수는 없고,
**벌 수 있는 양의 상한을 데이터로 묶는다.**

1. **스폰 명부는 서버가 준다.** 존에 들어가면 서버가 몬스터 개체 id 와 종류를
   내려준다. 처치 보고는 그 id 로만 받고, **한 id 는 한 번만** 인정한다.
   되살아나는 시각(`respawn_ms`)도 서버가 안다 → 한 존에서 벌 수 있는 최대치가
   **스폰 수 × 리스폰 속도**로 고정된다. 추정이 아니라 표에서 나온 상한이다.
2. **최소 처치 시간.** 서버는 장비·레벨을 알기 때문에 그 캐릭터의 최대 DPS 를
   계산할 수 있다. 몬스터 체력 ÷ 최대 DPS 보다 빨리 잡았다는 보고는 버린다.
3. **존 입장 조건.** 레벨이 모자란 존의 처치는 인정하지 않는다.
4. **이상치는 기록만 한다.** 상한에 자주 닿는 계정은 로그에 남긴다. 제재는 사람이 한다.

기기에서 무적을 켜도 처치 속도가 빨라질 뿐이고, 그 속도는 1·2번에 걸린다.
물약은 개수를 세지 않고 쿨타임만 막으므로 애초에 장부가 아니다.

## 통로

`Transport` 앞면은 그대로 둔다 (화면 코드는 한 줄도 안 바뀐다).
`World` 안에서 **장부를 바꾸는 자리만 `Ledger` 로 뗐다** (2026-09-28, 1단계).

| 파일 | 역할 |
|---|---|
| `godot/world/ledger.gd` | ✔ 장부 판정 한 벌 — `kill`(드롭·경험치·레벨·전직 시험) · `buy`/`sell` · `enhance`/`enhance_many` · `use_crystal` · `equip`/`unequip`/`sort_bag` · `learn_skill`/`feed_upgrade` · `grant_once`/`grant_starter_gear`. 서버와 로컬이 **같은 파일**을 쓴다 |
| `World._ledger_call` | ✔ **장부로 가는 단 하나의 길.** 부르고 → 이벤트를 흘리고 → 스탯을 다시 만들고 → 레벨이 올랐으면 체력을 채운다 |
| `godot/server/ledger_server.gd` | ✔ 서버의 판정 — 메시지 하나 → 답 하나. 소켓을 모른다. `OPS` 에 있는 장부 요청만 받는다 |
| `godot/server/account_store.gd` | ✔ 계정 저장소 — 계정 하나 = JSON 파일 하나 (아래 "저장") |
| `godot/server/game_server.gd` | ✔ 웹소켓으로 받아 `LedgerServer` 에 넘긴다. `poll` 을 부르는 쪽이 돌린다 |
| `godot/server/server_main.gd` | ✔ 서버 실행 파일 (아래 "띄우기") |
| `godot/tests/server_test.gd` | ✔ 저장소 · 요청·거절 · 같은 번호 두 번 · 실제 웹소켓 왕복 · 새 계정 = `World.join` |
| `godot/net/server_ledger.gd` | (3단계) 기기 쪽 — 같은 요청을 서버로 보내고 답으로 장부를 덮는다 |

`Ledger` 는 **`KEYS` 칸만 만진다**(직업·전직 단계·레벨·경험치·골드·스킬·스킬 포인트·스킬 강화·스킬 경험치·
가방·장비·`granted`). 자리·체력·NPC 거리는 모른다 — NPC 곁인지는 `World` 가 먼저 본다.
굴림은 `World._rng` 를 같이 쓴다 (테스트가 씨앗으로 결과를 고정한다).

**`World` 에 남은 장부 변경은 둘뿐이다** — 치트·테스트 모드(`debug_*`·`grant_test_*`, 서버에는
없다)와 저장 불러오기(`restore`, 3단계에서 서버의 welcome 으로 바뀐다). 그 밖에 새로 넣지 않는다.

- 지금은 `_ledger_call` 이 `Ledger` 를 **바로** 부른다. 3단계에서 이 자리를 갈라
  **테스트 모드는 지금처럼, 일반 모드는 `server_ledger`** 로 보낸다
  ([play-mode.md](play-mode.md)). 개발과 GitHub Pages 화면은 서버 없이 계속 돈다.
- 치트 요청(`debug*`·`testKit`·`invincible`…)은 **서버에 없다.** 일반 모드에서는 보낼 곳이 없다.
- 요청마다 번호(`id`)를 붙인다. 계정마다 **늘기만 한다.** 서버는 마지막 번호와 그 답을 계정 파일에
  남겨서, 끊겼다 같은 번호로 다시 보내면 **판정하지 않고 그 답을 다시 준다** — 두 번 깎이거나
  두 번 받지 않는다. 지난 번호는 `stale` 로 거절한다. 기기는 welcome 의 `last_req` 다음부터 쓴다.
- 상점·대장간이 NPC 곁인지는 **기기만 본다** — 자리는 서버에 없다. 멀리서 사고팔아도 값은 서버가
  정하니 버는 길이 되지는 않는다.

### 주고받는 것 (웹소켓, JSON 한 줄)

| 기기 → 서버 | 서버 → 기기 |
|---|---|
| `{t:"hello", token?}` | `{t:"welcome", ledger, last_req, token?}` — 토큰이 없거나 틀리면 **새 게스트 계정**(첫 스킬 + 시작 장비)을 만들고 그때만 `token` 을 준다 |
| `{t:"op", id, op, args}` | `{t:"result", id, ledger, events}` — `ledger` 는 `KEYS` 칸 통째, `events` 는 로컬과 같은 이벤트 |
| | `{t:"error", id?, reason}` — `no_hello` · `no_id` · `stale` · `unknown_op` · `bad_args` · `unknown_type` · `bad_message` · `store_failed` |

`OPS`(받는 요청과 인자 모양): `learn_skill` · `feed_upgrade` · `equip` · `unequip` · `sort_bag` ·
`use_crystal` · `buy` · `sell` · `enhance` · `enhance_many`. JSON 숫자는 실수로 오므로 모양대로 바꾸고,
모양이 틀리면 `bad_args`.

- **`kill` 은 아직 받지 않는다** — 처치 보고는 스폰 명부로 다시 봐야 해서 4단계에서 연다.
- **`grant_once` 는 끝까지 받지 않는다** — 기기가 "이걸 줘" 라고 할 수 있게 되면 끝이다.
  한 번 주는 것은 서버가 스스로 준다 (시작 장비는 계정을 만들 때).
- 새 계정의 장부는 `Ledger.fresh` 하나에서 나온다. `World.join` 의 새 캐릭터와 같아야 해서
  `server_test` 가 둘을 칸마다 대 본다.

### 띄우기

```bash
godot --headless --path godot --script server/server_main.gd -- --port=8765 --data=/srv/mmorpg/accounts
```

`--bind` 를 안 주면 `127.0.0.1` 에서만 듣는다 — TLS 는 앞에 선 Caddy 가 `wss://` 로 받아 넘긴다.
`--data` 를 안 주면 고도의 사용자 폴더(`user://accounts`)에 둔다. 서버도 **게임과 같은 프로젝트**
(`godot/`)라 `ledger.gd`·`items.gd`·`data/*.json` 을 그대로 읽는다.
- 드롭은 왕복(보통 50~100ms) 뒤에 뜬다. 몬스터가 쓰러지는 연출이 그보다 길어서 티가 안 난다.

## 저장

`user://save.json` 의 장부 칸(레벨·경험치·골드·가방·장비·스킬·`granted`)은 **서버 DB 로
간다.** 기기에는 자리·설정(물약 %·액션바)만 남는다. 칸이 바뀌므로 `VERSION` 을 올리고
옛 저장은 버린다 — 아직 사용자가 없어서 지금이 제일 싸다.

- **계정 하나 = JSON 파일 하나** (`<id>.json`) ★ (2026-09-28 사용자 선택). 처음에는 SQLite
  (`godot-sqlite`)였는데 **클라우드 세션에서 확장을 받을 수 없어**(403) 세션마다 서버 테스트를 못
  돌리거나 `.so` 를 저장소에 넣어야 했다. 플레이어끼리 거래가 없으니 여러 계정을 묶는 트랜잭션이
  필요 없고, 랭킹은 서버가 켤 때 읽어 메모리에 든다. 커지면 `account_store.gd` 만 DB 로 갈아 끼운다.
- 쓰기는 **임시 파일 → 이름 바꾸기** — 쓰다가 꺼져도 앞의 것이 온전히 남는다.
- 토큰은 `<id>.<비밀>` 이고 파일에는 **비밀의 해시만** 남긴다. id 는 16자리 16진수만 받는다 —
  토큰에 `../` 를 넣어 밖의 파일을 읽지 못하게.
- 확장이 없으니 ARM 확인도 가벼워졌다 — 고도 **공식 linux arm64 빌드**가 돌면 된다. 오라클에
  올릴 때 그 빌드로 `server_test` 를 한 번 돌린다.
- 계정은 처음에는 **기기 토큰(게스트)**. 구글·애플 로그인은 출시 전에 붙인다.
- 백업은 **오라클 밖**에 둔다. 무료 계정이 예고 없이 막힌 사례가 있다.

## 어디에 올리나

오라클 무료 티어 A1(ARM 4코어·24GB) 한 대. 계정은 **종량제로 바꾸고**(유휴 회수 방지)
**할당량 정책**으로 무료 한도 밖 자원을 못 만들게 막는다. 예산 알림 1달러.
HTTPS/WSS 는 Caddy 가 인증서를 받는다. 동시 접속 수천 명까지는 이 한 대로 본다.

## 손댈 때

- `World` 에 **장부를 바꾸는 코드를 새로 넣으면 안 된다.** 1단계 뒤에는 `ledger.gd` 에 넣는다.
- 드롭률·강화 확률을 고치면 `ledger.gd` 한 곳만 고치면 서버·로컬이 같이 바뀐다.
- 옛 Colyseus 서버(`packages/server`)의 계정·토큰·DB 스키마는 대조용으로 읽는다
  ([persistence.md](persistence.md)). 예측·보정([networking-state.md](networking-state.md))은
  이 구조에서는 **필요 없다** — 움직임은 서버로 가지 않는다.
