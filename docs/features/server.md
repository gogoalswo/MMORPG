# 서버 — 장부만 판정한다

## 무엇

플레이어끼리는 **만나지 않는다**. 전투·이동·몬스터는 지금처럼 **기기 안에서** 돈다.
서버는 **"값이 생기고 없어지는 것"** 만 판정한다 — 경험치·레벨·골드·가방·장비·강화·
스킬·전직, 그리고 **드롭**. 그 위에 채팅과 랭킹을 얹는다.

2026-09-28 에 정했다 ("드롭까지 서버에서 판정하는 걸로 가자").
**7단계(유료 재화 — 서버 검증)까지 들어갔다** — 판정은 `ledger.gd`, 서버는 `godot/server/`, 기기는 서버 주소가
있으면 `ServerLedger` 로 붙는다. **아직 올린 서버가 없어서** 주소는 비어 있고, 화면은 전처럼 혼자 논다.
아래 "단계" 가 순서다.

## 왜 이렇게 나눴나 ★★

- **쓰는 것만 검증하면 소용없다.** 전투가 기기 안에 있으면 "몬스터 잡아서 골드 10만"
  이라는 보고를 믿을 근거가 없다. 버는 쪽이 뚫리면 쓰는 쪽 검증은 그냥 통과한다.
  그래서 **드롭을 굴리는 것도 서버다** — `_kill` 의 주석 "굴리는 쪽은 언제나
  판정하는 쪽이다" 그대로다.
- **전투까지 서버로 옮기지 않는다.** 만나지 않는 게임에서 매 틱 입력을 서버로 보내면
  비용(서버·지연·보정)만 늘고 얻는 게 없다. 옛 16단계 계획("고도 헤드리스가 `World`
  를 통째로 돈다")은 **이 결정으로 바뀌었다.**
- **서버도 고도 헤드리스다.** 드롭·랜덤 옵션·강화 확률·스탯 계산이 GDScript
  (`items.gd`·`stats.gd`·`combat.gd`)에 있다. Node 로 짜면 판정이 두 언어 두 벌이 된다
  ([godot-migration.md](godot-migration.md) "왜 서버까지 고도로 가나").
  서버는 이 파일들을 **그대로 불러 쓴다.**

## 판정을 둘로 가른다

| | 기기 (`World`) | 서버 (`Ledger`) |
|---|---|---|
| 이동·충돌·카메라 | ✔ | |
| 몬스터 AI·체력·피해 계산 | ✔ | |
| 스킬 시전·쿨타임·이펙트 | ✔ | |
| **처치 인정 → 드롭·경험치·골드** | 보고만 한다 | ✔ 굴린다 |
| 레벨·스킬 포인트 | 받아서 그린다 | ✔ |
| 가방·장비·장착·정렬 | 받아서 그린다 | ✔ |
| 상점·강화·크리스탈·스킬 경험치 넣기 | 요청만 한다 | ✔ |
| 스킬 배우기·강화, 전직 | 요청만 한다 | ✔ |
| 물약 쿨타임 | ✔ (개수를 세지 않는다 — 장부가 아니다) | |
| 채팅·랭킹 | | ✔ |

기기는 서버가 준 장부(레벨·장비)로 스탯을 만들어 싸운다. 장비를 기기에서 부풀려도
**서버에 없는 장비라 다음 접속에 사라지고**, 보상 계산에도 안 쓰인다.

## 처치 보고를 어떻게 믿나 ★

전투가 기기에 있는 이상 "잡았다" 는 주장이다. 완전히 막을 수는 없고,
**벌 수 있는 양의 상한을 데이터로 묶는다.**

✔ 4단계(2026-09-28)에 들어갔다 — `LedgerServer._enter` · `_check_kill` · `server/kill_check.gd`.

1. **몬스터 명단은 서버도 안다.** 기기가 존에 들어가면 `enter` 를 보내고, 서버는 그 존의
   명단(`World.roster` — id·종류·되살아나는 시간, 자리는 없다)을 센다. 명단은 존 표에서
   결정적으로 나온다(`<종류>_<번호>`) — 기기의 `_spawn_monsters` 와 같은 규칙이라
   `server_test` 가 모든 존에서 둘을 대 본다. 처치 보고는 `{kind, zone, id}` 이고
   **그 존 · 그 id · 그 종류**가 명단과 맞아야 받는다(`wrong_zone` · `not_in_roster`).
   한 id 는 되살아나기 전에 두 번 못 잡는다(`not_respawned`) → 한 존에서 벌 수 있는 최대치가
   **명단 수 × 되살아나는 속도**로 묶인다. 추정이 아니라 표에서 나온 상한이다.
   존에 다시 들어오면 명단을 새로 센다 — 기기도 존을 다시 열면 몬스터를 새로 놓는다.
2. **최소 처치 시간** (`KillCheck.min_ms`, `too_fast`). 서버는 레벨·장비·배운 스킬·강화를 안다.
   피해가 공격력에 비례하므로 "시간 W 동안 넣을 수 있는 배율" 의 **상한**을 세운다 —
   **시전 잠금을 무시하고 모든 스킬을 동시에 쏘고 치명타가 늘 터진다고** 친다. 그래서 실제보다
   늘 크다. 몬스터가 나올 수 있게 된 때(들어온 때 · 되살아난 때)부터 그 W 의 **절반**에서
   1.5초(네트워크 흔들림)를 뺀 것보다 빨리 잡았다는 보고는 버린다.
   - 그래서 **약한 몬스터는 0초**다 (새 캐릭터가 평타로 5.4초 걸리는 초원 몬스터도 한 번에
     쏟으면 잡힌다). 약한 몬스터는 1번(명단 × 되살아나기)이 묶고, 이것은 체력 큰 몬스터·보스에서 걸린다.
   - **정상 플레이를 거절하는 쪽이 훨씬 나쁘다** — 그래서 넉넉하게 잡았다. 좁히려면 시전 잠금부터 넣는다.
   - 스킬·강화 표에 **처치 검증이 모르는 칸**이 생기면 `server_test` 가 실패한다
     (`KNOWN_SKILL_KEYS` · `KNOWN_UPGRADE_KEYS`). 피해를 올리는 효과면 `min_ms` 에 넣는다.
3. **존 입장 조건** (`zone_locked`). **게임에 있는 규칙만 본다** — 전직 시험은 바로 다음 단계이고
   레벨이 될 때만 (`World.job_advance` 와 같다). 일반 사냥터는 게임에도 막는 규칙이 없어서
   서버도 안 막는다. 새 규칙을 서버에서 지어내지 않는다.
   ★ **던전 하루 한 번**(2026-10-02)은 게임 규칙이라 서버도 본다 — `_enter` 가 `Ledger.dungeon_entries_left`
   로 대 보고 다 썼으면 `daily_used`, 되면 `Ledger.dungeon_enter` 로 장부에 센다(서버에 붙으면 세는 쪽은 서버다).
   던전 몬스터는 한 번 들어와 한 번만 잡는다 — 같은 개체를 또 보고하면 `_check_kill` 이 `once_per_entry`
   → [dungeons.md](dungeons.md) "하루 한 번".
4. **이상치는 기록만 한다.** 거절한 처치는 서버 출력에 `처치 거절 <계정> <이유>` 로 남기고
   보상만 안 준다. 제재는 사람이 한다.

- 사냥 상태(존·들어온 때·잡은 시각)는 **메모리에만** 둔다 — 서버를 다시 켜면 다음 `enter` 부터 센다.
- 끊겨 있는 동안 같은 몬스터를 두 번 잡으면(되살아나는 시간보다 길게 끊겼을 때) 다시 붙어
  한꺼번에 도착한 두 번째 보고는 `not_respawned` 로 거절될 수 있다. 드물고, 보상 한 번이 빠질 뿐이다.

기기에서 무적을 켜도 처치 속도가 빨라질 뿐이고, 그 속도는 1·2번에 걸린다.
물약은 개수를 세지 않고 쿨타임만 막으므로 애초에 장부가 아니다.

## 통로

`Transport` 앞면은 그대로 둔다 (화면 코드는 한 줄도 안 바뀐다).
`World` 안에서 **장부를 바꾸는 자리만 `Ledger` 로 뗐다** (2026-09-28, 1단계).

| 파일 | 역할 |
|---|---|
| `godot/world/ledger.gd` | ✔ 장부 판정 한 벌 — `kill`(드롭·경험치·레벨·전직 시험) · `buy`/`sell` · `enhance`/`enhance_many` · `use_crystal` · `equip`/`unequip`/`sort_bag` · `learn_skill`/`feed_upgrade` · `grant_once`/`grant_starter_gear`. 서버와 로컬이 **같은 파일**을 쓴다 |
| `World._ledger_call` | ✔ **장부로 가는 단 하나의 길.** 부르고 → 이벤트를 흘리고 → 스탯을 다시 만들고 → 레벨이 올랐으면 체력을 채운다 |
| `godot/server/ledger_server.gd` | ✔ 서버의 판정 — 메시지 하나 → 답 하나. 소켓을 모른다. `OPS` 에 있는 장부 요청만 받는다 |
| `godot/server/kill_check.gd` | ✔ 최소 처치 시간 — 이 캐릭터가 이 몬스터를 이보다 빨리 잡을 수 없다 (넉넉한 상한) |
| `godot/server/account_store.gd` | ✔ 계정 저장소 — 계정 하나 = JSON 파일 하나 (아래 "저장") |
| `godot/server/game_server.gd` | ✔ 웹소켓으로 받아 `LedgerServer` 에 넘긴다. `poll` 을 부르는 쪽이 돌린다 |
| `godot/server/server_main.gd` | ✔ 서버 실행 파일 (아래 "띄우기") |
| `godot/tests/server_test.gd` | ✔ 저장소 · 요청·거절 · 같은 번호 두 번 · 실제 웹소켓 왕복 · 새 계정 = `World.join` |
| `godot/net/server_ledger.gd` | ✔ 기기 쪽 — 요청을 쌓아 보내고, 답(`replied`)·welcome 으로 `World.apply_ledger` 가 장부를 덮는다. 끊기면 다시 붙는다 |
| `godot/net/local_transport.gd` | ✔ `server_url()` 이 있고 **일반 모드**면 `_attach` — `World.remote` 에 꽂고 매 프레임 `poll` |
| `godot/tests/remote_test.gd` | ✔ 실제 웹소켓으로 `World` 를 서버에 붙인다 — welcome(시작 장비·첫 선물·정수) · 처치 · **답을 잃고 다시 붙어도 한 번만 판정** |

`Ledger` 는 **`KEYS` 칸만 만진다**(직업·전직 단계·레벨·경험치·골드·스킬·스킬 포인트·스킬 강화·스킬 경험치·
가방·장비·`granted`·다이아·헬스 프로틴과 운동 단계 → [fitness.md](fitness.md) · 던전 하루 입장 `dungeon_entries` → [dungeons.md](dungeons.md)). 자리·체력·NPC 거리는 모른다 — NPC 곁인지는 `World` 가 먼저 본다.
굴림은 `World._rng` 를 같이 쓴다 (테스트가 씨앗으로 결과를 고정한다).

**`World` 에 남은 장부 변경은 둘뿐이다** — 치트·테스트 모드(`debug_*`·`grant_test_*`, 서버에는
없다)와 저장 불러오기(`restore` — 서버에 붙으면 곧 welcome 이 장부 칸을 덮는다). 그 밖에 새로 넣지 않는다.

- `_ledger_call` 은 `World.remote` 가 **없으면** `Ledger` 를 바로 부르고, **있으면** 요청만 보낸다.
  기기는 먼저 바꿔 보이지 않는다 — 답이 오면 `apply_ledger` 가 `KEYS` 칸을 통째로 덮고
  이벤트를 흘리고 스탯을 다시 만든다(레벨이 올랐으면 체력을 채운다). 드롭·강화는 굴림이라
  기기가 먼저 보여 줄 값이 없다.
- **서버에 붙는 조건: 서버 주소가 있고 · 일반 모드.** 주소는 명령줄 `-- --server=ws://…` 이 먼저,
  없으면 프로젝트 설정 `mmorpg/server_url`. **테스트 모드는 안 붙는다** — 치트(`debug_*`)가
  기기에서 장부를 바꾸는데 서버 답이 덮어 버린다 ([play-mode.md](play-mode.md)).
  주소가 비어 있으면 전처럼 혼자 논다 — GitHub Pages 화면은 서버가 없어서 비워 둔다.
- 붙으면 **시작 장비·첫 선물은 서버가** 계정을 만들 때 준다 (`Ledger.welcome_gifts` — 로컬과 한 목록).
  토큰은 `user://account.json` 에 **서버 주소마다** 남긴다.
- 끊기면 `RETRY_MS`(2초) 뒤에 같은 토큰으로 다시 붙는다. 답을 못 받은 요청은 welcome 의 `last_req`
  로 가린다 — 그보다 작으면 이미 판정됐으니 버리고, 같으면 다시 보내 **남겨 둔 답**을 받고,
  크거나 안 보낸 것은 보낸다(안 보낸 것은 `last_req` 뒤로 번호를 새로 매긴다).
- JSON 은 정수를 실수로 준다(`3` → `3.0`). 서버가 계정 파일을 읽을 때와 기기가 답을 받을 때
  `Ledger.from_json` 으로 **정수인 실수는 정수로** 되돌린다.
- 치트 요청(`debug*`·`testKit`·`invincible`…)은 **서버에 없다.** 일반 모드에서는 보낼 곳이 없다.
- 요청마다 번호(`id`)를 붙인다. 계정마다 **늘기만 한다.** 서버는 마지막 번호와 그 답을 계정 파일에
  남겨서, 끊겼다 같은 번호로 다시 보내면 **판정하지 않고 그 답을 다시 준다** — 두 번 깎이거나
  두 번 받지 않는다. 지난 번호는 `stale` 로 거절한다. 기기는 welcome 의 `last_req` 다음부터 쓴다.
- 상점·대장간이 NPC 곁인지는 **기기만 본다** — 자리는 서버에 없다. 멀리서 사고팔아도 값은 서버가
  정하니 버는 길이 되지는 않는다.

### 주고받는 것 (웹소켓, JSON 한 줄)

| 기기 → 서버 | 서버 → 기기 |
|---|---|
| `{t:"hello", token?}` | `{t:"welcome", ledger, last_req, token?}` — 토큰이 없거나 틀리면 **새 게스트 계정**(첫 스킬 + 시작 장비)을 만들고 그때만 `token` 을 준다 |
| `{t:"op", id, op, args}` | `{t:"result", id, ledger, events}` — `ledger` 는 `KEYS` 칸 통째, `events` 는 로컬과 같은 이벤트 |
| | `{t:"error", id?, reason}` — `no_hello` · `no_id` · `stale` · `unknown_op` · `bad_args` · `unknown_type` · `bad_message` · `store_failed` |

`OPS`(받는 요청과 인자 모양): `enter` · `kill` · `learn_skill` · `feed_upgrade` · `equip` · `unequip` · `sort_bag` ·
`use_crystal`(어디 · 번호/슬롯 · **차수** 2/3) · `buy` · `sell` · `enhance` · `enhance_many` · `trial_clear` · `sandbag_record` ·
`set_loot_skip`(안 주울 장비 등급 목록 → [hud.md](hud.md) "설정 창")
(→ [sandbag.md](sandbag.md) "서버가 기록을 믿는 근거"). JSON 숫자는 실수로 오므로 모양대로 바꾸고,
모양이 틀리면 `bad_args`.

- **`kill` 은 `{kind, zone, id}` 만 받는다** — 레벨·경험치·보스 여부는 `Ledger.kill` 이 몬스터 표에서
  찾는다. 기기가 수치를 보내면 서버가 그 값을 믿어야 해서다. 판정 전에 위 "처치 보고를 어떻게 믿나" 로
  대 본다 — 거절 이유는 `no_zone` · `wrong_zone` · `not_in_roster` · `not_respawned` · `too_fast`.
- **`trial_clear`**(존 이름) — 시련의 탑 통과. 서버가 **제가 인정한 처치**(`_hunts` 의 `killed`) 중
  들어온 때부터 제한 시간 + `SLACK_MS` 안에 잡은 것을 세어 필요한 수(7)에 닿아야 크리스탈을 준다
  (`LedgerServer._check_trial`). 거절 이유는 `wrong_zone` · `not_trial` · `too_few` · `claimed`(한 번
  들어와 한 번만) → [dungeons.md](dungeons.md) "시련의 탑".
- **`enter`**(존 이름)는 장부를 바꾸지 않는다 — 서버가 명단을 세고 입장 조건(`zone_locked` ·
  `no_zone`)을 본다. 기기는 붙을 때(`LocalTransport._attach`)와 존을 옮길 때(`World.open`) 보낸다.
- **`grant_once` 는 끝까지 받지 않는다** — 기기가 "이걸 줘" 라고 할 수 있게 되면 끝이다.
  한 번 주는 것은 서버가 스스로 준다 (시작 장비는 계정을 만들 때).
- 새 계정의 장부는 `Ledger.fresh` 하나에서 나온다. `World.join` 의 새 캐릭터와 같아야 해서
  `server_test` 가 둘을 칸마다 대 본다.

### 띄우기

```bash
godot --headless --path godot --script server/server_main.gd -- --port=8765 --data=/srv/mmorpg/accounts
```

`--bind` 를 안 주면 `127.0.0.1` 에서만 듣는다 — TLS 는 앞에 선 Caddy 가 `wss://` 로 받아 넘긴다.
`--data` 를 안 주면 고도의 사용자 폴더(`user://accounts`)에 둔다. 서버도 **게임과 같은 프로젝트**
(`godot/`)라 `ledger.gd`·`items.gd`·`data/*.json` 을 그대로 읽는다.
- 드롭은 왕복(보통 50~100ms) 뒤에 뜬다. 몬스터가 쓰러지는 연출이 그보다 길어서 티가 안 난다.

주고받는 것:

| 기기 → 서버 | 서버 → 모두 |
|---|---|
| `{t:"chat", text}` | `{t:"chat", from, text}` · 알림은 `{t:"chat", system:true, text}` |
| | 거절: `{t:"error", reason}` — `no_hello` · `chat_empty` · `chat_limit` |

- **보낸 사람에게 따로 답하지 않는다** — 제 말도 방송으로 돌아와 채팅창에 적힌다. 그래서
  기기는 먼저 적지 않는다(서버가 잘랐거나 막았으면 다르게 보인다).
- **이름은 서버가 붙인다** (`name_of` — 계정의 이름, 없으면 `display_name` = `모험가#` + 계정 id 앞 네 자리).
  기기가 채팅에 실은 `from` 은 버린다 — 믿으면 남의 이름으로 말할 수 있다. 계정의 이름은 hello 의 `name` 을
  **`Names` 규칙으로 다시 걸러** 남긴 것이다(시작 화면에서 정한다) → [play-mode.md](play-mode.md) "이름".
  welcome 에 확정한 `name` 을 싣는다.
- **다듬기** — 줄바꿈·제어 문자를 빼고 앞뒤 공백을 자르고 **100자**(`CHAT_MAX_LEN`)에서 자른다.
  빈 말은 `chat_empty`. 기기 입력칸도 100자까지만 받는다.
- **도배 막기** — 연달아 **3번**(`CHAT_BURST`), 그 뒤로는 **2초에 한 번**씩 찬다(`CHAT_REFILL_MS`).
  막히면 `chat_limit` → 기기가 채팅창에 "말을 너무 빨리 보냈습니다" 를 적는다.
- **지난 줄** — 서버가 최근 **30줄**(`CHAT_HISTORY`)을 메모리에 들고 welcome 에 싣는다. 들어오자마자
  채팅창이 비어 있지 않게. 서버를 다시 켜면 비운다 (저장하지 않는다).
- **알림** — 장부 요청의 답 이벤트를 보고 `ANNOUNCE_ENHANCE`(**+7**) 이상 강화 성공만 알린다
  (한 번 강화는 장비 이름까지, 다중 강화는 단계만). 같은 번호로 다시 보낸 요청은 남겨 둔 답을
  돌려줄 뿐이라 **두 번 알리지 않는다.** 알릴 것을 늘리면 `_announce` 에 넣는다.
- **말은 글자 그대로 적는다** — `ChatLog` 는 `add_text` 로 넣어서 남이 보낸 `[color]` 같은 BBCode 가
  서식으로 읽히지 않는다. 읽히면 남의 채팅창 모양을 바꿀 수 있다 (`chat_log_test` 가 본다).
- **채팅은 쌓아 두었다 보내지 않는다** — 끊겨 있으면 `say` 가 false 로 버린다. 다시 붙었을 때
  한참 전 말이 뒤늦게 가면 엉뚱하다. 장부 요청과 다르다.
- 채팅은 `World` 를 거치지 않는다 — 장부가 아니라 사람끼리 오가는 말이다.

## 유료 재화 — 다이아 (7단계) ★

2026-09-28 사용자 선택: **이름은 다이아 · 충전과 검증만 먼저(무엇을 파는지는 아직 없다) · 구글 플레이만.**
서버 쪽 검증은 다 들어갔고, **실제로 켜려면 아래 "켜려면 필요한 것"** 이 남았다.

| 파일 | 역할 |
|---|---|
| `packages/shared/src/store.ts` → `godot/data/store.json` | 상품 표 — 플레이 상품 id → 다이아 수 (`dia_100` 100 · `dia_550` 550 · `dia_1200` 1200, **임시**). 가격은 플레이 콘솔이 정한다 |
| `world/ledger.gd` `diamonds` · `credit_diamonds` | 장부 칸. **기기가 부를 수 있는 요청(`OPS`)에는 없다** — 들어오는 길은 결제 검증 하나 |
| `server/ledger_server.gd` `_purchase` · `poll_jobs` · `_finish_purchase` · `take_replies` | 영수증 받기 · 검증 일감 · 다이아 넣기 · 그 연결에만 답하기 |
| `server/purchase_verifier.gd` · `google_play_verifier.gd` | 검증기 틀 · 구글 플레이 (서비스 계정 JWT → 접근 토큰 → `purchases.products.get`) |
| `server/http_call.gd` | 노드 없이 `poll` 로 도는 HTTP 요청 한 번 (`LedgerServer` 는 노드가 아니다) |
| `server/account_store.gd` `find_order` · `write_order` | 주문 기록 — `orders/<구매 토큰의 sha256>.json`. 토큰 원문은 안 남긴다 |
| `net/server_ledger.gd` `purchase` · `purchase_done` 신호 | 영수증 보내기 · 결과 받기 (`purchased` 면 장부도 덮는다) |

주고받는 것: `{t:"purchase", product, token}` → (검증이 끝나면) `{t:"purchased", product, diamonds, ledger, events, already?}`
또는 `{t:"error", reason, product}` — `store_off` · `unknown_product` · `bad_token` · `in_progress` ·
`order_taken` · `purchase_invalid`(+`detail`: `canceled` · `pending` · `consumed` · `http …`) · `store_failed`.

- **개수는 상품 표에서 찾는다** — 기기가 보낸 개수는 없다.
- **영수증 한 장에 한 번.** 구매 토큰의 해시로 주문 파일을 남겨 **어느 계정이든** 두 번 못 받는다.
  같은 계정이 다시 보내면 `already` 로 받은 것처럼 답한다 — 기기는 이제 그 구매를 소모하면 된다.
  다른 계정이면 `order_taken`. 검증 중에 또 보내면 `in_progress`.
- **계정을 먼저 쓰고(`account.orders` 에 표시) 주문 파일을 뒤에 쓴다.** 사이에 꺼지면 계정의 표시가
  두 번 받는 것을 막는다. 반대 순서면 돈만 나가고 다이아가 없는 채로 남을 수 있다.
- **구글이 "결제됨(`purchaseState 0`) · 아직 소모 안 됨(`consumptionState 0`)" 이라고 해야** 넣는다.
- 검증은 시간이 걸려서 **일감**으로 돈다 — `_purchase` 는 빈 답을 주고, `GameServer.poll` 이 매 프레임
  `poll_jobs` 를 돌려 끝난 것을 **그 연결에만** 보낸다. 그사이 끊겼으면 버린다 — 기기가 다음에 같은
  영수증을 또 보내면 `already` 로 받는다.
- 접근 토큰은 한 시간 가니 **만료 1분 전까지 다시 쓴다** (여러 결제가 한 번만 받는다).
- 거절·결제는 서버 출력에 `결제 거절 …` · `결제 … +N` 으로 남는다.
- 테스트: `server_test` 가 가짜 검증기로 흐름 전부(한 번만 · 다른 계정 · 취소 · 다시 켜도 기억 · 계정만
  쓰고 꺼진 경우)를, **테스트 안에 띄운 가짜 구글**로 `GooglePlayVerifier` 를 실제 HTTP 로 본다
  (JWT 서명은 진짜 RSA 키로 만들고 공개키로 풀어 본다). `remote_test` 는 웹소켓으로 영수증을 보내
  기기의 다이아가 느는 것까지 본다.

### 켜려면 필요한 것 (사용자 몫)

1. **플레이 콘솔** — 앱을 올리고 소모성 인앱 상품 `dia_100` · `dia_550` · `dia_1200` 을 만들고 가격을 정한다.
2. **서비스 계정 키** — 구글 클라우드에서 서비스 계정을 만들어 플레이 콘솔에 "재무 데이터 보기 ·
   주문 관리" 권한으로 초대하고, 키(JSON)를 받아 **서버 기계에만** 둔다 (저장소에 넣지 않는다).
   서버를 `--play-package=<패키지 이름> --play-key=<키 경로>` 로 띄운다.
3. **기기 쪽 결제** — 고도 안드로이드 빌드에 구글 플레이 결제 플러그인을 붙여 상점 창에서 사게 하고,
   받은 구매 토큰을 `Transport.send(&"purchase", {product, token})` 로 보낸다. **`purchased` 를 받은
   뒤에만 소모(consume)한다** — 그래야 같은 상품을 또 살 수 있고, 소모하지 않은 구매는 3일 뒤 구글이
   환불한다. 이 부분(플러그인·상점 창·다이아 표시)은 아직 없다.

## 저장

서버에 붙으면 장부의 원본은 **서버의 계정 파일**이다. `user://save.json` 은 **형식을 그대로 둔다** —
자리·설정(물약 %·액션바)을 거기서 읽고, 장부 칸은 welcome 이 곧 덮는다. 기기가 저장에 적는 장부
칸은 서버에서 받은 것의 사본일 뿐이라 해가 없다. 그래서 처음 계획했던 `VERSION` 올리기는 안 했다
(옛 저장을 버릴 이유가 없다). 서버 주소를 비우면 그 사본으로 혼자 논다.

- **계정 하나 = JSON 파일 하나** (`<id>.json`) ★ (2026-09-28 사용자 선택). 처음에는 SQLite
  (`godot-sqlite`)였는데 **클라우드 세션에서 확장을 받을 수 없어**(403) 세션마다 서버 테스트를 못
  돌리거나 `.so` 를 저장소에 넣어야 했다. 플레이어끼리 거래가 없으니 여러 계정을 묶는 트랜잭션이
  필요 없고, 랭킹은 서버가 켤 때 읽어 메모리에 든다. 커지면 `account_store.gd` 만 DB 로 갈아 끼운다.
- 쓰기는 **임시 파일 → 이름 바꾸기** — 쓰다가 꺼져도 앞의 것이 온전히 남는다.
- 토큰은 `<id>.<비밀>` 이고 파일에는 **비밀의 해시만** 남긴다. id 는 16자리 16진수만 받는다 —
  토큰에 `../` 를 넣어 밖의 파일을 읽지 못하게.
- 확장이 없으니 ARM 확인도 가벼워졌다 — 고도 **공식 linux arm64 빌드**가 돌면 된다. 오라클에
  올릴 때 그 빌드로 `server_test` 를 한 번 돌린다.
- 계정은 처음에는 **기기 토큰(게스트)**. 구글·애플 로그인은 출시 전에 붙인다.
- 백업은 **오라클 밖**에 둔다. 무료 계정이 예고 없이 막힌 사례가 있다.

## 어디에 올리나

오라클 무료 티어 A1(ARM 4코어·24GB) 한 대. 계정은 **종량제로 바꾸고**(유휴 회수 방지)
**할당량 정책**으로 무료 한도 밖 자원을 못 만들게 막는다. 예산 알림 1달러.
HTTPS/WSS 는 Caddy 가 인증서를 받는다. 동시 접속 수천 명까지는 이 한 대로 본다.

## 손댈 때

- `World` 에 **장부를 바꾸는 코드를 새로 넣으면 안 된다.** 1단계 뒤에는 `ledger.gd` 에 넣는다.
- 드롭률·강화 확률을 고치면 `ledger.gd` 한 곳만 고치면 서버·로컬이 같이 바뀐다.
- 옛 Colyseus 서버(`packages/server`)의 계정·토큰·DB 스키마는 대조용으로 읽는다
  ([persistence.md](persistence.md)). 예측·보정([networking-state.md](networking-state.md))은
  이 구조에서는 **필요 없다** — 움직임은 서버로 가지 않는다.
