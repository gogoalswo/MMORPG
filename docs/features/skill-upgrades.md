# 스킬 강화

## 무엇

스킬마다 **강화가 둘까지**(1번·2번) 붙는다. **던전을 깨면 스킬 경험치가 저절로 쌓이고**
(N단계 × 1000), **스킬창의 강화 칸**에서 강화 하나를 골라 **[넣기]** 로 그 경험치를 넣는다.
필요 경험치(**스킬의 전직 단계로 정한다** — 아래 표)에 닿으면 붙는다. 한 번 붙으면 계속
남는다(저장된다).

요청 흐름 (전부 2026-09-23):
1. "각 스킬별로 두 개씩 강화가 가능하게 … 스킬 강화서를 먹어서 사용하면 강화" →
   강화마다 강화서 한 장, 가방에서 "사용".
2. "스킬창에서 스킬 강화하는 ui 만들어. 인벤토리에서 사용하지 말고" → 스킬창 강화 칸.
3. **"스킬 강화를 개별로 하지 말고 스킬 강화 경험치북들 만들고 해당 경험치로 강화 …
   어떤 타입을 강화할지 선택해서 경험치를 넣을 수 있으면 … 특정 경험치에 도달하면
   스킬 강화 되도록"** → 경험치북 세 종류(하급 100 · 중급 500 · 상급 2000). 강화서는 없앴다.
4. **"하급, 중급, 상급 이렇게 나누지 말고, 던전 깨면 알아서 경험치를 습득하는 방식으로 해.
   1단계는 1000 … 2단계는 2000, 3단계는 3000"** (2026-09-28) → **지금 판.** 경험치북은
   없앴고, 넣는 곳은 사용자가 "모아 두고 골라 넣기" 를 골랐다. 옛 책은 "그냥 없애기".

## 규칙

### 경험치를 넣어 강화한다 ★★

- **던전 보스를 잡으면** 그 단계의 `skillExp`(단계 × 1000)가 캐릭터의 `skill_exp` 에
  더해진다 (`_check_dungeon_clear`). **잡을 때마다** 받는다 — 보스가 다시 서면(15분,
  나갔다 들어오면 바로) 또 받는다. 사냥터 보스·전직 시험 보스는 안 준다(던전 존이 아니다).
- **스킬창에서 카드를 눌러 강화를 고르고**(금테, 처음엔 1번), 아래 **[넣기]** 를 누르면
  모아 둔 경험치가 고른 강화에 **모자란 만큼만** 들어간다 — 남는 것은 `skill_exp` 에 그대로
  남아 다른 강화에 쓴다. (경험치북 판은 넘친 만큼 버렸다.)
- 쌓인 경험치가 그 강화의 `exp` 에 닿으면 **바로 붙는다.** 붙은 강화에는 더 못 넣는다
  (단추가 꺼진다). 경험치가 0 이어도 꺼진다.
- 가방에는 아무것도 안 들어온다 — 스킬 경험치는 물건이 아니라 캐릭터의 수치다.
- **남의 직업 스킬에는 못 넣는다.** 스킬을 **배웠는지는 안 본다** — 강화는 캐릭터에
  남으므로 나중에 배워도 붙어 있다.
- 필요 경험치는 **스킬의 전직 단계(`tier`)로 정한다** — `SKILL_UPGRADE_EXP_BY_TIER`
  (2026-09-28 요청. 그 전엔 다 1000 고정이었다):

  | 스킬 | 필요 경험치 | 지금 스킬 |
  |---|---|---|
  | 기본 (`tier` 0) | 1,000 | 할퀴기 |
  | 1차 전직 | 10,000 | 낙뢰 |
  | 2차 전직 | 50,000 | 빙주각 |
  | 3차 전직 | 200,000 | 천붕각 |
  | 4차 전직 | 1,000,000 | (아직 없다) |

  강화 표(`UPGRADE_LIST`)에는 적지 않고 `SKILL_UPGRADES` 를 만들 때 채운다 — 같은
  스킬의 두 강화는 늘 같은 값이다. 고도는 `skills.json` 의 `exp` 를 그대로 읽는다.
- **밸런스** (2026-09-28 에 계산해서 사용자에게 보였다) — 전직 레벨에 맞는 단계를 돈다고
  치면(N단계 보스 Lv.`N×10−1`) 강화 하나에 드는 클리어 수는 기본 1 · 1차(3단계) 4 ·
  2차(7단계) 8 · 3차(12단계) 17 · 4차(18단계) 56. 4차만 크게 뛴다 — 비용은 5배인데
  보상은 1000씩 는다. 길면 4차 비용을 50만으로 낮추면 28회다 (아직 안 바꿨다).

### 저장 ★

- `skill_upgrades: { 스킬 id: [강화 id…] }` — 붙은 것.
- `skill_upgrade_exp: { 스킬 id: { 강화 id: 경험치 } }` — **붙기 전까지** 쌓인 것.
  붙으면 그 줄을 지운다(`_add_upgrade`). 둘로 나눈 것은 옛 저장(붙은 목록만 있던 판)을
  그대로 읽기 위해서다.
- `skill_exp: 정수` — 아직 안 넣은 스킬 경험치 (2026-09-28).
- 둘 다 **없던 칸을 더한 것**이라 저장 `VERSION` 을 올리지 않았다 (`granted` 와 같은
  방식). 되살릴 때 **지금 표에 있는 것만**, 경험치는 **아직 안 붙은 것만** 남긴다.
- 앞 판의 강화서(`scroll_thunder_fall_stun`)와 경험치북(`skill_book_1~3`)은 재료 표에서
  빠졌다 — 가방에 남아 있으면 불러올 때 **돌려주지 않고** 버려진다 (`_restore_stack` 이
  모르는 id 를 버린다. 경험치북은 사용자가 "그냥 없애기" 를 골랐다).

### 스킬창 강화 칸 ★★

```
┌ 설명 ──────┬ 스킬 ─────────────────┬ 강화 ─────────────────┐ [X]
│ 큰 아이콘   │ 장착 중 [1][2][3][4]   │ ┏ 기절            1번 ┓ │
│ 이름        │ 스킬 목록 (4열)        │ ┃ 맞은 적 3초 기절     ┃ │
│ 요구 레벨…  │                        │ ┃ ▓▓▓░░░░░░░           ┃ │
│ 설명        │                        │ ┃ 경험치 300 / 1000    ┃ │
│             │                        │ ┗━━━━━━━━━━━━━━━━━━━━━┛ │
│             │                        │ ┌ 없음            2번 ┐ │
│             │                        │ 기절에 경험치 넣기       │
│             │          [해제] [장착] │ [하급+100][중급][상급]  │
└─────────────┴────────────────────────┴───────────────────────┘
```

- **셋째 칸(폭 280, `UPGRADE_W`)을 세웠다.** 설명 칸 밑이나 목록 밑에 줄로 넣으면 창이
  580 → 760px 가 되어 720 을 넘는다. 옆으로는 **1250 × 632** 로 1280 × 720 안에 든다.
- 카드는 **고른 스킬**을 따라간다 — 이름(붙었으면 금빛) · 번호 · 효과 · 경험치 막대 ·
  `경험치 300 / 1000` 또는 "강화 완료". 표에 없는 번호는 "없음 / 아직 없는 강화" 이고
  고를 수 없다.
- 카드는 스킬 칸처럼 **겉에 투명 단추(`hit`)를 덮고**, 고른 카드에 고른 칸 테두리
  (`_pick_box`)를 두른다.
- 넣기 단추는 카드 폭(280) 하나를 다 쓴다. 경험치북 판에는 단추 셋이 폭을 나눴다.
- 막대는 `ProgressBar` 에 코드 스타일(어두운 판 + 흐린 금 테, 채움 `#e8c14a` = 경험치
  글자색)을 입혔다. 새 조각은 없다 → [ui-art-style.md](ui-art-style.md).
- **창을 열면 맨 앞으로 올린다** (`move_to_front`). 넓어진 창이 왼쪽 테스트 단추 줄
  밑으로 들어가 단추 글자가 창 위에 찍혔다 (찍어서 봤다).

### 강화는 따로 붙고 같이 붙을 수도 있다 ★

"스턴 강화가 안 되고 범위 증가 강화만 했으면 색상은 변경하면 안되겠지" (요청).
그래서 **이펙트도 강화마다 따로** 바꾼다 — 기절은 번개의 **색만**, 범위는 **크기와
줄기 수만** 건드린다. 둘이 섞여도 서로를 덮지 않는다.

- 판정이 `skill` 이벤트에 `upgrades: [강화 id…]` 를 싣는다. 화면은 그것만 보고 고른다
  (`game.gd` `_show_skill`). 화면이 저장값을 따로 읽으면 판정과 어긋날 수 있다.

### 기절 ★

- **첫 대에서 건다** — 살아남은 놈에게만. 연타가 있어도 다시 걸지 않는다.
- 기절 동안 `_step_monsters` 가 그 놈을 건너뛴다 — 못 움직이고 못 때린다.
  상태는 `"stun"` 이고 화면은 `Idle` 을 돌린다 (모르는 상태는 대기로 본다).
- **예고한 보스 범위 공격은 기절해도 터진다.** 기절 검사를 예고 검사 **뒤**에 둔 이유다 —
  "한번 예고한 것은 그대로 터진다" ([godot-migration.md](godot-migration.md) "예고한 원은
  그 자리에 고정된다")를 기절이 깨면 원이 떠 있는데 안 터지는 일이 생긴다.
- 보스에게도 걸린다. 부활하면 풀린다 (`_respawn`).
- 기절한 놈 머리 위 표시는 **아직 없다** — 멈춰 서 있는 것으로만 보인다.

### 붉은 번개 ★

- 색 한 벌(`PALETTE_BLUE` · `PALETTE_RED`)은 **헤일로 · 색 빛 · 불똥** 셋이다.
  **흰 심과 금·그을림(흙)은 안 바뀐다** — 가장 밝은 자리가 희어야 빛으로 읽히고,
  땅은 번개 색과 상관없이 흙이다.
- 붉은 벌은 푸른 벌과 **밝기 순서를 맞췄다** — 헤일로 `#ff2a1a` 가 가장 짙고 색 빛
  `#ffa090` 이 옅다, 불똥 `#ff8a70`. 번쩍임 빛(`OmniLight3D`)도 헤일로 색이다.
- **풀은 한 벌을 같이 쓰고 되감을 때 색만 칠한다** (`Strike.paint`). 리본·섬광은 매
  프레임 `_pal` 을 읽고, 만들 때 굳는 것(빛·불똥 방출기)만 `paint` 가 바꾼다
  → [skills.md](skills.md) "히치 — 이펙트 풀".
- 찍어 보기: `npm run shot:godot -- thunder_fall+stun`.

### 넓은 낙뢰 (2번 "범위") ★

요청: "범위 증가 되면 더 50% 크기 커진거에 맞게 번개가 두 번 더 내리치게" → 어디에
치는지는 "지금처럼 가운데 하나 떨어지고 살짝 옆으로 양쪽에서 내려치면 될 것 같아".

- **판정** — 사거리에 `rangeMul`(1.5)을 곱한다 (4 → 6m). 겨누기(`_pick_targets` 로 대상
  찾기)부터 판정·알리는 모양(`skillRange`)까지 **같은 값**을 쓴다. 각은 그대로다 (2026-09-24 부터 원이라 반경만 넓어진다).
  낙뢰의 기본 사거리(4m)는 그대로라 `skills.test.ts` 의 "한 방향 스킬은 사거리 4 넘으면
  투사체" 규칙에는 안 걸린다 — 강화로 넓어진 것은 표의 사거리가 아니다.
- **이펙트** — 가운데 세 번(0 · 0.18 · 0.36초) 뒤에 **캐릭터 기준 왼쪽(0.54초) →
  오른쪽(0.72초)** 에 한 번씩 더 친다. 옆 거리는 `SIDE_GAP` **1.9m**(캐릭터 키 남짓,
  720p 에서 좌우 약 93px). 방향은 화면이 아니라 **캐릭터가 보는 쪽에 수직**이다
  ([effect-rules.md](effect-rules.md) "방향은 캐릭터 기준").
- **땅에 남는 것(금·그을림·지면 전기)을 1.5배**로 키운다(`WIDE`, `Strike.ground_mul`).
  **줄기 굵기는 그대로다** — 굵은 리본은 번개가 아니라 띠로 보인다.
- **옆 번개 둘은 늘 만들어 두고, 넓힘이 없으면 쉬게 한다**(`Strike.rest`, `active`).
  풀이 한 벌이라 넓은 낙뢰가 처음 나올 때 새로 만들면 그 순간 멈칫한다.
- 옆 번개 굵기는 가운데 마지막 것과 같다.
- **찍어서 봤다.** 마을은 차원문 옆이라 오른쪽 번개가 문에 조금 가린다. 옆 번개가
  어디 떨어졌는지는 작은 모아 찍기(`shot_sheet`)로는 못 읽었다 — 그 순간을 이펙트
  시계(`fx._t`)로 기다려 **캐릭터 주위를 2배로 잘라 찍어서** 봤다. 화면 좌표는
  `unproject_position` 으로 쟀다 (45° 를 볼 때 캐릭터 x=640, 옆 번개 547 · 733).
- 찍어 보기: `npm run shot:godot -- thunder_fall+wide@45` (`+stun+wide` 면 둘 다).

### 할퀴기 강화 ★ (2026-09-23)

요청: "강화전 다단히트 3회로 만들고 / 강화 1 : 부채꼴 각도 40도 증가, 이펙트로 그 만큼
길이 증가 / 강화 2 : 다단 히트 2회 증가, 이펙트 색상 변경".

- **기본을 5타에서 3타로 줄였다.** 한 대는 **56% 그대로**다 (사용자 선택) — 기본 합계
  168%, 연타 강화를 붙이면 예전 다섯 번(280%)과 같다. 설명도 "세 번 긁어낸다".
- **1번 부채꼴** (`arcAdd` 40°) — 판정 각 120 → **160°**. 이펙트는 쓸고 가는 호를 **같은
  40°만큼** 늘린다(140 → 180°, `SWEEP_WIDE`). 꼬리 각도 같은 비율로 늘린다 — 호만
  늘리면 긴 호 위로 짧은 점이 지나가 보인다. 머리가 끝까지 가는 시간(0.12초)은 그대로다.
- **2번 연타** (`extraHits` 2) — 3 → **5타**. 예약(`_combos`)이 둘 더 들어간다. 이펙트는
  긁기가 **두 번 더**이고, 빛 두 겹(헤일로·테)이 **보라**(`PALETTE_PURPLE`)가 된다 (사용자
  선택). **흰 심과 닿는 자리의 노란 불꽃은 그대로다.**
- 둘은 따로 논다 — 부채꼴만이면 청백 긴 호 세 번, 연타만이면 보라 140° 다섯 번.
- **메시는 여전히 한 번만 깐다.** 넓은 쪽(`MESH_ARC` 180°)까지 깔아 두고, 얼마나 그릴지는
  셰이더의 `head`/`tail` 이 정한다. 토막은 40 → **52**(3.5° 씩 그대로).
- **긁기 다섯을 늘 만들어 두고** 기본일 때 뒤의 둘은 쉬게 한다(`active`). 풀이 한 벌이라
  강화한 할퀴기가 처음 나올 때 새로 만들면 멈칫한다.
- 이펙트 수는 판정 표와 맞아야 한다 — `skill_fx_test` 의 `_case_table` 이 `hits` ·
  `extraHits` · `arcAdd` 를 이펙트 상수와 맞춰 본다.
- **찍어서 봤다** — 머리가 끝까지 간 순간(이펙트 시계 0.13초)을 기본·부채꼴 두 장으로
  잘라 찍어 호가 양끝으로 더 뻗는 것을, 둘 다 붙인 것은 보라 다섯 줄을 봤다.
  찍어 보기: `npm run shot:godot -- rising_kick+wide+combo@225`.
- 스킬창 설명의 데미지 줄(`56% * 3연타`)은 **기본값**이다 — 강화는 오른쪽 카드에만 적는다.

### 천붕각 강화 ★ (2026-09-23)

"천붕각 스킬은 어떤식으로 강화하는게 좋을까?" 에 여진·진폭 등을 제안했고, 사용자가
**"균열지대만들고 진폭도 만들어. 균열지대는 0.5초마다 40% 데미지"** 로 정했다.

- **1번 진폭** (`rangeMul` 1.5) — 범위 6 → **9m**. 처음엔 `targetsAdd` 5 로 최대 대상
  10 → 15 도 있었는데, 2026-09-24 에 스킬 명수 상한 자체를 없애면서 `targetsAdd` 를 뺐다
  (범위에 든 놈은 전부 맞는다 → [skills.md](skills.md)).
  판정·알리는 모양이 같은 값을 쓴다. 이펙트는 아래 "진폭 이펙트 — 모래 토네이도".
- **2번 균열 지대** (`zoneMs` 3000 · `zoneTickMs` 500 · `zonePower` **1.0** — 처음 0.4 였다가 2026-09-24 "도트 데미지 100%로 바꾸자. 너무 약해" 로 올렸다) — 내리찍은 자리에
  **판정 모양 그대로(같은 중심·반경)** 땅이 남아, 0.5 · 1.0 · … · 3.0초에 **여섯 번**
  `공격력 × 1.0` 를 넣는다 (`World._open_zone` → `_zones` → `step` 의 `_run_zones`).
  - **틱마다 대상을 다시 고른다** — 땅에 남은 것이라 걸어 들어온 놈은 맞고 나간 놈은
    안 맞는다 (연타는 첫 대에서 한 번 고른다 — 거기와 갈리는 자리다).
  - **공격력은 건 순간의 값**이다. 쓴 사람이 죽거나 존을 옮기면(`open`) 지대도 사라진다.
  - 틱이 밀려 있으면(탭을 내렸다 올림) 밀린 만큼 한꺼번에 넣지 않고 **한 번만** 넣는다 —
    여러 대가 한 자리에 겹쳐 뜨면 한 대로 보인다.
  - 진폭과 같이 붙으면 지대도 9m · 15마리다.
- **진폭 이펙트 — 모래 토네이도** (2차 시안, 2026-09-24) ★ 1차(금·먼지 충격파 1.5배)는
  **"별로다. 모래 먼지가 토네이도처럼 바람이 주변을 휙 감싸서 공격하게"** 로 거절됐다.
  참고 그림 없이 말로 정한 모양(띠 3~4줄이 휘감아 올라가며 9m 까지 휙 돌았다 흩어짐,
  모래 알갱이, 금·먼지 충격파 없음)을 사용자가 "이대로 해" 로 받았다 (`QuakeParts.Tornado`).
  - **띠는 직접 메시**다. 띠 여섯의 나선을 **게임 전체에서 한 번만** 깔고(점마다 각 ·
    높이 비율 · 반지름 비율), 셰이더가 반지름(1.2 → 9m, 0.55초) · 높이(1.2 → 4.5m) ·
    도는 각(초속 13rad 에서 풀린다)을 넣는다. 폭은 **위아래로** 벌린다 — 누운 리본이다.
  - **깔때기** — 아래는 반지름의 30%, 위로 갈수록 넓어져 꼭대기 바깥이 판정 반경(9m)이다.
  - **띠는 짧고 가파르다** (0.65바퀴). 1차 캡처에서 띠 넷이 1.1바퀴를 낮게 감았더니
    위에서 보면 **납작한 고리가 퍼지는 것** — 규칙이 금한 충격 파동 고리 — 였다.
  - 두 겹(넓고 옅은 바람 1.5m + 좁고 진한 모래 0.5m), 알파 혼합, 띠 양끝은 옅게.
  - 띠 사이는 **모래 먼지 덩이** 64개(`FxTex.puff`, 2.1m, 옅게)가 둘레에서 솟아 바깥으로
    휘돈다(`radial`·`tangential_accel`). 작고 진하게 뒀더니 **물방울무늬**였고,
    `proximity_fade` 가 없어 발밑에서 **땅에 잘린 곧은 모서리**가 보였다 (둘 다 찍어서 봤다).
  - 진폭이면 **먼지 충격파(앞머리·덩이·기둥)와 금·그을림을 끈다** — 흙 알갱이·섬광만 남는다.
    균열 지대가 같이 붙으면 **금은 남긴다**(1.5배).
- **균열 지대 이펙트 — 진흙 소용돌이** (3차 시안, 2026-09-24) ★ 1차(틈이 붉게 맥동)·2차(틈에서
  용암 분수)는 둘 다 거절됐다 — **"균열지대 이펙트 별로다. 진흙이 소용돌이처럼
  빨려들어가는 이펙트로"** (`QuakeParts.Mud`). 용암빛·조명·분수는 전부 걷었다.
  - **갈색 웅덩이와 작은 알갱이는 걷었다** (2026-09-24 "아래 회오리는 냅두고 갈색 바닥이랑
    조그만한 모래알 같은 파티클은 제거해"). 웅덩이(판정 반경만큼 깔던 젖은 흙빛 판 ·
    `FxTex.pool`), 가운데로 끌려가던 진흙 덩이 36개, 내리찍을 때 튀던 흙 알갱이(균열 지대일
    때만)를 뺐다. **소용돌이 띠만 남는다.** 강화 없는 천붕각의 흙 알갱이는 그대로다.
  - **촘촘한 나선 띠 여덟**(로그 나선 0.92바퀴, 폭 1.8m)이 바깥에서 가운데로 휘어 들고, 띠를 따라 끊긴 무늬가
    가운데로 흘러든다. 띠는 짙은 진흙 + 가운데 옅은 흙빛 줄 두 겹이다. **메시는 한 번 깔고
    셰이더가 돌린다** (토네이도와 같은 방식). 폭은 반지름 방향으로 벌리고 가운데로 갈수록 가늘다.
    - 다섯 줄 · 1.15바퀴, 셋 · 0.85바퀴는 **동심원 고랑**으로 보였다 (웅덩이가 띠를 덮던 때).
      그다음 넷 · 반 바퀴는 성긴 바람개비였는데, 사용자가 **"이런식으로 촘촘하게 회오리"** 하며
      캡처(여덟 줄쯤이 한 바퀴 가까이 감겨 든 모양)를 줬다 (2026-09-24).
    - 여덟 줄을 **반지름을 고르게 줄이며**(1 − u) 한 바퀴 감았더니 다시 **동심원**이었다 —
      바깥쪽에서 띠가 원과 8° 밖에 안 벌어진다. **로그 나선**(r = 0.1^u, 어디서나 ≈22°)으로
      바꾸니 은하처럼 휘어 드는 회오리가 됐다. 줄이 늘어 폭은 2.2 → 1.8m 로 좁혔다.
    - 띠 텍스처(`streak`)를 알파로 그대로 쓰면 가운데 한 줄만 진해서(평균 0.25) 옅은 고랑이었다 —
      `smoothstep` 으로 **속을 채우고 가장자리만** 부드럽게 한다.
    - 투명한 판들이 중심이 같아 **그리는 순서가 제멋대로**였다 —
      `render_priority`(띠 1 · 줄 2)로 못 박았다 (웅덩이가 있을 때 띠를 덮었다).
  - **틱마다 조여든다** — 0.5초마다 도는 속도가 초속 1.6 → 8.6rad 로 확 빨라졌다 풀리고(시간
    상수 0.18초) 소용돌이가 8% 오므라든다. 피해가 들어가는 순간이 보인다.
  - (걷음) 진흙 덩이 36개가 가장자리에서 가운데로 끌려가며 돌았다 (`radial_accel` 음수 ·
    `tangential_accel`) — 지대 동안 계속 나온다.
  - 균열 지대면 **먼지 충격파(앞머리·덩이·기둥)를 끈다** — 먼지가 소용돌이를 덮었다 (캡처).
  - 진흙은 흙이라 **알파 혼합**이다. 이펙트 시간(`ZONE_TIME` · `ZONE_TICK`)은 판정 표(`zoneMs` ·
    `zoneTickMs`)와 같아야 한다 — `quake_fx_test` 가 소용돌이 반경·조여듦 여섯 번과 함께 본다.
- **찍어서 봤다** — 토네이도는 0.12 · 0.3 · 0.5 · 0.75초 네 장과 발밑 확대, 진흙은 0.3 · 0.55 ·
  1.8 · 3.3초 네 장과 확대. 새 강화 이펙트 셰이더·방출기는 `FxWarm` 이 한 번 띄워 굽는다.
- 지대의 **테두리(어디까지가 지대인가) 표시는 없다** — 금이 퍼진 자리로만 보인다.

### 빙주각 강화 ★ (2026-09-24)

"빙주각 스킬 강화 추천 좀" 에 파쇄·빙결·한파 확산·서리 감속·얼음 갑옷을 제안했고, 사용자가
**"파쇄랑 빙결 구현해봐"** 로 정했다. 참고 그림은 없다 — 제안할 때 말로 적은 모양 그대로다.

- **1번 파쇄** (`followMs` 1100 · `followPower` 0.8) — **뒤따르는 한 대**: 1.1초 뒤, 기둥이
  부서지는 순간 **그때 범위 안에 있는 놈 전부**에게 `한 대 × 0.8` 을 넣는다. **한 번만 터지는
  지대**(`_zones`, 균열 지대 틱과 같은 자리)로 건다 — 같은 중심·반경으로 그 순간 다시 고른다.
  - 처음엔 첫 대로 맞은 놈에게만 예약했다(`_combos`). **"얼음 파편이 터질 때 처음 맞은
    몬스터가 아니면 데미지가 안 들어가. 터질 때 범위 기준으로 데미지 줘"** (2026-09-25).
  - 연타(`extraHits`)와 달리 **간격·배율이 강화마다 따로**다.
  - 1.1초는 **첫 고리 기둥이 부서지는 때**(`IceFx.shatter_at` = 솟기 0.14 + 서 있기 0.95)다 —
    `ice_fx_test` 가 판정 표와 맞춰 본다.
  - 이펙트: 기둥이 0.28초에 땅으로 꺼지던 것을 **0.05초에 빠지게** 하고(`BREAK_SINK`), 그 순간
    기둥 허리에서 **큰 조각 76개**(길쭉한 40 + 뭉툭한 36, 초속 5~11, **보통 조각의 2.2~4배** —
    길쭉한 것이 0.8~1.4m)가 사방으로 터진다 — 원래 꺼질 때 튀던 잔 조각(60개)에 더해진다.
    큰 조각은 날아가는 동안 크기를 지키다 끝에만 줄어든다(`_hold_curve`). 섬광과 번쩍임 빛이
    부서지는 순간 한 번 더 켜진다.
  - **처음엔 보통 조각 크기(0.2~0.5m)로 130개였다** — "너무 작아서 잘 보이지도 않아. 파편이
    터지는 것처럼 크게" (2026-09-24). 색종이처럼 흩날렸다. 크기를 키우며 개수를 절반 남짓으로
    줄였다 — 크고 많으면 얼음 더미에 몬스터가 묻힌다.
- **2번 빙결** (`stunMs` 2000 · `stunLook` 'ice') — 판정은 낙뢰 기절과 같다(2초 · 못 움직이고
  못 때림). 다른 것은 **보이는 것**이다: 판정이 몬스터에 `stun_look = "ice"` 를 달고, 화면이
  (`game.gd` `_tick_frozen`) 그 놈의 몸에 **얼음빛 덧칠**(`material_overlay`, 가산 · 하늘색)을
  입히고 **동작을 멈춘다**(`Rig.freeze` — 히트스톱과 같은 멈춤).
  - 맞을 때 붉히기(`HitFx.flash_body`)도 같은 덧칠 자리를 쓴다 — 붉히기가 걷어 가면 **다음
    프레임에 얼음을 도로 입힌다.** 풀리면 얼음 덧칠만 걷는다.
  - 낙뢰 기절이 뒤에 걸리면 `stun_look` 이 비어 얼음이 풀린다 (마지막에 건 쪽이 이긴다).
  - 이펙트: 기둥이 짙은 청색(`#0b3a86` → `#86c8ff`)이다. 흰 테는 그대로다.
- 둘은 따로 논다 — 파쇄는 기둥의 끝(꺼짐 → 부서짐), 빙결은 맞은 몬스터와 기둥 색이다.

### 테스트 단추 (왼쪽 아래 테스트 줄)

- **"스킬 경험치 +10만"** — 스킬 경험치를 `World.DEBUG_SKILL_EXP`(100000) 넣는다
  (`debugSkillExp`). 경험치북 +10 단추 자리를 그대로 쓴다.
- **"전체 1번 강화" · "전체 2번 강화"** — 이 직업의 **모든 스킬에 그 번호 강화를
  경험치 없이** 붙인다 (`debugUpgradeAll`). 그 번호가 없는 스킬은 건너뛴다.
- **"테스트: 강화 초기화"** — 붙은 강화와 강화마다 쌓인 경험치를 전부 지운다. 넣은
  스킬 경험치는 돌려주지 않는다 (`debugResetUpgrades`).
- 줄이 위로 자라서 전체 1번·2번은 **한 줄에 반씩** 놓았다 (`_test_button`).

## 손댈 때

- **강화를 더할 때** — `SKILL_UPGRADES` 에 한 줄(`exp` 필수, 효과는 `stunMs` · `rangeMul` · `arcAdd` · `extraHits` · `zoneMs`·`zoneTickMs`·`zonePower` · `followMs`·`followPower` · `stunLook` 중에서) → `npm run export:godot`.
  효과가 새 종류면 `cast` 에 판정을, `_show_skill` 에 이펙트 분기를 더한다.
  효과 문구(`desc`)는 **카드(280px) 한 줄**에 들어가야 한다.
- **던전 보상을 바꿀 때** — `DUNGEON_SKILL_EXP_PER_STAGE`(단계당). 단계마다 따로 주려면
  `RAID_STAGES` 의 `skillExp` 를 고치고 `zones.test.ts` 의 "단계 × 1000" 검사도 고친다.
  새 던전 종류(시련의 탑 · 보물 창고)를 열면 그 단계에도 `skillExp` 를 채운다.
- **이펙트를 바꿀 때** — [effect-rules.md](effect-rules.md) 를 먼저 읽고, 바꾸면
  `npm run shot:godot` 으로 찍어 본다.
- 옛 Colyseus 서버(`ZoneRoom.ts`)에는 안 붙였다.
