# 스킬

## 무엇

마법사·궁수 10개씩, **격투가 6개** — 총 26개. 배우고(스킬 포인트) 그중 **4개만 액션바에 올린다.**

**기사 10개는 2026-09-17 에 기사 직업째로 지웠다** (강타·회전베기·재정비·방패 밀치기·
대지 가르기·강철 의지·처형·최후의 방벽·대지진·왕의 심판). 그래서 **자기 회복
스킬(`selfHeal`)이 하나도 없다** — 필드와 판정은 `World` 에 그대로 남아 있으니,
회복기를 만들면 값만 넣으면 된다. 고도 쪽 `skill_test.gd` 의 회복 테스트도 같이 뺐다.

**격투가는 2026-09-12 에 이펙트가 붙은 넷만 남기고 정리했다** (할퀴기·호포각·백호격·천붕각).
**호포각(`tiger_roar`)·백호격(`white_tiger`)은 2026-09-23 에 지웠다** (요청). 지금 격투가는
할퀴기·천붕각·낙뢰·빙주각 넷이다. 저장에 남은 두 id 는 불러올 때 걸러진다(`World` 의 저장
복원이 "지금 있는 것만" 되살린다). 요구 레벨은 나중에 스킬마다 다시 정한다.
할퀴기의 id 는 `rising_kick` 이다 — 이름이 '올려차기' 에서 바뀌었지만 저장된 캐릭터가
그 id 로 남아 있어 그대로 둔다.
지운 여덟(발 연타, 돌려차기, 정권 지르기, 진각, 운기조식, 백열권, 파동권, 절명권)은 이름과
수치만 있고 화면에서는 기본 공격과 구분이 안 됐다.
저장된 캐릭터의 배운 목록에 지운 id 가 남아 있어도 `skillForJob` 이 걸러서 무시된다.

**낙뢰(`thunder_fall`)를 2026-09-18 에 더했다** — 격투가 다섯째이고 **이펙트가 붙은
것도 이것까지 둘**이었다 (할퀴기·낙뢰). **2026-09-23 에 천붕각이 셋째가 됐다** (아래 "이펙트 — 천붕각").
**같은 날 빙주각(`frost_pillar`, Lv.40)을 여섯째로 더했다** — 땅을 짓밟아 얼음 기둥이
사방에서 솟는다 (아래 "이펙트 — 빙주각"). 액션바는 4칸이라 **여섯이 다 올라가지는 않는다** —
고도에서는 스킬창에서 골라 **장착**하면 된다. 4칸이 다 찼으면 바꿀 칸을 누르라고
묻는다 (아래 "스킬창과 퀵슬롯").

## 규칙

- **직업별 개수·요구 레벨은 더 이상 맞추지 않는다** (2026-09-12). 원래는 넷 다
  1, 6, 12, 20, 35, 55, 80, 120, 150, 200 으로 똑같았다 — "배우는 시점이 다르면 그 자체로
  강약이 갈린다" 는 이유였다. 그런데 그 규칙 때문에 **격투가에 하나 더하려면 나머지 세
  직업 몫까지 같이 설계해야 했다.** 직업마다 콘텐츠가 따로 붙는 단계라, 균형을 맞추느라
  만들고 싶은 걸 못 만드는 쪽이 더 손해다. 검사는 `skills.test.ts` 에서 뺐다.
- 아직 지키는 것: 직업마다 Lv.1 스킬이 하나씩 있고, 요구 레벨이 오름차순이며,
  직업마다 고를 수 있을 만큼(액션바 칸 수 이상)은 갖는다.
- **"Lv.20 까지 액션바 칸 수만큼은 열린다" 검사는 2026-09-23 에 뺐다.** 호포각·백호격을
  지우니 격투가가 Lv.20 까지 둘(할퀴기·천붕각)뿐이었고, 사용자가 "나중에 스킬별로 레벨
  따로 지정할 거야" 라며 검사를 지우라고 했다. 그때까지 낮은 레벨 액션바에는 빈 칸이 남는다.
- `SKILL_BAR_SIZE = 4`, `SKILL_POINT_PER_LEVEL = 1`.
- **테스트 스위치 `SKILL_COOLDOWN_OFF`** (`skills.ts`) — 켜면 서버 판정(`handleSkill`)과
  액션바가 둘 다 쿨타임 0 으로 본다 (`skillCooldown`). 스킬 데이터의 `cooldown` 은 그대로다.
  켜져 있어도 서버 자동 시전만은 `AUTO_SKILL_TEST_GAP`(1초)마다 한 번 — 0 이면 몬스터 곁에서
  매 틱(15Hz) 쏜다. **2026-09-12 스킬 이펙트 테스트 때문에 켜 둔 상태다. 끝나면 false.**
- **테스트 스위치 `SKILL_UNLOCK_ALL`** (`skills.ts`) — 켜면 **요구 레벨과 스킬 포인트를
  둘 다 안 본다.** Lv.1 캐릭터가 천붕각(Lv.150)을 바로 배워 쓴다.
  서버(`handleLearnSkill`)와 스킬창이 둘 다 `canLearn`(레벨)·`skillPointCost`(포인트)를
  보므로 한 곳만 바꾸면 양쪽이 같은 답을 낸다. 데이터의 `reqLevel` 은 그대로라 스킬창에는
  여전히 "Lv.150" 이라고 적혀 있고, false 로 되돌리면 곧바로 다시 잠긴다.
  **레벨을 안 보는 게 목적이므로 `skills.test.ts` 의 "레벨이 모자라면 못 배운다" 는
  스위치가 켜진 동안 건너뛴다** — 테스트가 실패하는 게 아니라 규칙이 잠시 없는 것이다.
  **직업은 스위치와 무관하게 본다** — 남의 직업 스킬은 배워도 `handleSkill` 이 거른다.
  **켜져 있으면 접속할 때 그 직업 스킬을 전부 배운 상태가 된다** (`grantStartingSkill`).
  레벨과 포인트를 풀어 놔도 스킬창에서 한 번씩 눌러야 배워지는데, 확인하러 들어올 때마다
  그걸 반복하는 건 확인이 아니라 잡일이다. **액션바는 4칸이라 요구 레벨 순으로 앞의 넷만
  올라간다** — 뒤쪽 스킬을 보려면 스킬창(K)에서 바꿔 낀다.
  스위치를 끄면 이미 배운 것은 그대로 남는다 (저장된 캐릭터라서).
  **켜져 있으면 화면 왼쪽에 디버그 목록이 뜬다** (`ui/skillDebug.ts`) — 그 직업 스킬을
  전부 늘어놓고 누르면 **액션바를 거치지 않고 바로 쏜다.** 서버도 같이 풀린다
  (`handleSkill` 이 평소에는 액션바에 올라간 것만 받는데, 이 스위치가 켜져 있으면
  그 검사만 건너뛴다 — 직업과 쿨타임은 그대로 본다). 스위치를 끄면 목록도 사라진다.
  **2026-09-12 스킬 이펙트 확인 때문에 켜 둔 상태다. 레벨 개방을 설계할 때 false.**
- **고도에서는 화면 왼쪽 아래 단추로 쿨타임 0 을 켜고 끈다** (2026-09-19 요청).
  레벨 잠금 해제 단추도 달았다가 같은 날 걷었다 (요청) — 그건 `skills.json` 으로만 바꾼다.
  단추는 `testSwitch` 요청만 보내고, `World.set_test_switch` → `Skills.set_switch` 가
  메모리의 표 값을 바꾼다 (표는 한 벌이라 판정·화면이 같이 따라온다).
  **`skills.json` 은 안 바꾼다** — 다시 켜면 파일 값(지금은 둘 다 켬)으로 돌아온다.
  레벨 잠금 해제를 도중에 켜도 "접속할 때 전부 배운 상태" 는 다음 접속부터다.
- **같은 줄 위에 무적 단추도 있다** (2026-09-19 요청). 이건 표 스위치가 아니라
  플레이어 값(`player.invincible`)이다 — 요청 `invincible` → `World.set_invincible`.
  켜면 `_hit_player` 가 피해만 0 으로 만들고 맞는 이벤트는 그대로 낸다.
  존을 옮겨도 유지되고(`join` 이 넘겨받는다), 저장에는 안 들어간다.
- 스킬 필드: `power`(공격 배율) / `range` / `arc` / `maxTargets` /
  `cooldown` / `projectile?` / `selfHeal?` / `hits?` / `hitGap?`.
- **연타(`hits`·`hitGap`)** (2026-09-23, 할퀴기) — 한 번 쓰면 `hits` 번 때린다.
  `power` 는 **한 대의** 배율이다. 첫 대는 누르는 순간, 나머지는 `hitGap`(ms)
  간격으로 `World.step` → `_run_combos` 가 넣는다.
  - **대상은 첫 대에서 한 번만 고른다.** 대마다 다시 고르면 첫 대에 죽은 놈 자리를
    옆 놈이 채워 "다섯 번" 이 대상마다 제각각이 된다. 그 사이 죽은 쪽(때린 쪽·맞는
    쪽)은 건너뛴다 — 부활한 놈을 때리면 안 된다. 존을 옮기면(`open`) 예약을 비운다.
  - **한꺼번에 넣지 않는 이유**: 피해 숫자가 한 자리에 겹쳐 한 대로 보이고,
    이펙트의 다섯 줄기와 박자가 안 맞는다. 이펙트 간격(`SkillFx.GAP`)은
    `hitGap` 과 같아야 한다 — `skill_fx_test.gd` 가 표와 맞춰 본다.
  - **옛 Colyseus 서버(`ZoneRoom`)는 `hits` 를 모른다** — 거기서는 한 대만 들어간다.
    고도 서버를 붙일 때 `World._run_combos` 를 옮긴다.
- **회복기는 때리지 않는다** — `power: 0`, `maxTargets: 0`. 둘 다 하면 판정 경로가 갈린다.
- **투사체 규칙**: 한 방향으로(`arc < 2π`) 사거리 4 넘게 쏘는 스킬에는 투사체가
  반드시 있어야 한다. 없으면 멀리서 쏘는데 아무것도 안 날아가고 즉시 맞는 것처럼
  보인다. 반대로 자기 중심 전방위기(`arc >= 2π`, 투사체 없음)는 사거리 8 이하여야
  한다 — 길면 화면 밖 적까지 맞아 무슨 일인지 알 수 없다. 둘 다 테스트가 잡는다.
- **격투가는 전부 근접이다** — 한 방향기는 사거리 4 이하, 전방위기는 8 이하라
  투사체가 하나도 없다. 날아가는 호랑이·백호는 **이펙트가 그렇게 보일 뿐**이고,
  판정은 사거리 안의 근접이다 (이펙트도 사거리까지만 간다 — 아래 이펙트 절).
  **회복기가 없다** — 운기조식을 지우면서 같이 없어졌다. 파고들어 몰아치는 직업이라
  아쉬움이 적다. 필요해지면 다시 만든다. (기사를 지운 2026-09-17 부터는 **어느
  직업에도** 회복기가 없다.)
- 격투가 요구 레벨은 **1 / 6 / 12 / 20 / 30** 이다. 원래 레벨(20·45·100·150)대로 두면
  1레벨이 기본 공격만 갖고 시작하고, Lv.20 까지 배울 게 하나뿐이라 액션바가 빈다.
  낙뢰만 30 인 것은 **앞의 넷으로 액션바가 이미 차기 때문**이다 — 다섯째까지 20 안에
  넣으면 무엇이 올라갈지가 요구 레벨 순서에 달려 헷갈린다.

### 겨누고 쏘기 ★
몬스터를 클릭해 **겨눈 상태**로 스킬을 쓰면 그쪽으로 나간다
([auto-hunt-and-targeting.md](auto-hunt-and-targeting.md)).
**찍어 둔 게 없으면 서버가 사거리 안에서 가장 가까운 놈을 대신 잡는다**
(`ZoneRoom.acquireTarget`) — 아래 "안 찍고 눌렀을 때".

| 스킬 | 어디서 터지나 |
|---|---|
| **원거리** (`projectile` 이 있다) | **겨눈 놈이 서 있는 자리.** 그 자리를 중심으로 한 원 |
| **근접** (투사체가 없다) | 예전 그대로 **내 몸 앞 부채꼴.** 다만 몸이 겨눈 쪽을 향한다 |

- **원거리·근접을 가르는 것은 `projectile` 하나다** (`isRangedSkill`). 필드를 새로
  만들지 않은 이유는 이미 그게 그 구분을 하고 있기 때문이다 — 투사체 규칙상 한
  방향으로 사거리 4 넘게 쏘는 스킬에는 투사체가 반드시 있고, 투사체 없는 전방위기는
  사거리 8 이하다. 필드를 하나 더 두면 **두 값이 어긋난 스킬이 반드시 생긴다.**
- **근접기를 타겟 자리에서 터뜨리지 않는 이유**: 내 앞을 베는 동작인데 판정만
  저쪽에서 나면 이펙트와 어긋난다. 반대로 원거리기를 시전자 정면 부채꼴로 재면
  "타겟을 찍었는데 옆에 있던 놈만 맞는" 일이 난다.
- **터지는 반경은 사거리가 아니다** (`blastRadius`). 원거리기는 사거리가 10~14 라
  그대로 쓰면 지름 20m 가 넘어 **화면(세로 21유닛) 전체가 범위**가 된다. 그래서
  `range × 0.35`, 상한 6. 단일기(`maxTargets <= 1`)는 타겟 하나만 맞아야 하므로
  몸 하나 크기(`SKILL_BLAST_MIN = 0.6`)만 본다.
- **사거리 밖을 겨누고 눌러도 날아가지 않는다.** 그러면 사거리라는 수치가 없는 것과
  같다. 그때는 예전처럼 내 몸에서 부채꼴로 재고, 닿는 게 없으면 헛친다.
- 자동 사냥이 부를 때는 **자기가 고른 놈**을 인자로 넘긴다. 안 넘기면 사람이 찍어 둔
  타겟을 보고 엉뚱한 쪽으로 돌아선다.
- 확인: `npm run probe -- aim` ([verification.md](verification.md)).

### 범위 표시 (테스트 단추) ★
왼쪽 아래 **"테스트: 스킬 범위"** 를 켜면, 스킬을 쓸 때마다 **판정이 실제로 훑은
자리**가 땅에 청록색으로 한 번 그려지고 HUD 에 `반경 · 각 · 맞은 수/상한` 이 뜬다.

2026-09-21 에 만들었다. 설계([stat-balance.md](stat-balance.md) 5장)는 "범위 스킬로
무리를 정리한다"가 전제라 **반경·각이 곧 사냥 속도**인데, `range`·`arc`·`maxTargets`
숫자만 봐서는 화면에서 얼마나 덮는지 알 수가 없다.

| 파일 | 역할 |
|---|---|
| `godot/world/world.gd` `cast` | `skillRange` 이벤트를 **늘** 낸다 |
| `godot/game/skill_range.gd` | 받은 모양을 땅에 그린다 (`SkillRange.show_cast`) |
| `godot/game/game.gd` `_toggle_range` · `_show_skill_range` | 단추와 이벤트 처리 |
| `godot/tests/skill_test.gd` `_case_range` | 세 모양이 판정과 같은지 |
| `godot/tools/shot.gd` | `npm run shot:godot -- range:<스킬id>` — 무리 한가운데에서 찍는다 |

- **모양을 화면이 다시 계산하지 않는다.** ★★ `cast` 가 `_pick_targets` 에 넘긴
  값(중심·반경·각·바라보는 쪽)을 그대로 이벤트에 싣는다. 화면이 `skills.json` 을
  다시 읽어 그리면 판정이 바뀔 때 조용히 갈라져서 **"표시는 맞는데 안 맞는"**
  최악의 디버그 도구가 된다.
- **모양은 한 가지다** — 중심에서 `facing` 을 가운데로 한 각 `arc` 의 부채꼴.
  원거리기가 날아가 터진 것은 중심이 착탄점이고 각이 한 바퀴(TAU)로 와서 같은
  코드가 원을 그린다. `_pick_targets` 가 부채꼴을 쓰는 조건(착탄점이 없고 각이
  한 바퀴 미만)까지 판정 쪽에서 풀어 보내므로 화면에는 분기가 없다.
- **이벤트는 켜지 않아도 나간다.** 그릴지 말지는 화면 값(`_show_range`)이다 —
  판정에 표시용 상태를 두면 그때부터 판정이 화면을 안다.
- **맞은 수를 같이 적는 이유**: 반경만 보면 "왜 저기 있는 놈이 안 맞지" 가
  `maxTargets` 때문인지 각 때문인지 알 수 없다.
- 높이 0.11m — 보스 예고 원(0.06)·고른 표시 고리(0.08)보다 위다. 겹쳤을 때
  이게 가려지면 도구 구실을 못 한다.

#### 안 찍고 눌렀을 때 ★
겨눈 놈이 없으면 **사거리 안에서 가장 가까운 몬스터**를 잡고 그놈에게 나간다
(`ZoneRoom.acquireTarget`, 클라이언트는 `main.ts` 의 `faceTarget(사거리)` +
`RemoteMonsters.nearest`).

- **찍지 않으면 판정이 내 정면 부채꼴로만 나갔다.** 눈앞에 몬스터를 두고도 몸이
  조금 비껴 있으면 헛치는데, 화면에서는 이유가 보이지 않는다.
- **고른 놈을 진짜 조준으로 등록한다** — `targets` 에 적고 `target` 메시지로
  알려준다. 클릭으로 찍은 것과 **같은 자리**라 이름표 표시·해제 규칙
  (Esc·죽음·존 이동)이 그대로 적용되고, 다음 스킬도 같은 놈에게 이어 나간다.
  이 시전에만 몰래 쓰고 말면 클라이언트는 조준이 없는 줄 알고 이펙트를 정면으로
  그리는데 판정만 옆에서 나 **둘이 어긋난다.**
- 고르는 규칙은 자동 사냥과 **같은 `pickHuntTarget`** 이다(`currentId = null`).
  "가장 가까운 놈"을 두 벌 만들면 자동 사냥과 손 시전이 서로 다른 놈을 고른다.
- 범위는 **그 스킬의 `range`** 다. 더 멀리서 잡아 봐야 `blastAt` 이 사거리 밖을
  잘라내 헛치고, 몸만 엉뚱한 쪽으로 돈다.
- **회복기(`maxTargets <= 0`)는 잡지 않는다.** 때리지 않는데 조준 표시만 켜진다.
- **기본 공격은 그대로다** — 찍은 놈이 없으면 예전처럼 정면으로 휘두른다.
  근접 사거리는 짧아서 자동으로 잡아 줄 만큼 애매한 거리가 나오지 않는다.

### 자원 소모는 없다
**마나를 게임에서 걷어냈다.** 스킬을 쓰는 데 드는 것은 쿨타임뿐이다.

자원 관리가 컨텐츠를 만드는 데 방해만 됐다 — 마나가 떨어지면 스킬이 안 나가고,
그러면 이펙트도 판정도 확인할 수가 없다. 반쯤 끄는 스위치를 두는 것보다
아예 없애는 쪽이 코드가 정직하다.

없어진 것들:
- `SkillDef.mpCost`, `Stats.maxMp`, `ItemBonus.maxMp`
- `Player` 스키마의 `mp` / `maxMp`, 서버의 마나 회복 틱
- 상태바의 마나 막대, 액션바 칸의 소모량, 마나 부족 잠금(`is-poor`)
- 스킬창 설명의 "마나 N" 줄

장신구와 마법서가 마나를 주던 자리였다 — 그 몫은 공격과 체력으로 옮겼다
([items.md](items.md)).

### 이펙트 — 고도 (`skill_fx.gd`) ★
**이펙트는 고도 엔진에서 코드로 짓는다** (2026-09-17 지시. 띠·줄기는 파티클이 아니라 직접 메시 — [effect-rules.md](effect-rules.md) — 아래 웹 클라이언트
절은 지워진 three.js 쪽 기록이고, 규칙과 "왜 그렇게 했는가" 만 읽는다).
지금 고도에 있는 것은 **할퀴기와 낙뢰 둘**이다.

| | 무엇 |
|---|---|
| 할퀴기(`rising_kick`) | **발톱 세 가닥짜리 초승달이 앞 120° 를 세 번(강화하면 다섯 번), 좌↔우 번갈아 쓸고 가며 닿는 자리에서 노란 불꽃이 튄다** (`SkillFx.claw`, 셰이더로 움직이는 호 메시 5장(기본은 3장만 쓴다) × 3겹 + 불똥) |
| 낙뢰(`thunder_fall`) | **앞쪽 한 지점에 번개가 세 번 겹쳐 꽂히고, 닿은 자리에서 땅이 갈라지며 파편이 튄다** (`LightningFx.bolt`, `CPUParticles3D` 열다섯) |

#### 할퀴기 — 초승달 세 번 (2026-09-23 갈아엎음) ★
**같은 날 기본을 다섯 번에서 세 번으로 줄였다** — "연타" 강화(+2)가 생겨서다. 한 대는
0.56 그대로라 기본 합계는 1.68, 연타를 붙이면 아래의 옛 다섯 번(2.8)과 같다. 강화는
"부채꼴"(판정 160° · 호 180°)과 "연타"(다섯 번 · 보라) 둘이다 → [skill-upgrades.md](skill-upgrades.md).
아래는 다섯 번이던 때 적은 것이라 "다섯" 은 **연타 강화를 붙인 모양**으로 읽는다.

**요청: "한 번에 5번 데미지, 부채꼴 120° 정도."** 참고 그림(사용자 제공)은
**희고 푸른 초승달 궤적 여러 줄이 나란히 휘어 지나가고, 닿는 자리에서 노란 불꽃이
튀는** 것이었다. 그래서 그 전의 파티클 X 자(코어·발톱 광선 넷·불똥)를 버렸다.
판정은 위 "연타" — 0.56 × 5타, 120°, 최대 4마리, 80ms 간격이다 (**합계 2.8 은
한 방이던 때와 같다** — 피해가 공격력에 비례해서 나눠도 합이 같다).

- **줄기는 파티클이 아니라 직접 메시다** (effect-rules.md 3절). 머리가 호를 따라
  나아가고 꼬리가 따라붙는 초승달이다. 폭은 시선에 수직이고, 가장자리를 죄는 것은
  `FxTex.streak` — 낙뢰와 같은 텍스처다.
- **메시는 게임 전체에서 한 번만 만들고, 움직임은 셰이더가 한다** (`CLAW_SHADER`,
  `arc_mesh`) ★★ 처음에는 프레임마다 메시 15장을 GDScript 로 다시 깎았는데
  **"스킬 사용하면 히치가 걸려"** 라는 지적을 받았다 (2026-09-23). 재 보니 떠 있는
  동안 프레임당 1.6ms(최대 3ms, PC) — **낙뢰(0.16ms)의 10배**였고, 웹·폰은 GDScript 가
  몇 배 느려 한 프레임(16ms)을 넘겼다. 지금은:
  - 긁기 다섯의 호 메시를 **보는 쪽 0 으로 한 번** 깐다(폭 0). 할퀴기마다 노드만
    `facing` 으로 돌린다 — 쓸 때마다 만들면 그것만으로 2.8ms 가 튀었다.
  - 꼭짓점 셋(바깥 · 가운데 · 바깥)이 같은 자리에 있고, 셰이더가 `tail`~`head`
    사이의 바깥 꼭짓점만 초승달 폭(`sin(π·u^1.6)`)으로 벌린다. `UV2.x` = 그 점의 각,
    `UV2.y` = ±발톱 굵기, `NORMAL` = 호의 진행 방향.
  - **폭 방향은 셰이더가 월드에서 구한다**(`world_vertex_coords`, 시선 × 진행 방향) —
    그래서 메시가 보는 쪽과 무관하다.
  - 프레임마다 하는 일은 재질에 `head`·`tail`·`tint` 를 넣는 것뿐 → **0.03ms.**
  - 머리 끝은 토막(`SEGMENTS` 40 = 3.5°) 단위로 나아간다. 성기면 끝이 뚝뚝 끊긴다.
  - **다음 띠·줄기 이펙트도 이렇게 짓는다** — 매 프레임 `SurfaceTool` 로 깎는 건
    웹·폰에서 히치가 된다.
- **처음 쓸 때 멈칫하는 것은 `FxWarm` 이 막는다** — 아래 "셰이더 미리 굽기".
- **한 번 = 나란한 발톱 자국 셋**(`CLAWS`, 반지름 2.0 · 2.3 · 2.6m). 가운데가
  가장 굵다 — 셋이 같으면 판자 세 장이다.
- **세 겹 — 폭만 다른 같은 길** (effect-rules.md 5절): 청백 빛 0.85m · 밝은 테
  0.32m · 흰 심 0.1m.
- **초승달 폭** `sin(π·t^1.6)` — 꼬리는 실처럼 가늘고, 머리 쪽 3분의 2 에서 가장
  굵고, 머리 끝은 뾰족하다. 폭이 일정하면 막대가 날아가는 것으로 보인다.
- **다섯 번이 좌 → 우, 우 → 좌로 번갈아** 쓸고, 기울기(`TILTS`)도 이웃끼리 반대라
  참고 그림처럼 대각선이 엇갈린다. 같으면 한 줄로 겹쳐 다섯 번이 한 번으로 보인다.
- **쓸고 가는 각은 140°** — 판정(120°)보다 넓어야 부채꼴 끝에 선 놈도 긁힌 것으로
  보인다. 머리가 0.12초에 끝까지 가고, 꼬리(115°)가 0.16초 동안 머리로 모이며
  사라진다. 제자리에서 옅어지기만 하면 호가 한동안 그려져 있어 "그림 한 장" 이 된다.
- **방향은 캐릭터 기준** — 호의 가운데가 늘 보는 쪽이다. 노드는 회전하지 않고
  점을 찍을 때 `facing` 을 넣는다(`arc_point`) — 리본 폭을 월드 시선으로 재기 때문.
- **머리가 정면을 지날 때 닿는다** — 거기서 노란 섬광(`LightningFx.flare`, 제자리에서
  사그라든다)과 불똥 12개.
- 크기(720p, 1m = 38px): **쓸고 간 길이 144px · 빛 폭 33px · 심 폭 4px.** 한 번
  0.64초.
- 확인: `skill_fx_test.gd`(몇 번·몇 겹·번갈아·앞쪽·px·**표와 박자 일치**·치웠나),
  생김새는 `npm run shot:godot -- rising_kick@225`(화면 위를 보고) · `@135`(옆).
- 색은 **청백 빛(`#6bb8ff` 계열) · 흰 심 · 섬광 노랑(`#ffc24a`)** 이다. 피해
  숫자(연노랑)·치명타(주황)·피격(붉은색)과 한 화면에서 갈려야 한다.

#### 옛 할퀴기 (파티클 X 자, 2026-09-17 ~ 09-22) — 규칙만 남긴다
- **판을 세워 두지 않는다** — 발톱 자국을 판 모양 메시로 제자리에 세웠더니 **"이미지
  붙여 놓은 것 같다"** 는 지적을 받았다. 지금 초승달도 메시지만 **매 프레임 호를
  따라 움직이고 줄어든다** — 서 있는 판이 아니다.
- 크기는 px 로 정한다 — 피격 이펙트에서 16px 로 잡았다가 "안 나온다" 는 말을 들었다.
#### 셰이더 미리 굽기 (`fx_warm.gd`) ★
고도는 재질을 **처음 그리는 순간** 셰이더를 컴파일한다. 가상 화면에서 재 보니
**첫 사용 때 할퀴기 330ms · 낙뢰 230ms** 가 튀었다 (두 번째부터는 없다).
그래서 게임에 처음 들어갈 때(`_build_zone`) `FxWarm.run` 이 이펙트를 한 벌씩
(할퀴기 · 낙뢰 · 피격 보통/치명타) **실제로 띄워** 96px `SubViewport` 에 1.6초 그린다.

- 이펙트는 **렌더 레이어 20**(`FxWarm.LAYER`)에만 두고, 본 화면 카메라의 `cull_mask`
  에서 그 레이어를 뺀다 — 사람 눈에는 아무것도 안 보인다. 빛은 `light_cull_mask` 로
  무대만 비춘다. 무대는 y −200 이라 본 화면과 섞이지 않는다.
- **재질만 모아 그리지 않고 실제 이펙트를 띄우는 이유** — 파티클(멀티메시)·빌보드·
  Label3D 처럼 **그리는 방식마다 따로 컴파일되는 변형**이 있어서 재질만으로는 놓친다.
- 한 게임에 한 번(`_done`). 컴파일된 셰이더는 존을 옮겨도 남는다.
- 결과(가상 화면): 첫 사용 **할퀴기 330 → 90ms, 낙뢰 231 → 131ms** — 두 번째와
  같아졌다. 굽는 값은 게임에 들어갈 때 한 번 치른다.
- **새 이펙트를 만들면 `FxWarm._spawn` 에 한 줄 더한다.** 안 더하면 그 이펙트만
  처음 쓸 때 멈칫한다.
- 맞은 몸을 붉히는 것(`HitFx.flash_body`)은 몸이 있어야 해서 굽지 않는다.
- ★ **구운 셰이더는 같은 재질이 살아 있어야 남는다.** `StandardMaterial3D` 는 같은
  설정의 재질이 하나도 안 남으면 셰이더를 버린다 — 굽던 이펙트가 지워지는 순간
  구운 것도 같이 버려졌다. 지금은 게임이 먼저 채워 둔 풀(`FxPool.fill`)이 재질을
  붙들고 있다. 아래 "히치 — 이펙트 풀".

#### 히치 — 이펙트 풀 (`fx_pool.gd`) ★ (2026-09-23)
"스킬 사용할 때 **자꾸** 히치가 걸려" — 처음만이 아니라 매번이었다.
`tools/hitch.gd` 로 한 프레임을 덩어리별로 재서 원인 넷을 찾았다 (헤드리스, 클라우드 PC):

| 원인 | 전 | 후 | 고친 것 |
|---|---|---|---|
| 이펙트를 **쓸 때마다 새로 만든다** — 노드 수십 개 · 재질 · `CPUParticles3D` · 빛 | 할퀴기 2.8ms · 낙뢰 7ms · 천붕각 5ms | 0.03~0.15ms | **풀** — 끝나면 숨겨 두고 되감아 쓴다 |
| 이펙트가 다 꺼지면 **셰이더를 버리고 다음에 다시 짓는다** (화면에서는 재컴파일) | 다시 쓸 때 1.1~1.6ms + 컴파일 | 없음 | 풀이 재질을 붙든다 |
| 피해 공식의 K(`Stats.k_of`)가 **한 대마다 기준 플레이어를 통째로 재계산** | 0.8ms × 대 수 — 할퀴기 시전 4ms | 1.2ms | 레벨별로 한 번만 구해 기억 → [stat-balance.md](stat-balance.md) |
| 처치 알림(옛 `LootLog`)이 **줄마다 컨테이너·글자를 새로 만들었다** | 한 줄 1.6~2.2ms | — | 같은 날 채팅창(`ChatLog`, `RichTextLabel` 하나에 덧붙임)으로 바뀌며 사라졌다 → [hud.md](hud.md) |

- **풀은 게임에 하나, 존 밖**(`game._fx`)에 붙는다. 존은 차원문을 지날 때 통째로
  버려지므로 거기 두면 풀도 같이 지워진다. 존을 옮기면 떠 있던 것만 거둔다(`recall`).
- 게임을 열 때 미리 채운다 (`FxPool.PREFILL`: 할퀴기 2 · 낙뢰 1 · 천붕각 1 · 타격 12).
  모자라면 그때 하나 더 만들고, 그 뒤로는 그것도 되쓴다.
- **이펙트 규격** — 띄우는 `static func` 가 `FxPool.take` 로 쉬는 것을 먼저 꺼낸다.
  노드를 짓는 `_build`(한 번)와 되감는 `_start`(매번 — **아무것도 새로 만들지 않는다**)를
  나누고, 끝나면 `finish()` → `FxPool.give`. **부모가 풀이 아니면 예전처럼 지운다**
  (테스트 무대 · `FxWarm`).
- 되감아 쓰는 방출기는 `emitting = true` 가 아니라 **`restart()`** 로 켠다.
- 낙뢰 리본은 45ms 마다 다시 깎지만 **있던 메시를 비우고 채운다**(`ribbon` 의 `into`) —
  `ArrayMesh` 를 새로 만들고 버리지 않는다.
- 무리 한가운데서 스킬과 상관없이 들던 몬스터 틱(`World._step_monsters`, 201마리,
  1.7ms)은 같은 날 격자로 0.96ms 로 줄였다 → [collision.md](collision.md) "격자".
- 새 이펙트를 만들면: 위 규격대로 짓고, `FxPool.PREFILL` 과 `FxWarm._spawn` 에 한 줄씩.

- **남이 쓴 것은 아직 안 그린다** — 다른 플레이어를 세우는 자리가 고도에 없다.

### 이펙트 — 낙뢰 (`lightning_fx.gd`) ★
**한 지점에 번개가 세 번 순차적으로 겹쳐 치고, 친 자리에서 땅이 갈라지며 파편이 튄다.
번개는 캐릭터 뒤에서 앞 방향으로 내리꽂힌다** (2026-09-18 지시).

#### 줄기는 파티클이 아니라 리본 메시다 ★★

**처음에는 가닥 메시를 `CPUParticles3D` 로 방출했다.** 테스트는 다 통과했는데
화면에서는 다발로 뭉친 실이었다 — **"다른 프로젝트에서는 금방 잘 만드는데 넌 너무
엉뚱하게 만들고 있어"** (2026-09-18, 참고 그림을 받고 알았다). 파티클이 정하는 것은
"어디로 얼마나 빨리"뿐이고, **선의 모양은 메시에 통째로 박혀 있어 자리마다 바꿀 수가
없다.** 번개에서 중요한 건 바로 그 모양이다
→ [hit-effects.md](hit-effects.md) 의 "파티클로 만들 것과 메시로 만들 것".

지금은 **경로를 잡고 그 위에 리본을 깎는다.** 규칙은
[effect-rules.md](effect-rules.md) 에 있다 — **이펙트를 건드리기 전에 그것부터 읽는다.**

| 무엇 | 어떻게 |
|---|---|
| 경로 `trail` | 시작점에서 꽂히는 자리까지, 중간을 **누적 난수**로 흩는다. 점마다 따로 흩으면 톱니가 되고, 누적하면 이어진 굽이가 된다. 양 끝은 제자리 |
| 리본 `ribbon` | 경로를 따라 폭을 준다. 폭 방향은 **시선에 수직**(금은 지면 안) — 카메라가 어디서 보든 화면에서 같은 굵기다 |
| 잇기 | 폭 방향을 **점마다 이웃 두 토막의 평균**으로 구한다. 토막마다 따로 사각형을 만들면 꺾인 자리에서 이음새가 벌어져 **판자 조각**이 흩어진다 |
| 3겹 | 넓은 헤일로(0.5m = 19px) + 색 빛(0.2m = 8px) + 가는 흰 심(0.09m = 3px). **한 줄기를 굵게 보이려면 가닥을 늘리는 게 아니라 폭만 다른 겹을 쌓는다** ([effect-rules.md](effect-rules.md) 5절) |
| 테두리 없이 | 폭 방향 UV 에 **`FxTex.streak()` 텍스처**를 입힌다. 폭 전체를 같은 알파로 채우면 양쪽에 또렷한 선이 생겨 **테두리를 두른 것**처럼 보인다 (2026-09-18 에 지적받았다). 꼭짓점 알파로 죄면 삼각형 안에서 직선으로 줄어 심이 각진다 — 텍스처는 감쇠 곡선을 그대로 준다 |
| 지글거림 | **45ms 마다 경로를 다시 잡는다.** 가만히 서 있으면 붙여 놓은 그림이다 |

**알갱이인 것만 파티클이다** — 튀는 흙 파편 하나뿐이다.

- **떨어지는 자리는 내가 선 자리다** (`AHEAD` 0, 2026-09-18 지시: "스킬이 내 앞에서
  떨어지는데 내 위치에서 떨어지도록 해"). 앞 2.8m 에 떨어뜨렸더니 내가 부른 것이
  아니라 저쪽에 떨어진 것으로 보였다.
- **번개는 어느 쪽을 보든 화면 밖에서 온다** (`from_dir`, 2026-09-18 지적:
  "방향에 따라 엄청 짧게 나오기도 하고 번개 시작지점이 보이기도 해"). 캐릭터가
  보는 쪽 반대에 두었더니 카메라가 고정각이라 **카메라 쪽을 볼 때 시작점이 화면
  아래로 내려왔다.** 지금은 **카메라에서 먼 쪽 6.5m · 높이 9m**(342px)에 두므로
  열여섯 방향 전부 화면 밖이다.
- **화면 가로로도 민다** (`LEAN` 0.55 + `SWAY` ±0.35). 안 밀면 화면에서 수직으로
  내려와 캐릭터와 겹쳐 기둥으로 보인다. 보는 쪽에 따라 기울기가 달라져서
  "늘 똑같은 대각선" 도 아니다 → [effect-rules.md](effect-rules.md) 3절의 예외.
- **회전을 주지 않는다.** 번개는 하늘에서 땅으로 오는 것이라 월드 기준이어야 하고,
  리본의 폭도 월드 기준 시선(`view_dir`, `CameraRig` 의 고정각)으로 잰다. 보는 쪽은
  시작점 좌표에 넣는다. (할퀴기는 X 자가 화면에서 X 여야 해서 카메라 평면에 맞췄다 —
  거기와 여기가 갈리는 자리다.)
- **주 줄기는 하나다.** 둘을 따로 세웠더니 한 줄기가 여러 줄로 갈라져 보였고,
  곁줄기를 따로 기울였더니 별개의 번개가 화면을 가로질렀다 — 규칙이 경고한
  그대로였다 (2026-09-18 캡처). 곁줄기는 **같은 길을 0.22m 흔든 사본**(`jitter`)
  이고, 굵기는 **폭만 다른 3겹**으로 낸다 → [effect-rules.md](effect-rules.md) 5절.
- **균열 길이는 캐릭터 키(1.8m)의 1.5~4배**여야 한다 (같은 문서 3절) — 갈래마다
  0.85~1.35 를 곱하고 연타마다 굵어져 2.7~5.7m 가 된다.
- **세 번은 180ms 간격이고 자리가 0.36m 씩 어긋난다.** 간격이 줄기 수명(0.3s)보다
  짧아야 겹쳐 보이고, 완전히 같은 자리면 두 번째·세 번째가 안 보인다. 흔드는 값은
  상수(`JITTER`)이고 `Strike` 마다 **씨앗을 박아 둔다**(`_rng.seed`) — 같은 낙뢰가
  늘 같은 모양이어야 테스트가 읽는다. 뒤로 갈수록 16% 씩 굵어진다.
- **금은 한 번 정해 두고 자라기만 한다.** 매 프레임 다시 흩으면 갈라진 자국이
  꿈틀거린다. 자라는 것(`cut` 으로 경로 앞부분만 그린다)이 "갈라진다" 를 만든다 —
  다 그려 놓고 띄우면 그려진 그림이다.
- **금은 지면 안에서만 굽는다** (`trail(flat = true)`). 위아래로도 흩었더니 1.23m
  솟아올라 뿌리가 됐다 (헤드리스 테스트가 잡았다).
- **크기는 px 로 정한다** — 720p 에서 1m 가 38px 이라 **헤일로 19px · 색 빛 8px ·
  흰 심 3px · 시작 높이 269px · 금 길이 122px · 파편 8px** 이다 (캐릭터 키가 68px).
  **얇은 쪽이 낫다** (2026-09-18 지시) — 굵은 리본은 번개가 아니라 띠로 보인다.
  다만 파티클로 만들던 때처럼 3px 까지 깎지는 않는다: 그때 실이 된 것은 굵기가
  아니라 **가닥이 뭉쳐서**였고, 뭉쳐 보이면 가닥 수를 줄이는 게 맞다.
- **금도 한 겹이다.** 둘레에 밝은 돌빛을 깔아 봤더니 갈라진 틈이 아니라 **테두리를
  두른 그림**이 됐다 (2026-09-18 에 지적받았다). 가장자리는 줄기와 같은

  굴렸다가 **"입자가 너무 크고 두껍고 사각사각하다"** 는 말을 들었다 (2026-09-18).

### 이펙트 — 옛 웹 클라이언트 (`skillFx.ts`, 지워짐)

| 백호격(`white_tiger`) | 백호가 잔상 두 장을 달고 **정면으로** 내달린다 (`whiteTiger`, `TIGER_RUN`, `public/assets/fx/white_tiger.png`) |
| 천붕각(`sky_breaker`) | 위에서 큰 발이 떨어지고(0.3초), 닿는 순간 지면이 갈라지며 얇은 충격파가 퍼진다 (`skyBreaker`, `SKY`) |
| 격투가 스킬이 맞았을 때 | 섬광에 더해 **빛나는 주먹** (`signature` → `fist`, `public/assets/fx/fist.png`) — 섬광만으로는 칼로 벤 것과 같아 보인다. **지금은 여기까지 오는 스킬이 없다**: 남은 넷은 전부 시전할 때 자기 그림을 그린다 (`castSignature`) |

- 색은 `skillColor(skill)` — 투사체가 있으면 그것과 맞추고, 없으면 직업으로 정한다.
- **남이 쓴 것도 보인다.** 옆에서 뭘 하는지 안 보이면 같이 노는 느낌이 안 난다.
- 전방위 고리는 **판정 범위와 같은 크기**로 그린다. 다르면 "분명 닿았는데
  안 맞았다"가 된다.
- 투사체가 있는 스킬은 고리를 겹쳐 그리지 않는다 — 날아가는 게 이미 보여준다.
- 명중 섬광은 투사체가 **도착할 때** 뜬다. 피해 숫자와 같은 타이밍이다.
- 조명을 받지 않는 재질에 가산 혼합. 겹칠수록 밝아지고, 어두운 사냥터에서도
  같은 밝기로 읽힌다.
- 메시는 모양별로 풀에 넣고 재사용한다. 동시에 48개까지만 살려두고 넘으면
  오래된 것부터 거둔다 — 난전에서 화면이 하얘지지 않게.

### 서버 검증
- `handleSkill` 은 **액션바에 올라간 스킬만** 허용한다
  (`viewer.character.skillBar.includes(skill.id)`).
- 직업과 쿨타임을 서버가 다시 본다. 클라이언트 액션바의 쿨타임 표시는 안내일 뿐.
- 클라이언트가 서버 응답을 안 기다리고 쿨타임을 먼저 돌리는 이유: 연타 도배 방지.
  서버가 거절하면 쿨타임만 돈 셈이라 손해가 작다.

### 이펙트 ★
`skillFx` 가 넷을 그린다 — `cast`(발밑 고리) / `nova`(전방위기 사거리 고리) /
`impact`(명중 섬광) / `heal`(감싸고 올라가는 고리). 색은 `skillColor` 하나로
정한다 (투사체가 있으면 그 색, 없으면 직업 색).

- **어디에 그리는지가 이펙트 종류보다 중요하다.** 시전자 자리에 그리는 건
  **자기 주위로 터지는 기술(`arc >= 2π`)뿐**이다. 근접기(강타처럼 앞을 내리치는
  것)는 발밑에서 고리가 솟으면 "내가 뭔가를 둘렀다" 로 보여서 동작과 전혀 안 맞는다 —
  **맞은 자리에서 터뜨린다.** 그러려면 어느 스킬이었는지 알아야 하므로
  `HitEvent.skillId` 를 서버가 같이 보낸다 (좌표 x/z 와 같은 이유).
  날아가는 기술은 투사체와 착탄이 대신 보여주므로 시전 자리에 겹쳐 그리지 않는다.
- **기본 공격에는 이펙트를 안 그린다.** 타격마다 섬광이 터지면 난전에서 화면만
  번쩍이고 정작 누가 맞았는지는 더 안 보인다. 대신 맞은 쪽이 잠깐 하얘진다
  ([combat.md](combat.md) 의 피격 표시).
- **밝기 곡선을 크기와 반대로 두면 안 된다.** 예전에는 `opacity * (1-t)²` 로
  처음부터 옅어졌는데, 크기는 `t` 를 따라 커지므로 **가장 커지는 순간이 가장
  투명한 순간과 겹쳤다.** 이 게임 카메라는 거리 40 · FOV 30 이라 화면 세로가
  월드 21유닛이다 — 작을 때는 몇 픽셀뿐이라, 결국 어느 프레임에도 눈에 걸리는
  그림이 없었다. 실제로 재보니 **최대 밝기가 765 중 15~22**(약 2.5%)였다.
  2026-09-07 "스킬 이펙트가 안 나온다" 가 이것이다.
  지금은 **빠르게 켜고 · 커져 있는 동안 유지하다 · 끝에서 끈다.**
- **크기와 두께는 카메라 거리에 맞춰야 한다.** 거리 40 에서 반지름 1.15 짜리
  고리는 캐릭터에 가려 안 보인다. 테 두께도 0.22 로는 1080p 에서 10픽셀 남짓이다.
- `nova` 는 **실제 판정 사거리와 같은 크기**로 그린다. 보여주기용이라도 크기가
  다르면 "분명 닿았는데 안 맞았다" 가 된다.
- 이펙트가 하나 빠져도 게임은 그대로 돌아간다 — 판정은 이미 서버가 끝냈다.
- **이펙트는 음영(GTAO) 계산에서 뺀다** (`skillFx.group.userData.noAO`, `postfx.ts`).
  GTAO 는 음영을 구하려고 장면을 한 번 더 그리는데 모든 물체를 같은 재질로 덮어 그린다.
  스프라이트는 거기서 화면을 향해 돌지 않고 서 있는 판자로 그려져 **까만 네모**가 됐다
  (2026-09-12, 그때는 발 연타에서 났다). three 는 점·선만 빼 주므로 `noAO` 가 붙은 것도 숨기게 해 두었다.
  새로 만드는 빛 효과 묶음(투사체·궤적 등)도 같은 증상이면 그 그룹에 `noAO` 를 붙인다.
- **그림 스프라이트(주먹·발·호랑이)는 깊이 검사를 끄고 몸 위에 그린다** (`depthTest: false`,
  `renderOrder` 10). 맞은 몸 한가운데서 터지므로, 켜 두면 몸통 앞쪽이 그림을 가린다 —
  키 2.2m 넘는 오우거에서 절반 넘게 먹혀 "이펙트가 안 나온다" 로 보였다 (2026-09-12).
- **할퀴기는 두 번 갈아엎은 자리다** (`CLAW`). ① 노란 검기 네 장을 정면으로 날렸더니
  발차기가 아니라 칼을 휘두른 것 같았고 ② 차오르는 발 그림으로 바꿨더니 **캐릭터를 덮어**
  무슨 일이 난 건지 안 보였다. 지금은 가느다란 자국 넷이 엇갈린다.
  **큰 그림 한 장은 쿼터뷰에서 몸을 가린다** — 가는 선 여럿이 훨씬 잘 읽힌다.
  검기·발 그림과 그 지오메트리(`makeBladeGeo`)는 같이 지웠다.
- **한 번에 긋는 셋은 나란하고, 두 번을 서로 반대로 긋는다** (`strokes` × `sets`).
  각을 제각각 벌렸더니 할퀸 자국이 아니라 **별표**가 됐고, 나란하게만 뒀더니 이번엔
  **한쪽으로만 그은 빗금**이 됐다 (2026-09-12, 둘 다 지적받았다). 지금은 세 가닥을
  0.7rad 로 긋고 0.1초 뒤 −0.7rad 로 세 가닥을 더 그어 **X 로 엇갈린다** — 한 손으로
  긁고 반대 손으로 되긁는 모양이다. 같은 세트 안에서만 각을 ±0.07 흔든다.
- 가닥은 **자국에 수직인 방향으로** 0.32m 씩 벌려 늘어놓는다. 벌리는 방향을 월드 x/z 로
  잡으면 카메라 각에 따라 간격이 찌그러지므로, 화면 가로(카메라 오른쪽 벡터)와 높이로
  나눠 민다.
- **할퀸 자국은 화면을 정면으로 보게 세운다** (`rotation.y = cameraYaw`). 월드 방향으로
  세우면 카메라 각에 따라 옆으로 누워 **선 하나로** 보인다. **자리는 `facing` 을 따른다** —
  화면이 아니라 캐릭터가 보는 쪽 1.1m 앞이어야 "내가 앞을 긁었다" 가 된다.
- **자국은 가늘고, 가운데가 굵고, 양 끝이 뾰족하고, 살짝 휜다** (`makeSlashGeo`).
  폭이 일정한 막대면 끝이 뭉툭해서 "막대를 놓았다" 로 보이고, 곧기만 하면 빗금이 된다.
  폭은 **길이의 1/25** — 1/11 은 넓적한 마름모였고, 1/40 은 이 카메라에서 3픽셀이라
  배경에 묻힌다 (고리 두께로 한 번 겪은 일이다).
- **몸 앞에서 터지는 메시는 깊이 검사를 꺼야 한다** (`onTop`). 그림(스프라이트)은 늘 그렇게
  그리지만 메시는 기본이 켜져 있어서, 안 끄면 몸통이 자국을 가린다.
- **날아가는 것은 `vx`/`vz` 로 민다** (백호격). 투사체(`projectiles.ts`)는
  **대상이 정해진 것**만 다룬다 — 쏜 자리와 맞을 자리를 알아야 날아가는 시간을 계산할
  수 있어서다. 대상 없이 허공으로 뻗는 것은 이펙트 쪽에서 속도를 준다.
- **날아가는 것은 사거리까지만 간다.** 판정보다 멀리 뻗으면 `nova` 를 판정 범위와 다르게
  그렸을 때와 똑같이 "분명 닿았는데 안 맞았다" 가 된다. 사는 시간은
  `(사거리 − 시작 거리) ÷ 속도` 다 — **몸 앞에서 출발하므로 그만큼 덜 가야 한다.**
  그냥 `사거리 ÷ 속도` 로 뒀더니 3m 짜리가 3.7m 까지 날아갔고, `npm run fx-probe` 가
  잡았다 ([verification.md](verification.md)).
- **호포각은 몸에서 솟는다** (`TIGER`). 처음엔 호랑이 얼굴을 정면으로 날렸는데, 그건
  "쏜" 것이지 "끌어올린" 것이 아니었다 (2026-09-12). 지금은 둘이다 — ① **굵은 기운
  열여섯 줄기가 바닥에 방사로** 뻗고 ② 호랑이가 캐릭터 위로 커지며 올라온다
  (2.2→4.8m, 캐릭터 1.8m 를 넘어야 몸에서 나온 것으로 보인다).
  **한가운데 섬광은 뺐다** — 구(`burstGeo`)를 3m 로 키웠더니 가산 혼합이라 **화면을 덮는
  노란 덩어리**가 됐다. 둘러싸는 모양은 이 스킬에 안 맞는다 (고리도 같은 이유로 뺐다).
- **기운은 뿌리가 굵고 끝이 사라져야 한다** (`makeSpikeGeo`). 처음엔 할퀸 자국을 눕혀
  썼는데, 그건 가운데가 굵고 폭이 길이의 1/25 이라 **허연 실선**으로 보였다 — "나약하다"
  는 지적을 받은 게 그것이다. 지금은 뿌리 반폭이 길이의 1/13 이고 끝으로 갈수록
  `(1−t)^1.6` 으로 얇아진다. 줄기도 열 개에서 **열여섯**으로 늘렸다 — 성글면 약해 보인다.
- **호포각은 푸른 기운이다** (`skillColor` 0x8fd0ff, `TIGER.spikeColor` 0x3fa8ff).
  그러려고 **그림을 회색조로 만들어 커밋했다** — 주황 그림에 파랑을 곱하면 탁한 녹색이 된다.
  회색조로 두면 색은 코드 한 줄로 바뀐다.
- **기운 색은 스킬 색보다 진하다.** 그림은 제 밝기가 있어 옅게 물들여야 하지만, 제 색이
  없는 기운까지 옅게 주면 허옇게 뜬다. 그림을 쓰는 것과 안 쓰는 것은 색을 따로 준다.
- **호포각에는 고리를 안 그린다.** 사거리를 보여주려고 얇은 충격파를 넣었더니 **바닥에
  큰 타원**이 남아 그게 먼저 눈에 들어왔다. 기운 줄기가 사거리까지 뻗으므로 범위는 그것으로
  읽힌다. 고리(`shockGeo`)는 천붕각에서만 쓴다.
- **이펙트가 사방이면 판정도 전방위여야 한다.** 호포각은 원래 정면 90° 였는데 이펙트를
  바꾸면서 `arc` 를 2π 로 고쳤다. 안 고치면 사방으로 터지는 걸 보고도 뒤쪽 적이 안 맞아
  "닿았는데 안 맞았다" 가 된다. `maxTargets` 도 3 → 5 로 올렸다.
- **기운 줄기 길이는 사거리에 묶여 있다.** "줄기를 더 길게" 는 곧 사거리를 늘리는 일이라
  `range` 를 4 → 6 으로 올렸다 (전방위기 상한 8 이내). 이펙트만 늘리면 판정 밖까지 뻗는다.
  굵기는 그것과 무관해서 따로 키운다 (뿌리 반폭 = 길이의 0.1125).
- **호포각만 직업 색을 안 쓴다** (`skillColor`). 솟는 게 기(氣)가 아니라 불호랑이라서다.
  액션바 궤적도 같이 물든다.
  호포각 색이 흰빛에 가까운 이유는 **그림이 이미 주황빛이기 때문**이다 — 진한 주황을
  곱하면 색이 두 번 먹어 빨갛게 죽는다.
- **잔상은 같은 그림을 조금 늦게·작게·흐리게 띄운 것이다** (`TIGER_RUN`). 속도가 같으니
  간격을 유지한 채 따라붙어 한 마리가 빠르게 지나간 자국으로 보인다. 새 그림이 필요 없다.
- **옆모습 그림은 진행 방향에 따라 뒤집어야 한다** (`flipX`, 백호). 스프라이트는 늘 화면을
  보므로 월드 각으로는 판단할 수 없고, **화면에서 어느 쪽으로 가는지**를 봐야 한다:
  `sin(진행각 − 카메라각)` 이 음수면 화면 왼쪽이다. 그래서 `SkillFx.cameraYaw` 를
  `main.ts` 가 매 프레임 넣어 준다 (카메라는 사용자가 돌릴 수 있다).
  안 뒤집으면 왼쪽으로 갈 때 뒷걸음질 치는 것처럼 보인다. 뒤집기는 `scale.x` 를 음수로
  주는 것이라, 크기를 정하는 자리(`place`·`update`)가 둘 다 같은 규칙을 써야 한다.
- **날아가는 그림은 가면서 커져야 한다** (`TIGER.sizeFrom` → `sizeTo`). 크기가 그대로면
  덮쳐 오는 게 아니라 그림이 미끄러지는 것처럼 보인다. 호랑이는 1.6m 에서 3.6m 까지
  — 캐릭터(1.8m)의 두 배가 되어야 "포효가 덮친다" 로 읽힌다.
- **천붕각은 순서가 전부다** (`skyBreaker`). 발과 바닥 셋을 한 번에 띄우고 **바닥은
  발이 닿을 때까지 기다린다**(`wait`). 같이 뜨면 "떨어져서 갈라졌다" 가 아니라 한 덩어리로
  번쩍인 것으로 보인다. 3.2m 에서 시작하는 건 캐릭터(1.8m)보다 커야 하늘에 뜬 게 발인 줄
  알아보기 때문이다.
- **떨어지는 발은 네온 발톱 그림이다** (`sky_foot.png`, 2026-09-16 교체). 바르코 워크플로우
  화면을 찍어 만들었다 — 출력물이 아니라 캡처라 받아 올 주소가 없다 ([ASSETS.md](../ASSETS.md)).
  **회색조로 만들어 커밋했다.** 처음엔 원본의 네온색(파랑·초록)을 살리려고 흰빛으로 띄웠는데,
  "노랑으로 바꿔 달라" 는 요청이 오자 **색을 입힐 방법이 없었다** — 파란 그림에 노랑을 곱하면
  까맣게 죽는다. 호포각에서 이미 겪은 일이고, 답도 같다: 회색조로 두면 색은 코드 한 줄이다.
  512² 인 것도 이 그림뿐이다 (가는 선뿐이라 256 으로 줄이면 뭉개진다).
- **캡처 가장자리에서 잘린 그림은 위쪽을 지워 둔다.** 원본 캡처에 다리가 잘려 들어 있어
  그대로 쓰면 **하늘에서 싹둑 잘린 채로 내려온다** (2026-09-16 지적). 위쪽 42% 를
  smoothstep 으로 흐려 두면 다리가 사그라지는 것으로 읽힌다 — 그림을 다시 만들 일이 아니다.
- **천붕각은 직업 색을 안 쓴다** (`skillColor`, 0xffc23c). 금빛이라 발·금·지진파가
  한 색으로 묶인다. **연노랑이 아니라 진한 금색이어야 한다** — 가산 혼합이라 겹치는 곳은
  흰빛으로 뜨고, 옅은 색으로 두면 전부 흰 덩어리가 된다 (격투가 색 0xcfe8ff 로 뒀을 때가
  그랬다).
- **지진은 "갈라짐" 이 아니라 "어긋난 시간차" 다** ★ (2026-09-16). 예전에는 방사 균열
  일곱 갈래를 **한 덩어리로** 만들어 한 번에 띄웠다(`makeCrackGeo`). 갈라진 것으로는
  보였지만 **흔들리지는 않았다** — 전부 같은 순간에 같은 속도로 퍼져서 바닥에 무늬 한 장이
  켜진 것과 다르지 않았다. 지금은 셋이 겹친다.
  ① **금 여덟이 `fissureStep`(0.035초)씩 어긋나게 갈라지고** (`makeFissureGeo`)
  ② **밟은 자리에서 먼지가 터지고** (`DUST`)
  ③ **지진파 고리 둘이 `waveGap`(0.18초) 차로 잇따라 밀려난다** (`shockGeo`).
  금을 따로 띄우는 것이 핵심이라 한 덩어리 지오메트리를 포기했다 — 이펙트 칸(`MAX_LIVE` 48)을
  스물두 개까지 쓰지만 그만큼이 지진다움이다.
- **갈라진 땅은 가는 금이지 벌어진 도랑이 아니다** ★ (`makeFissureGeo`). 두 번 갈아엎었다.
  한 덩어리 균열(반폭 0.035)을 가닥별로 쪼개면서 **반폭을 0.07 로 키웠는데**, 사거리 6 에서
  0.42m 짜리 흰 띠가 되어 "두꺼운 선" 이라는 지적을 받았다. 지금은 **0.012** — 폭 0.14m,
  1080p 에서 일곱 픽셀이다. 가는 대신 ① 마디마다 크게 꺾이고 ② **곁가지가 한 번 갈라진다.**
  곁가지가 금다움의 전부다 (예전 균열에서도 같은 결론이었다). 가늘어진 만큼 개수는
  여섯 → 여덟로 늘렸다.
- **들려 솟는 지면 판은 지웠다** (`makeRubbleGeo`). 높이를 주려고 판을 세웠는데, 가산 혼합에
  큰 사각형이라 **바닥에 흰 종이가 떠 있는 것**으로 보였다. 높이는 먼지가 대신 준다 —
  먼지는 실루엣이 흐려서 크게 띄워도 덩어리로 안 뭉친다.
- **먼지만 보통 혼합으로 그린다** ★ (`blend: 'normal'`, `DUST`). 다른 이펙트는 전부 가산이라
  겹칠수록 밝아지는데, **먼지는 빛나는 게 아니라 가려야** 하는 것이다. 가산으로 두면 흙먼지가
  아니라 흰 연기가 빛난다. 그래서 `dust.png` 만 **알파를 가진 RGBA** 다 — 보통 혼합에서 알파가
  없으면 까만 네모로 그려진다. 재질은 풀에서 돌려 쓰므로 혼합이 바뀔 때 `needsUpdate` 를 켠다.
- **먼지는 고리가 아니라 터짐이어야 한다.** 여덟 덩이를 `vx`/`vz` 로 바깥으로 밀되,
  **발밑에서 곧장 피어오르는 셋**(`DUST.core`)을 같이 띄운다. 이게 없으면 가운데가 비어
  먼지 고리로 보인다. 나가는 각은 등간격에서 ±0.3rad 만 흔든다 — 완전한 난수면 한쪽에 몰려
  터진 자리가 치우쳐 보인다.
- **지진파 고리는 얇고 어둡다** (`shockGeo` 0.965~1, 밝기 0.5/0.32). 두꺼우면 갈라진 금보다
  고리가 먼저 눈에 들어온다 — 호포각에서 고리를 아예 뺀 것과 같은 이유다. 둘째 고리가 더 작은
  건 사거리를 두 번 주장하지 않기 위해서다.
- 새 바닥은 `npm run fx-probe -- sky_breaker` 로 **스물두 개 · 1.4초**, 먼지가 2.6m 까지만
  나가는 것(사거리 6 안)을 확인한다. 생김새는 브라우저 없이 지오메트리를 위에서 내려다보게
  찍어 봤다 ([verification.md](verification.md)).
- **밖으로 밀려나는 것은 테가 얇아야 한다** (`shockGeo`, 0.92~1). 기본 고리(`ringGeo`)는
  두께가 반지름의 38% 라 사거리 6 에 쓰면 지름 12m 짜리 흰 도넛이 화면을 덮어 정작
  보여주려던 균열이 안 보인다.
- **`castSignature` 는 "이 스킬은 내가 다 그렸다" 를 돌려준다.** true 면 부르는 쪽(`main.ts`)이
  전방위 고리(`nova`)를 건너뛴다 — 천붕각은 그 고리를 발이 닿는 순간에 맞춰 스스로 띄우기
  때문이다. 밖에서 먼저 그리면 발보다 고리가 앞서 퍼져 앞뒤가 뒤집힌다.
- **크기·높이 곡선은 기본이 ease-out 이고, 떨어지는 것만 `ease: 'in'` 이다.** 가속하지 않으면
  "쿵" 하고 닿는 게 아니라 스르르 내려앉는다. 밝기가 꺼지기 시작하는 지점도 `fade` 로
  따로 준다 — 기본값(0.45)이면 절반쯤부터 흐려져 정작 착지가 안 보인다.
- **남은 넷은 맞히지 않아도 뜬다** (`castSignature`). 허공에 써도 발이 차오르고 호랑이가
  달린다 — "몬스터가 없어도 나와야 한다" 는 요청이었고, 그게 스킬을 쓴 느낌을 만든다.
  맞았을 때(`signature`)는 다시 그리지 않는다. 두 번 겹쳐 나온다.
  명중 확인은 `npm run probe -- fight --job fighter` 의 "스킬 명중" 줄로 한다.
  천붕각도 몬스터 없이 시전 자리에서 전부 나온다. 지금은 `SKILL_UNLOCK_ALL` 이 켜져 있어
  Lv.1 로도 배워서 쏴 볼 수 있고, 그리기만 확인하려면 콘솔에서 `__skillFx('sky_breaker')`
  ([verification.md](verification.md)).

### 스킬창과 퀵슬롯 (고도) ★

2026-09-19 요청으로 버튼만 있던 임시판을 갈아 끼웠다.

```
HUD                    [퀵1][퀵2][퀵3][퀵4][자동사냥]          [스킬][가방]
                        ↑ 아래 가운데 (2026-09-19)            ↑ 오른쪽 위
┌──────────────────────┬ 스킬 ─────────────────── [닫기] ┐
│      [큰 아이콘]      │ 장착 중  [1][2][3][4]              │
│        이름           │ 스킬 목록 (4열, 두 줄 보이고 끌어 올림) │
│ ┌ 요구 레벨·재사용·사거리 / 상태 ┐ │                    │
│ ┌ 설명 ────────────┐ │                     [해제] [장착]   │
└──────────────────────┴─────────────────────────────────────┘
```

- **왼쪽이 설명, 오른쪽이 고르기·장착/해제** 다. 받은 그림(가방 상세 화면)의
  배치를 좌우로 뒤집은 것이다 — 요청이 그랬다.
- **장착**: 빈 칸이 있으면 맨 뒤에 붙는다. **4칸이 다 찼으면 "바꿀 칸을 누르세요"**
  로 바뀌고, 장착 중 칸을 누르면 그 자리와 바꾼다 (단추는 "취소" 가 된다).
  옛 창은 말없이 맨 앞 칸을 밀어내서 무엇이 빠지는지 몰랐다.
- **빈 퀵슬롯은 눌러도 아무 일 없다** (2026-09-23 요청). 전에는 스킬창이 열렸는데
  뺐다 (`_on_bar_pressed`). 칸의 "+" 글자는 그대로 둔다.
- **설명 끝에 데미지 줄**을 붙인다 (2026-09-23 요청, `Skills.damage_text`).
  `power` 를 백분율로 적고(`데미지 : 260%`), 연타(`hits` ≥ 2)는 대수를 곱으로 붙인다
  (`데미지 : 56% * 5연타`). World 가 한 대마다 `공격력 × power` 를 넣으므로 한 대 몫이다.
  회복기(`selfHeal`)는 공격 판정이 없어 줄을 안 붙인다.
- **배우기 단추는 없다.** 장착할 때 아직 안 배웠으면 `learnSkill` 을 먼저 보낸다
  (`_send_bar`). World 는 배운 것만 액션바에 올리므로 순서가 바뀌면 그 칸이 걸러진다.
- **칸 번호 = 액션바 목록 순서다.** `World.set_skill_bar` 가 빈 칸 없이 앞에서부터
  채우기 때문에, 가운데 칸을 해제하면 뒤 칸이 한 칸씩 당겨진다. 빈 칸을 두려면
  World 의 액션바 형식(과 저장)을 바꿔야 해서 그대로 뒀다.
- **자동사냥도 같은 칸으로 퀵슬롯 옆에 붙는다** (2026-09-19). 칸 짓는 법은 같고
  아이콘만 더 물린다 → [hud.md](hud.md).
- **퀵슬롯 왼쪽 위에 단축키 번호**(1~4)를 적고, 키보드 1~4 로도 쓴다 (`_unhandled_input`).
  **목록 칸에는 장착 번호를 적지 않는다** — 번호는 퀵슬롯에만 있다 (2026-09-19 요청).
- 목록 칸 가운데 아래에 **안 배운 것만 "Lv.N 습득"**, 배우면 지운다.
- **쿨타임 연출**: 어둠이 12시에서 반시계로 남은 몫만큼 덮고(`FILL_COUNTER_CLOCKWISE`),
  그래서 **밝은 쪽이 시계 방향으로 넓어진다.** 경계에는 빛 바늘(`CoolEdge`)이 돌고,
  남은 초는 1초 아래에서 소수 한 자리로 바뀐다. 끝나는 순간 칸이 번쩍이며 살짝
  튀었다 가라앉는다(`_flash_ready`). 둥근 채우기는 늘이면 안 그려져서 흰 판을 칸
  크기 그대로 만든다(`_white`).
  - 도는 동안 아이콘을 흐리게 하던 것은 뺐다 — 어둠과 흐린 아이콘이 둘 다 어두워
    **걷히는 경계가 안 보였다.**
  - **테스트 스위치 `cooldownOff` 가 켜져 있으면 쿨타임이 늘 0 이라 연출이 안 보인다.**
- **왼쪽 상자 둘은 `ui_slot` 테두리다. `ui_subpanel` 을 쓰지 않는다.** ★ 그 그림은
  가운데 얇은 판 + 넓은 빛번짐이라, 9조각으로 늘이면 판이 글자보다 작게 그려져
  **글자가 상자 밖으로 나와 보였다** (2026-09-19). 수치(글자 사각형)로는 안에 있어서
  테스트로는 못 잡는다 — 찍어서 봤다.
- 칸은 전부 `_make_skill_cell` 하나로 짓는다 — 퀵슬롯·장착 칸·목록 칸·큰 아이콘.
  테두리 안쪽 여백을 0 으로 두고 아이콘만 `SKILL_INSET` 만큼 물린다. 고른 칸 테두리
  (`ui_slot_pick`)가 칸 테두리 위에 정확히 겹쳐야 해서다.
- **아이콘 이름 = `skill_<id>`.** 없으면(마법사·궁수) 칸에 스킬 이름이 글자로 나온다.
  스킬 아이콘은 칸을 꽉 채운 그림이라 `build-item-icons.mjs` 가 **배경을 걷지 않는다**
  (`FULL`) — 걷으면 어두운 연기·하늘을 따라 그림 속까지 파먹는다.
  `ui_slot_pick` 은 안쪽을 뚫는다(`HOLLOW`).
- 바르코 조각 둘(칸·고른 칸)은 **`ui_slot` 을 참고 그림으로 넣어** 가방 창과 결을 맞췄다.
- **셋째 칸 "강화"** (2026-09-23) — 고른 스킬의 강화 1번·2번 카드(경험치 막대)와
  경험치북 단추 셋. 창이 1250px 로 넓어져 **열 때 맨 앞으로 올린다** → [skill-upgrades.md](skill-upgrades.md)
- 확인은 `ui_test.gd` 의 `_case_skills` — 아래 가운데 자리·단추와 안 겹침·쿨타임 표시·
  창이 화면 안·좌우 배치·고르면 설명이 바뀜·데미지 줄·해제/장착/바꾸기·
  빈 퀵슬롯을 눌러도 창이 안 열림·새 문구 글자.

### 자동 시전
- 액션바 칸의 `A` 스위치. 목록은 `localStorage['mmo.autoSkills']` 에 남고
  접속하자마자 서버로 보낸다.
- 실제 시전은 서버 `tryAutoSkill` 이 한다 → [auto-hunt-and-targeting.md](auto-hunt-and-targeting.md).
- **고도**: `A` 스위치 없이 자동 사냥이 **액션바의 스킬을 전부** 칸 순서대로 쓴다
  (`World._auto_cast`) → [auto-hunt-and-targeting.md](auto-hunt-and-targeting.md) 의 "스킬도 쓴다".
