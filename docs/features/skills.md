# 스킬

## 무엇

직업당 10개, 총 30개. 배우고(스킬 포인트) 그중 **4개만 액션바에 올린다.**

## 어디

| 파일 | 역할 |
|---|---|
| `packages/shared/src/skills.ts` | 스킬 30개 정의, `canLearn`, `skillForJob` |
| `packages/shared/src/skills.test.ts` | 데이터 규칙 검사 (요구 레벨 순서, 직업 균형, 투사체 짝) |
| `packages/client/src/ui/skillBook.ts` | 스킬창 (K) — 배우기 / 장착 |
| `packages/client/src/ui/actionBar.ts` | 액션바 4칸 + 칸마다 자동시전 `A` 스위치 |
| `packages/client/src/scene/skillFx.ts` | 시전·전방위·명중·회복 이펙트, 스킬 색 |
| `packages/client/src/scene/skillFx.ts` | **스킬 이펙트** — 시전 고리, 전방위 고리, 명중 섬광, 회복 |
| `packages/server/src/ZoneRoom.ts` | `handleLearnSkill` / `handleSetSkillBar` / `handleSkill` / `tryAutoSkill` |

## 규칙

- 요구 레벨은 세 직업이 **동일**: 1, 6, 12, 20, 35, 55, 80, 120, 150, 200.
  직업마다 배우는 시점이 다르면 그 자체로 강약이 갈린다.
- `SKILL_BAR_SIZE = 4`, `SKILL_POINT_PER_LEVEL = 1`.
- Lv.20 까지 배울 수 있는 스킬이 최소 4개 — 안 그러면 액션바에 빈 칸이 남는다.
- 스킬 필드: `power`(공격 배율) / `range` / `arc` / `maxTargets` /
  `cooldown` / `projectile?` / `selfHeal?`.
- **회복기는 때리지 않는다** — `power: 0`, `maxTargets: 0`. 둘 다 하면 판정 경로가 갈린다.
- **투사체 규칙**: 한 방향으로(`arc < 2π`) 사거리 4 넘게 쏘는 스킬에는 투사체가
  반드시 있어야 한다. 없으면 멀리서 쏘는데 아무것도 안 날아가고 즉시 맞는 것처럼
  보인다. 반대로 자기 중심 전방위기(`arc >= 2π`, 투사체 없음)는 사거리 8 이하여야
  한다 — 길면 화면 밖 적까지 맞아 무슨 일인지 알 수 없다. 둘 다 테스트가 잡는다.

### 자원 소모는 없다
**마나를 게임에서 걷어냈다.** 스킬을 쓰는 데 드는 것은 쿨타임뿐이다.

자원 관리가 컨텐츠를 만드는 데 방해만 됐다 — 마나가 떨어지면 스킬이 안 나가고,
그러면 이펙트도 판정도 확인할 수가 없다. 반쯤 끄는 스위치를 두는 것보다
아예 없애는 쪽이 코드가 정직하다.

없어진 것들:
- `SkillDef.mpCost`, `Stats.maxMp`, `ItemBonus.maxMp`
- `Player` 스키마의 `mp` / `maxMp`, 서버의 마나 회복 틱
- 상태바의 마나 막대, 액션바 칸의 소모량, 마나 부족 잠금(`is-poor`)
- 스킬창 설명의 "마나 N" 줄

장신구와 마법서가 마나를 주던 자리였다 — 그 몫은 공격과 체력으로 옮겼다
([items.md](items.md)).

### 이펙트 (`skillFx.ts`)
스킬은 오랫동안 **투사체와 피해 숫자만** 있었다. 근접기와 자기 주위로 터지는
기술은 아무것도 안 보여서, 눌렀는데 숫자만 뜨는 것처럼 느껴졌다.

| 언제 | 무엇 |
|---|---|
| 스킬을 쓸 때 | 발밑에서 솟는 고리 (`cast`) |
| 전방위기(`arc >= 2π`, 투사체 없음) | 사거리만큼 퍼지는 고리 (`nova`) |
| 회복기 | 몸을 감싸고 올라가는 고리 (`heal`) |
| 맞았을 때 | 그 자리의 짧은 섬광 (`impact`) |

- 색은 `skillColor(skill)` — 투사체가 있으면 그것과 맞추고, 없으면 직업으로 정한다.
- **남이 쓴 것도 보인다.** 옆에서 뭘 하는지 안 보이면 같이 노는 느낌이 안 난다.
- 전방위 고리는 **판정 범위와 같은 크기**로 그린다. 다르면 "분명 닿았는데
  안 맞았다"가 된다.
- 투사체가 있는 스킬은 고리를 겹쳐 그리지 않는다 — 날아가는 게 이미 보여준다.
- 명중 섬광은 투사체가 **도착할 때** 뜬다. 피해 숫자와 같은 타이밍이다.
- 조명을 받지 않는 재질에 가산 혼합. 겹칠수록 밝아지고, 어두운 사냥터에서도
  같은 밝기로 읽힌다.
- 메시는 모양별로 풀에 넣고 재사용한다. 동시에 48개까지만 살려두고 넘으면
  오래된 것부터 거둔다 — 난전에서 화면이 하얘지지 않게.

### 서버 검증
- `handleSkill` 은 **액션바에 올라간 스킬만** 허용한다
  (`viewer.character.skillBar.includes(skill.id)`).
- 직업과 쿨타임을 서버가 다시 본다. 클라이언트 액션바의 쿨타임 표시는 안내일 뿐.
- 클라이언트가 서버 응답을 안 기다리고 쿨타임을 먼저 돌리는 이유: 연타 도배 방지.
  서버가 거절하면 쿨타임만 돈 셈이라 손해가 작다.

### 이펙트 ★
`skillFx` 가 넷을 그린다 — `cast`(발밑 고리) / `nova`(전방위기 사거리 고리) /
`impact`(명중 섬광) / `heal`(감싸고 올라가는 고리). 색은 `skillColor` 하나로
정한다 (투사체가 있으면 그 색, 없으면 직업 색).

- **어디에 그리는지가 이펙트 종류보다 중요하다.** 시전자 자리에 그리는 건
  **자기 주위로 터지는 기술(`arc >= 2π`)뿐**이다. 근접기(강타처럼 앞을 내리치는
  것)는 발밑에서 고리가 솟으면 "내가 뭔가를 둘렀다" 로 보여서 동작과 전혀 안 맞는다 —
  **맞은 자리에서 터뜨린다.** 그러려면 어느 스킬이었는지 알아야 하므로
  `HitEvent.skillId` 를 서버가 같이 보낸다 (좌표 x/z 와 같은 이유).
  날아가는 기술은 투사체와 착탄이 대신 보여주므로 시전 자리에 겹쳐 그리지 않는다.
- **기본 공격에는 이펙트를 안 그린다.** 타격마다 섬광이 터지면 난전에서 화면만
  번쩍이고 정작 누가 맞았는지는 더 안 보인다. 대신 맞은 쪽이 잠깐 하얘진다
  ([combat.md](combat.md) 의 피격 표시).
- **밝기 곡선을 크기와 반대로 두면 안 된다.** 예전에는 `opacity * (1-t)²` 로
  처음부터 옅어졌는데, 크기는 `t` 를 따라 커지므로 **가장 커지는 순간이 가장
  투명한 순간과 겹쳤다.** 이 게임 카메라는 거리 40 · FOV 30 이라 화면 세로가
  월드 21유닛이다 — 작을 때는 몇 픽셀뿐이라, 결국 어느 프레임에도 눈에 걸리는
  그림이 없었다. 실제로 재보니 **최대 밝기가 765 중 15~22**(약 2.5%)였다.
  2026-09-07 "스킬 이펙트가 안 나온다" 가 이것이다.
  지금은 **빠르게 켜고 · 커져 있는 동안 유지하다 · 끝에서 끈다.**
- **크기와 두께는 카메라 거리에 맞춰야 한다.** 거리 40 에서 반지름 1.15 짜리
  고리는 캐릭터에 가려 안 보인다. 테 두께도 0.22 로는 1080p 에서 10픽셀 남짓이다.
- `nova` 는 **실제 판정 사거리와 같은 크기**로 그린다. 보여주기용이라도 크기가
  다르면 "분명 닿았는데 안 맞았다" 가 된다.
- 이펙트가 하나 빠져도 게임은 그대로 돌아간다 — 판정은 이미 서버가 끝냈다.

### 자동 시전
- 액션바 칸의 `A` 스위치. 목록은 `localStorage['mmo.autoSkills']` 에 남고
  접속하자마자 서버로 보낸다.
- 실제 시전은 서버 `tryAutoSkill` 이 한다 → [auto-hunt-and-targeting.md](auto-hunt-and-targeting.md).

## 손댈 때

- 스킬을 추가하면 `npm test` 가 요구 레벨 순서·직업 균형·투사체 짝을 잡아 준다.
  통과 못 하면 데이터가 틀린 것이지 테스트가 틀린 게 아니다 —
  단, 규칙 자체가 현실과 안 맞는 경우도 있었다(자기 중심 폭발기). 그때는 규칙을 고친다.
