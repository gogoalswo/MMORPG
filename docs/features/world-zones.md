# 존과 월드

## 무엇

마을 1개 + 사냥터 28개 + **던전 20단계**, 전부 같은 크기의 정사각 맵. **존끼리는
이어져 있지 않다** — 어디를 가든 차원문에서 목적지를 고른다. 던전만은 차원문 목록에
없고 가방 옆 던전 창으로 들어간다 → [dungeons.md](dungeons.md).

## 규칙

### 크기
- 모든 존 `size: 66` (`zone.ts` 의 `ZONE_SIZE` 하나 — 마을·사냥터·던전·전직 시험), 이동 가능 영역 ±29.
- **2026-09-28 오후에 33 → 66 (한 변을 두 배)으로 키웠다** ★ ("맵 크기를 지금보다 두 배 키우고,
  몬스터 간격을 넓혀"). 차원문·무리·던전 보스·지형·꾸밈 자리를 **전부 두 배로** 옮겨 배치의
  모양(문은 화면 맨 위 귀퉁이, 무리는 아래 귀퉁이)은 그대로다. 몬스터 간격은 아래 "몬스터 자리" (2026-09-29 에 무리를 없애고 한 마리씩 세웠다).
- (이전) 같은 날 오전에 66 → 33 (한 변을 반)으로 줄였었다 ("맵 크기를 지금의 반으로"). 넓이 기준
  반(47)도 물었는데 한 변 기준을 골랐다. 맵이 한 화면보다 작았다.
- **화면 방향** — 카메라가 남동쪽 45°(`camera_rig.gd` `YAW`)에서 보므로 정사각 맵이 화면에는
  마름모다. 화면 위 = (-x, -z) 귀퉁이, 아래 = (+x, +z), 오른쪽 = (+x, -z), 왼쪽 = (-x, +z).
  사용자가 말하는 "위·아래" 는 이 화면 기준이다.
- (이전 기록, 66 일 때)
- **2026-09-23 에 92 → 62 (2/3)로 줄였다** ("맵이 너무 커"). 92 는 FOV 30 / 거리 40 /
  부각 42 에서 16:9 화면에 보이는 지면(약 56.5유닛)의 1.5배였다.
- **같은 날 62 → 66 으로 조금 되돌렸다.** "몬스터가 포탈이랑 너무 가깝다" 해서 무리를
  ±14 → ±16 으로 밀었는데, 무리가 이미 벽에 닿아 있어 맵을 키우는 것 말고는 자리가
  없었다 (마릿수를 줄이는 안과 벽에 걸치는 안 중 사용자가 이것을 골랐다).
- 무리·보스·차원문 자리가 같이 당겨졌다 (아래 각 절). 줄이면서 **도착 지점이 무리
  인식 범위 밖**과 **자동 사냥이 옆 무리를 안 끈다** 두 규칙을 놓았다 — 50마리를
  유지하면서 둘 다 지킬 자리가 없어서, 사용자가 "무리를 붙인다" 를 골랐다.
- 도착 지점은 어느 존이든 `default` = 맵 한가운데 `(0, 0)` 하나뿐이다. **마을만 예외로 `(4, 4)`** —
  한가운데에 문이 서 있어서 문 바로 아래(화면 아래쪽)로 물렸다 (2026-09-29).

### 차원문 ★
```
마을 ─┐
       ├─ 차원문 ─┬─ 슬라임 서식지(Lv3) · 뿔토끼 들판(Lv8)      ← 저레벨 여섯은 몬스터 한 종에 한 곳
사냥터 ┘          ├─ 버섯 군락지(Lv13) · 사마귀 둥지(Lv18)
                  ├─ 전갈 소굴(Lv23) · 코볼트 야영지(Lv28)
                  ├─ 잿빛 황야(30-40)
                  ├─ …
                  └─ 종말의 대지(190-200)
```
**마을은 맵 한가운데 `(0, 0)`, 사냥터를 뺀 나머지 존(던전·전직 시험)은 `(-18, -18)` — 화면 맨 위 귀퉁이 — 에** 목적지를 고르는 문이 하나 있다 (`ZoneDef.gate`,
`GateDef`). 밟으면 **이동하지 않고 목록을 연다.** 고르면 그 존의 `default`
스폰(맵 한가운데)으로 간다.

- **걸어 들어가는 포탈은 없다.** 예전에는 존끼리 사슬 포탈로 이어져 있어서
  가장자리(±34)를 밟으면 곧장 옆 사냥터로 넘어갔다. 전부 없앴다(요청).
  `zones.test.ts` 가 `ZoneDef` 에 `portals` 가 되살아나지 않는지 검사한다.
- **사냥터에는 문이 없다** ★ (2026-09-29 요청: "사냥터에 들어가면 포탈을 제거해"). 나올 때는 HUD
  위쪽 가운데 **"마을가기"** 단추로 마을에 간다 ([hud.md](hud.md) "마을가기") — 그래서 `ZoneDef.gate`
  는 선택(`gate?`)이다. 마을·던전·전직 시험에는 그대로 있다. `zones.test.ts` 의 "차원문이 사냥터
  말고는 모든 존에 있다" 가 양쪽을 본다.
- (이전) 문은 모든 존에 있어야 했다 — 하나라도 빠지면 그 존은 들어가면 죽는 것 말고는 나올 방법이
  없었다. 마을가기 단추가 생겨 사냥터는 빠졌다.
- **목록 맨 위가 마을이다.** 돌아가는 길이 20줄 끝에 있으면 매번 훑어야 한다.
- **마을로 오면 체력이 가득 찬다** ★ (2026-10-02 요청). 마을가기 단추·차원문·던전에서 나오기가 전부
  `world.gd` 의 `_move_to` 를 지나서 거기서 채운다. 죽어서 오는 길은 `revive` 가 따로 채운다.
  `monster_test.gd` 의 `_case_gate` 가 HP 1 로 마을에 와서 가득 찼는지 본다.
- 자리·색·이름을 **존마다 같게** 둔다 (`GATE_SPOT` `GATE_COLOR` `GATE_NAME`).
  존을 옮길 때마다 "나가려면 어디로" 를 다시 찾지 않는다. 이것도 검사한다.
  **자리만 마을은 예외** — `VILLAGE_GATE_SPOT` = (0, 0) (2026-09-29 요청 "마을에서는 포탈이 맵
  가운데 있게"). 마을은 몬스터가 없어 문과 몬스터를 양 끝으로 가를 이유가 없고, 광장 한복판이라
  먼저 눈에 띈다. 광장(12) 안이라 마을 지형은 문 자리를 `flats` 로 누르지 않는다.
- 색은 파랑 `#4aa8ff`, 문 위에 **「사냥터 이동」** 이 파란 글씨로 뜬다
  (`NameplateLayer` 의 `kind: 'portal'`). 밟기 전에는 무슨 문인지 알 수 없어
  그냥 지나치게 된다. 차원문 **창**도 같은 파란색으로 맞춰 뒀다.
- `test()` 의 armed 규칙 — 반경을 한 번 벗어나야 다시 발동하므로,
  창을 닫고 문 위에 서 있어도 계속 다시 열리지 않는다.
- 지금 서 있는 존은 목록에서 `현재` 로 표시하고 누를 수 없게 한다. 눌러 봐야
  존을 다시 세우기만 하고 아무 데도 안 간다.
- 자리 규칙: 스폰·NPC·몬스터 무리와 겹치면 안 된다. 겹치면 예외가 아니라
  "접속하자마자 창이 열린다" 같은 증상으로만 나타나서 `zones.test.ts` 가 잡는다.
  **도착 지점과 달리 인식 범위(`aggroRange`)까지는 안 본다** — 문은 걸어서 가는
  자리라 그렇게 잡으면 네 무리(±16) 사이에 놓을 데가 없다.
- **(4, 0) → (-9, -9)** (2026-09-28, "포탈을 맨 위 방향에 설치해"). 몬스터가 화면 아래
  귀퉁이에서만 나오니 문과 몬스터가 맵 양 끝으로 갈린다. 도착 지점에서 12.7, 이동 끝
  (±12.5) 안쪽. 마을은 광장을 11 → 12 로 넓혀 문 자리가 평평하게 남는다(아래 "지형").
- **(-9, -9) → (-18, -18)** (같은 날, 맵을 66 으로 키우며 두 배로). 도착 지점에서 25.5, 이동 끝
  (±29) 안쪽. 광장(12) 밖이라 마을은 문 자리를 `flats` 로 눌러 평평하게 둔다.
- (이전) **(9, 0) → (4, 0)** (2026-09-23). 무리가 ±14 로 붙으며 9 에서는 동쪽 두 무리
  가장자리에 문이 걸쳤다. 무리를 ±16 으로 민 지금은 x ≤ 10.2 면 검사를 지키지만
  **4 에 그대로 둔다** — 문과 몬스터 사이를 벌리려고 민 것이라서다 (무리 가장자리까지 7m).

**잠그지 않는다.** 레벨대(`Lv.33~38 보스 39`)와 위험/적정/쉬움만 표시하고 아무
사냥터나 고를 수 있다. 근거가 둘이다 — (1) 존에 들어가는 것 자체는 **원래도**
서버가 막지 않는다. 클라이언트가 룸을 고르고 서버는 받아준다. 여기서만 막으면
걸어가는 길로 우회하면 그만이라 규칙이 아니라 불편이 된다. (2) 파워레벨링은
경험치 감쇠가 이미 막고 있다 ([monsters-progression.md](monsters-progression.md)).
정말로 막아야 한다면 `ZoneRoom.onJoin` 에 검사를 넣어야 하고, 그건 이미 그 존에
서 있는 캐릭터를 접속 불가로 만들 수 있어 따로 결정할 일이다.

판정 기준은 `REACH = 4` 하나다 — `combat.test.ts` 가 레벨 곡선을 검사할 때
쓰는 값과 같은 눈금이라, 화면에 "적정" 인데 경험치는 안 붙는 구간이 안 생긴다.

### 저레벨 사냥터 여섯 — 몬스터 이름을 딴 곳 ★ (2026-09-29)
지시: "사냥터 이름을 몬스터 이름이랑 섞어서 만들어. 예를 들어 슬라임 서식지", 그리고 "몬스터마다
사냥터 하나 (6곳)". 옛 초원·덤불숲·메마른 협곡 세 곳이 여섯으로 갈렸다.

| id | 이름 | 몬스터 (Lv) | 바닥 |
|---|---|---|---|
| `slime_habitat` | 슬라임 서식지 | 슬라임 (3) | 풀 |
| `meadow` | 뿔토끼 들판 | 뿔토끼 (8) | 풀 (옛 초원) |
| `mushroom_grove` | 버섯 군락지 | 버섯괴물 (13) | 풀, 어둡게 |
| `thicket` | 사마귀 둥지 | 사마귀 (18) | 흙 지형 (옛 덤불숲) |
| `scorpion_den` | 전갈 소굴 | 전갈 (23) | 모래 |
| `canyon` | 코볼트 야영지 | 코볼트 (28) | 흙 (옛 메마른 협곡) |

- **옛 id 는 강한 종이 물려받았다.** 사냥터는 원래도 강한 종(Lv8·18·28)만 세웠으니 저장된 위치의 레벨대가
  그대로고, 테스트·덤불숲 지형(`terrain.gd` 의 `"thicket"`)도 그대로다. 약한 종(Lv3·13·23)은 전에는
  종만 있고 사냥터에 안 섰는데, 이제 제 사냥터가 생겼다.
- **표에서 뽑는다.** `FIELDS` 줄에 `weak: true` 를 달면 그 티어의 약한 종 사냥터다. `FIELD_MOBS` 가 표
  순서로 [티어, 종] 을 센다 — 강한 종 사냥터 하나가 티어 하나를 닫아서, 약한 종 사냥터가 끼어도 뒤
  사냥터(잿빛 황야 Lv38 …)의 레벨이 안 밀린다. 레벨을 손으로 적지 않는다.
- 자리 씨앗은 강한 종 사냥터가 예전 번호(티어) 그대로라 배치가 안 바뀌었고, 약한 종은 `100 + 티어` 다.
- 사냥터가 28곳이라 차원문 창은 29줄이다 (스크롤 창이라 넘치지 않는다 — `ui_test` 가 센다).

### 만렙 너머 사냥터 다섯 ★ (2026-10-02)
지시: "사냥터 5개 더 추가해" → "현재 마지막 사냥터 이후 사냥터야". 종말의 대지(Lv198) 뒤에 붙인다.
**만렙은 200 그대로**(사용자가 골랐다 — 만렙을 올리는 안도 물었다)라 몬스터 레벨은 전부 200 이다 (`monsters.ts` 의 `BEYOND`, 한 곳 한 종).
**체력·공격력은 기존 사냥터처럼** 오른다 (2026-10-04) — 기존 마지막 두 사냥터 사이 비율(Lv188 → 198, 고정 표에서 읽음:
체력 ×1.79 · 공격 ×1.43)을 종말의 대지 몬스터에 한 칸마다 더 곱한다. 방어는 Lv200 그대로. **덩치는 기존의 1.5배**(`BEYOND_SCALE`).
드랍은 6·7등급 창이 종말의 대지부터 이어지므로 **6·7등급 확률이 한 칸마다 ×1.1** ([items.md](items.md) "한 등급이 연달아 나오면").

### 바닥 ★
바닥은 **이미지 8장**(7장 + 2026-09-29 덤불숲 흙 · 바르코로 만든 타일 텍스처, [ASSETS.md](../ASSETS.md))으로 깐다.
존마다 `env.ground` **한 장만** 깐다. 풀 잎·흙길·자갈길은 없다.

| 바닥 | 존 |
|---|---|
| `stone` 돌판 | 마을 |
| `grass` 풀 | 초원·안개 늪·검은 삼림·뒤틀린 숲·빛바랜 고원 |
| `soil` 흙 | 덤불숲 (2026-09-29, 아래 "덤불숲") |
| `dirt` 마른 땅 | 메마른 협곡·잿빛 황야·소금 평원·그림자 계곡 |
| `snow` 눈 | 서리 고원·얼어붙은 심연 |
| `sand` 모래 | 붉은 사막·유황 분지 |
| `cobble` 자갈 | 무너진 성터·폐허 도시·심연의 문턱 |
| `lava` 용암 균열 | 화산재 언덕·균열 지대·종말의 대지 |

- **사냥터 20곳이 여섯 장을 나눠 쓴다.** 이미지가 7장이라고 존을 7개로 줄이지 않았다 —
  몬스터 티어·아이템 단계(20)·레벨 곡선이 사냥터 수에 1:1 로 묶여 있다 (2026-09-10
  요청: 사냥터 20개 유지, 바닥만 교체).
- **같은 텍스처를 쓰는 곳끼리는 존 색으로 갈린다.** `groundTint`(풀밭은 `grassLight`,
  나머지는 `dirtLight`) 쪽으로 텍스처 평균색을 절반(`TINT_PULL` 0.5)만큼 끌어당긴다.
  1 이면 소금 평원이 마른 땅의 제 색을 완전히 잃고, 0 이면 초원과 검은 삼림이 같은
  바닥이 된다. 명암(무늬)은 곱셈이라 그대로 남는다. 소금 평원은 금 간 마른 땅을
  하얗게 물들인 것이다.
- **반사율을 0.3배로 깐다**(`ALBEDO`). 조명(태양 2.7·환경광·ACES)은 예전 ambientCG
  텍스처 — 어둡고 존 색 ×2 를 곱해 쓰던 — 에 맞춰져 있다. 바르코 이미지는 화면에 보일
  밝기로 그려져 있어서 그대로 깔면 눈·모래·소금 평원이 하얗게 날아가 무늬가 사라졌다.
  마을에서 재 보니 반사율 → 화면(선형)이 3.2배였다. 조명을 건드리면 캐릭터·몬스터가
  같이 흔들리므로 바닥 쪽을 낮췄다.
- **풀 잎·길은 없다** (2026-09-10 요청: 이미지 준 맵만 깐다). 예전에는 풀밭·마을에
  흙길·자갈길을 스플랫 마스크로 섞고(`ROAD_FOR`, `createPathMask`), 풀 잎을 인스턴싱으로
  수만 포기 심었다(`GRASS_SHARE`, `grass.ts`). 셋 다 코드째 뺐다. `zones.test.ts` 가
  `road`·`roads`·`grassCount` 가 `env` 에 돌아오지 않는지 검사한다.
  **마을의 자갈길은 이것과 다르다** — 2026-09-26 에 지형을 만들라고 해서 고도 쪽
  `terrain.gd` 가 바닥 넉 장을 섞어 깐다(아래 "지형"). shared `env` 에는 여전히 길이 없다.
- `grassDark`/`grassLight` 는 이름만 풀이다 — 하늘·반구광의 땅 쪽 색과 풀밭 틴트로 계속 쓴다.
- 텍스처 성질은 존이 아니라 **이미지에 딸린 것**이라 `ground.ts` 의 `LOOKS` 에 있다.
  - 타일 크기: 돌판 6m(판석 80cm), 자갈 8m, 용암 12m, 나머지 4~6m. 자갈을 4m 로 두면
    기본 카메라에서 알이 안 보이고 잡티가 되고, 용암을 8m 로 두면 재 얼룩이 격자로 늘어선다.
  - `blend`: 배율이 다른 샘플을 겹쳐 반복을 깨는 비율. 돌판·자갈·용암처럼 **모양이
    뚜렷한 것은 0** — 섞으면 판석이 두 겹으로 비친다.
  - `glow`: 용암 균열은 스스로 빛난다. **틴트 전 원래 색**에서 붉고 파랑이 빠진 곳만
    골라서, 어두운 존 색을 곱해도 균열 빛은 안 죽는다.
  - `mean`: 텍스처 평균색. 틴트의 기준이라 **빌드 스크립트가 출력하는 값과 같아야 한다.**
- 이미지에 노멀·러프니스 맵이 없다. 노멀은 빌드 때 **밝기를 높이로 봐서** 만들고
  (`build-ground-textures.mjs`, 이음새가 안 생기게 반대편 가장자리와 이어서 계산),
  러프니스는 종류별 상수다.
- **고도에는 안개가 없다** ★ (2026-09-18 요청: "안개를 넣으라고 한 적이 없는데
  왜 넣은거야? 그냥 안개를 없애버려"). `environment_for` 가 `fog_enabled = false`
  로 두고, `ground_test.gd` 가 존 세 곳에서 꺼져 있는지 검사한다.
  - 안개는 옛 웹 클라이언트에 있던 것이 **고도 이관 때 따라온 것**이다(`e4a3791`).
    옮기면서 선형(70m → 190m)이 near 없는 지수 안개(`fog_density` 0.006)로
    바뀌어, 70m 앞에서나 끼어야 할 것이 **카메라 바로 앞(27m) 바닥에도 15%
    섞이고 있었다.**
  - 안개는 곱이 아니라 **더하기**라 돌 틈처럼 어두운 데를 그대로 들어올린다 —

    무늬가 거의 사라지고, 화면이 안개색(`#c2c8b8`)으로 떴다.
  - 조명(태양·환경광)은 반사율에 **곱해지므로** 무늬 대비 비율을 안 건드린다.
    대비를 깨는 건 더하기로 들어오는 안개뿐이었다.
  - **데이터에서도 지웠다.** `ZoneEnv` 의 `fogColor`·`fogNear`·`fogFar`, 테마 표
    (`FIELD_THEMES`)의 `fog` 열, `envFor` 의 안개 보간이 전부 없다. 옛 Colyseus
    서버는 `env` 를 그대로 넘겨주기만 해서 따로 고칠 데가 없었다.
- **고도는 바닥을 셰이더로 깐다**(`godot/game/ground.gdshader`). 2026-09-17 에
  "이미지로는 재질이 잘 보이는데 깔아 놓으면 돌 틈·풀이 너무 희미하다" 는 지적을
  받아 `StandardMaterial3D` 에서 옮겼다. 표준 재질로는 아래 셋 중 어느 것도 못 준다.
  - **무늬 대비**(`CONTRAST` 1.4) — 텍스처 평균색을 축으로 밝기 **비율**을 지수로
    벌린다(`mean * pow(c / mean, 1.4)`). 평균이 그대로라 존 밝기는 안 변하고 무늬만
    또렷해진다. 빼기로 벌리면 어두운 쪽이 0 에 붙어 돌 틈이 새까만 선이 된다.
    돌판 텍스처는 밝기 폭이 6.4배 → 13.4배가 된다 (`ground_test.gd` 가 찍는다).
    반사율 배율(`ALBEDO`)로는 안 된다 — 곱셈이라 밝기만 낮추고 대비는 그대로다.
  - **아니소트로픽 필터** — 쿼터뷰(내려보기 43도)라 바닥이 비스듬하다. 밉맵만 쓰면
    세로로 눌린 만큼을 기준으로 단계가 잡혀서 가로 무늬까지 같이 뭉갠다.
    표준 재질의 기본 필터에는 아니소트로픽이 없다.
  - **노멀 세기**(`NORMAL_DEPTH` 2.0) — 밝기로 만든 노멀맵이라 기본 1.0 으로는
    요철이 밋밋하다.
- 텍스처 자체에는 무늬가 충분히 있다(2026-09-17 에 잰 선형 밝기 — 돌판 p5 0.016 ·
  p95 0.102, 자갈 0.036 · 0.329). 화면에서 희미했던 건 이미지가 아니라 재질 쪽이었다.
- 일곱 장을 **부팅 때 전부** 받는다(KTX2 14장 2.5MB). 존마다 받으면 존 구성이
  비동기가 되는데, 그만한 크기가 아니다.

## 손댈 때

- 존을 추가/수정하려면 `zones.ts` 를 직접 고치기보다 생성 규칙을 고친다.
- 사냥터를 추가하면 차원문 목록(`FIELD_ORDER`)에 **저절로 들어간다.** 창은
  `zones.ts` 에서 이름·레벨대를 읽어 만들므로 따로 고칠 데가 없다.
  단 **`gate` 를 빼먹지 말 것** — 빼면 못 나오는 방이 된다.
- 고친 뒤 `npm test` — 문이 빠지거나 겹치면 여기서 잡힌다. 눈으로는 못 잡는다.
- **바닥 이미지를 바꾸거나 더하면**: 원본을 `assets-src/textures/varco/` 에 두고
  `build-ground-textures.mjs` 의 `SOURCES` 에 적는다 → 스크립트 → `npm run compress` →
  같은 이름을 `GROUND_KINDS`(shared `zone.ts`)와 `LOOKS`(client `ground.ts`, 출력된
  평균색까지)에 넣는다. 아무 존도 안 쓰는 이미지는 `zones.test.ts` 가 잡는다.
- 바닥은 **눈으로 봐야 한다.** 캐릭터 생성 화면이 월드를 가리므로, 콘솔에서
  `loadAssets` · `buildZoneScene` · `setupLighting` 을 불러 존 여러 곳을 오프스크린
  렌더러로 그려 한 장에 모아 본다(2026-09-10 에 9곳을 이렇게 봤다). 셰이더 오류는
  `renderer.debug.onShaderError` 로 글로 받는다.
- 존 개수를 바꾸면 [monsters-progression.md](monsters-progression.md) 의 티어 수,
  [items.md](items.md) 의 단계 접두어 20개가 같이 흔들린다.
